# 生成 RPD 需求文档

## 使用场景
用户提出一个新功能或新项目、需求还很模糊、要在动代码前先把需求写清楚时。

## 指令（分步）
1. 先把需求改写成 3 件事，逐条列出并与用户确认：**用户目标 / 输入输出 / 成功标准**。
2. 关键信息缺失时，只问 1–3 个最关键问题；其余合理假设并在文档中标注"假设"。
3. 按以下骨架产出 `plan/RPD_需求文档.md`：
   - 1 项目概述（定位 / 目标用户 / 当前状态）
   - 2 核心功能需求（总览表：模块 | 描述 | 优先级 P0·P1）
   - 3 详细功能需求（逐条：需求 / 交互 / 参数 / 边界）
   - 4 UI·UX 需求
   - 5 技术实现方案（技术栈 / 文件结构 / 关键点）
   - 6 分阶段规划（每阶段用 `[ ]` 勾选项）
   - 7 成功标准
   - 8 风险与应对（表格）
4. 每条需求必须"可判定做没做完"；写完提醒用户确认后再进入开发。

## 红线
- 只写将要实现的功能，不夸大。
- 未经确认不写代码。
