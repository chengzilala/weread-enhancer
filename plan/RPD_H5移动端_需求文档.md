# RPD 需求文档 · 微信悦读 H5 移动端（纯网页 App）

> 版本：v0.1（2026-10-06 新建；2026-10-07 更新 H8/H9 为「账户码 + 昵称托管」并补「我的账户」页）。把微信小程序「读完之后」的复盘 + 分享能力，搬到一个**纯网页（H5）**应用里，**并且包含小程序被禁的 AI 能力**（AI 仅允许在 web 侧，见 [RPD_小程序移动端_需求文档.md](./RPD_小程序移动端_需求文档.md#L261) 的 M15）。
> 定位：**浏览器插件的移动端「同构版」**——手机上不开小程序、不装插件，直接开网页就能用。
> 关系：与 [RPD_小程序移动端_需求文档.md](./RPD_小程序移动端_需求文档.md) 模块**一一对应**（小程序 M0–M14 ↔ H5 H0–H14，**H5 保留 AI**）；与 [RPD_网站生态_需求文档.md](./RPD_网站生态_需求文档.md)（对外官网）**并列、互不覆盖**——官网是「教程 / 内容站」，H5 是「能用的工具」。插件侧功能仍以 [RPD_需求文档.md](./RPD_需求文档.md) 为准。

## 1. 项目概述

- **定位**：把小程序里最有传播力的部分（阅读数据 + 阅读人格 + 每日卡片 + 灵感漫游）做成一个**可分享链接**的纯网页应用；**AI 能力完整保留**（人格画像 / 每日卡片成文 / 灵感漫游六段式）。
- **目标用户**：微信读书用户，手机上愿意粘贴一次自己 `wrk-` API Key（或让服务端记住），即可长期看数据、看人格、看回顾。
- **当前状态**：从零新建。可**大量复用**小程序侧已有资产：云函数 [wereadProxy/index.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js)、`mobile/miniprogram/shared/*` 的**纯计算逻辑**（persona-core / report-core / daily-core / wander-core 等）。
- **已确认的三件事（用户目标 / 输入输出 / 成功标准）**：
  - **用户目标**：手机浏览器打开一个网址，就能看自己的阅读数据、人格、回顾，并能一键分享；Key 输一次后**服务端记住**、长期免输。
  - **输入输出**：输入 = 用户自己的 `wrk-` Key（可让服务端记住）；输出 = 网页可视化报告 + 可分享的竖版图片 / 链接卡片。
  - **成功标准**：Key 输一次长期免输；核心数据 / 人格 / 卡片正确展示（含 AI）；能在手机浏览器顺畅分享；地址可公开访问。

### 1.1 关键前提（决定方案成立与否）

1. **数据必须经中转**。官方网关 `POST https://i.weread.qq.com/api/agent/gateway` 的 OPTIONS 预检返回 401，**浏览器 / 小程序都无法直连**（依据 [background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js#L6-L11)）。H5 与小程序一样，**必须经服务端中转**。
2. **中转复用现有微信云函数**。云函数出网不受小程序 request 合法域名白名单限制；且它**已具备 HTTP 访问服务入口**（[index.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js#L487-L506) 的 `handleHttp` 已带 CORS 头），**只需扩展允许的 action**，不新写后端。
3. **H5 无登录、无 openid**。小程序靠天然 `openid` 识别用户；H5 改为**匿名设备标识（deviceId）**——浏览器首次访问生成一个随机 ID 存本机，用它绑定「服务端记住的 Key」与「人格结果云同步」。

### 1.2 与其它端的关系

| 端 | 形态 | 定位 | 与 H5 关系 |
|---|---|---|---|
| 浏览器插件 | Chrome/Edge 扩展 | 读**过程**增强 + 数据/人格 | 数据算法同源；H5 是它的移动版 |
| 微信小程序 | 原生小程序 | 读**完之后**复盘 / 分享（**去 AI**） | 模块一一对应；H5 = 小程序的「带 AI 网页版」 |
| 官网（`web/`） | 静态教程站 | 教怎么用 / 内容 | H5 可从官网挂入口，但**代码独立** |
| **H5（本档）** | **`h5/` 纯网页 App** | **读完之后复盘 / 分享 + AI** | 独立构建与部署 |

## 3. 详细功能需求

### H0 中转服务（云函数 HTTP 化，P0）

- **需求**：复用现有云函数 `wereadProxy`，把它现有的 HTTP 访问入口从「只允许 `opsReport`」扩展为 H5 所需的全部动作，**不新写后端服务**。
- **要支持的动作（HTTP 调用，POST + JSON）**：
  1. `relay` —— 微信读书官方网关中转（入参 `{deviceId, apiName, params}`，Key 由服务端按 `deviceId` 取）；
  2. `ai` —— DeepSeek 转发（`{deviceId, messages}`，Key 由服务端取）；
  3. `keySave / keyGet / keyClear` —— Key 托管（见 H1）；
  4. `syncGet / syncPut` —— 人格结果云同步（按 `deviceId` 隔离，见 H8）。
- **安全 / 红线**：
  - Key **绝不出现在日志**（沿用现有 `maskKey` 掩码）；
  - `relay` / `ai` 的响应**不含明文 Key**；
  - CORS 仅允许**本站域名**（不延续现在的 `Origin: *`，改为白名单，防第三方站点盗用中转）。
- **边界**：网关超时 10s、AI 超时 30s（沿用现有常量）；错误码沿用现有 `{ok:false, code, error}` 结构。

### H1 Key 管理 · **服务端记住**（P0）

- **需求**：用户粘贴一次 `wrk-` Key → 存到服务端（按 `deviceId`）；之后所有请求只带 `deviceId`，**Key 不再回传浏览器**；用户可一键清除。
- **交互**：
  1. 首次进入 → 拦截页引导「粘贴你的微信读书 API Key」；
  2. 提交 → 前端送 `{deviceId, apiKey}` → 服务端校验格式（`wrk-` 前缀）→ 存库 → 回 `{ok, masked}`（如 `wrk-****(32)`）；
  3. 下次打开 → 前端用本机保存的 `deviceId` 询问「是否已配置」（回掩码，不回明文）；
  4. 首页 / 我的页显示「已配置 · wrk-****」+ **清除**按钮。
- **存储要求**：
  - 新集合 `wre_users`（或复用命名规范），**权限＝仅管理端可读写**；
  - 文档 `_id = deviceId`；Key 字段**应用层加密**（服务端环境变量密钥）后存储；
  - `deviceId` = 浏览器生成的随机串（≥ 32 位，非用户信息）。
- **密钥红线（已同步更新）**：项目密钥红线已放开为「**不提交到代码仓库、不写日志；产品可按需把用户自填的 Key 加密托管在服务端**（须隐私政策声明 + 可一键清除）」（规则母本与所有副本、以及移动端开发计划 §5 已同步）。本模块即按此实现：**用户明示同意后，Key 加密托管于服务端**，可随时一键清除；**默认不静默开启**，首次填写时明确告知。
- **边界**：
  - Key 失效（401/403）→ 提示重填；
  - 清缓存 / 换浏览器 → `deviceId` 丢失 → 提示重新填写；若记得账户码，可在「我的账户 → 跨设备登录」找回（见 H8）；
  - 用户点「清除」→ 服务端删文档 + 本机清 `deviceId` / 掩码。

### H2 数据总览（首页，P0）

- 对齐小程序 M2：Hero 主卡（累计阅读时长 / 天数）+ 迷你趋势图（本周 / 本月）+ 指标卡 + 偏好分类 / 时段 + 读得最多 Top3 + 书架 / 笔记 / 人格入口。
- A 档零成本数据优先渲染，B 档（报告类）懒加载；首屏 1 屏内出关键数字。

### H3 阅读人格（P0）

- 对齐小程序 M3：**纯本机计算**，4 维代码 + 16 型称号 + 判定依据 + 数据证据 + 16 型线描插画。
- 复用 `persona-core.js` 纯函数；**人格主体不依赖 AI**（AI 仅在 H10 做润色）。
- **版式（2026-10-07，已落地）**：结果页**严格完整复刻插件板式**（此前为缩略版、内容过少）——头部（代码 + 称号 + 一句定调 + 人物线描插画）→ 生成分享图 → 三个特质绰号 → 一句话画像 → AI 润色块 → 四维进度条（左右极名 + 百分比 + 依据）→ 数据证据 chips → 原文证据（引用块 + `书名·年份`）→ 语料提示 → 词语分析（高频词 TOP10 条形 / 情绪三色条 / 主题词 / 词云 / 口头禅）→ 边界声明。涉及 `h5/src/views/persona.js`、`h5/assets/app.css`。

- 复用 `report-core.js` 纯函数；图表用原生 canvas / SVG（零依赖）。

### H5 分享（P1）

- 边界：不支持 `navigator.share` 的浏览器 → 退化为「下载图片 + 复制链接」。

### H8 账户码（匿名身份 + 跨设备登录）（P1）

- **身份**：首次访问生成 `deviceId`（随机 32 位十六进制、非个人信息）存本机 localStorage；不登录、不弹授权。
- **账户码即身份**：把 `deviceId` 以**「账户码」**呈现给用户，它就是「账号」；换设备时在新设备「我的账户 → 跨设备登录」粘贴账户码即可找回同一账户的托管 Key + 昵称（人格结果按 `deviceId` 存云，集合 `wre_sync`，`_id = deviceId`）。
- **安全**：账户码等同密码，页面默认**只显示掩码**（前 4 后 4），点「显示完整」才展开；「退出登录」＝本机换新 `deviceId`（原账户与托管数据仍在服务端，可凭账户码再次登录）。
- **可达性**：「我的账户」页**不设 Key 门槛**（未配置 Key 时也可进入），否则换设备的人无法进入登录入口。
- **未来扩展**：账户模型预留 `openid` 绑定位，将来接入微信登录（小程序 web-view 免费取 openid / 认证服务号网页授权）时只需把 openid 绑到已有账户，属叠加改动。
- **红线**：云同步只存「本机算出的人格结果 + 昵称」与加密托管 Key，**不存原始接口数据**。

### H9 头像昵称（P1）

- 昵称：用户自填，**可托管到自建云函数**（非敏感展示名，随账户跨设备同步，离开时代码不持有 Key 明文）；本机 localStorage 只作显示缓存。
- 头像：**不上传图片**，用昵称首字在本机渲染（零存储、零隐私风险），用于账户页身份头与分享图署名。

### H10 AI 人格画像（P1 · H5 保留）

- 对齐小程序 M10：把本机算好的人格判定交 AI（DeepSeek）润色成一段画像；提示词与 [ai.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/miniprogram/shared/ai.js#L14-L21) 的 `SYSTEM_PROMPT` 保持一致。
- **Key 来源**：走 H1 服务端托管（前端不持有明文）；未配置 → 退回纯本地规则并提示。

### H11 每日卡片回顾（P1 · H5 保留 AI）

- 对齐小程序 M11：每天用历史划线 / 想法 → 「引用 + AI 说明 + 关联旧记忆」卡片；本机存档、可回看、可分享。
- **往期回顾（2026-10-06 新增）**：每日卡片页底部「往期回顾」列表**点开任一条可看整张卡片**（引用 + AI 说明 + 关联旧划线），顶部显示「正在看往期 · 日期」+「回到今天」；看往期时隐藏「重新生成」。**入口**：「我的账户」页新增「复盘与回顾」区块 →「每日卡片 · 往期回顾」按钮。
- **与小程序不同**：小程序 M15 后改为「纯本地规则排版」，**H5 保留 AI 成文**。
- 关联首版 = 关键词召回 + LLM 串联（embedding 留 P2）；卡片只存本机。

### H12 灵感漫游（P1 · H5 保留 AI）

- 对齐小程序 M12：六段式深度综述（标题 / 摘要 / 正文 / 来源可见 / 外部火花 / 创作种子）。
- 门槛：划线 ≥ 300 且 想法 ≥ 100；铜 / 银 / 金分级；**每周 1 篇**（银 2 / 金 3）+ 手动重生成限流；历史归档 + 随机漫游。
- **红线**：正文引用读者原文用下划线标出；外部火花统一标「AI 联想 · 未核实」，**禁止编造书名 / 原文**。

### H13 语音复习（TTS，P1）

- 对齐小程序 M14，但**H5 用浏览器内置 Web Speech API**（`speechSynthesis`）——零成本 / 零依赖 / 不联网，**无需服务端 TTS**。
- 范围：**A 档**＝想法 / 单条划线 / H11 卡片；**B 档**＝H12 漫游整期 / 按书连读。**不做**「听书」、不做对谈电台。
- 红线：**音频本机合成 / 播放、不上传**；**不提供书摘音频分享**；文案不得用「听书 / 电台 / 节目」。

### H14 运营看板（P2 · 作者）

- 对齐小程序 M13，转为 H5 语境：**无 openid** → 改为「账户码（deviceId）白名单 + 服务端校验」，白名单内才下发；否则 `code=forbidden`。
  - 免口令：管理员账户码配在云函数环境变量 `ADMIN_DEVICE_IDS`（英文逗号分隔）；输入框与本地口令缓存已移除。
  - 仅作者一人使用，不做复杂鉴权；账户码本身即身份私钥，只需配一处即可。
- 数据：小程序使用量 + 插件匿名上报 + H5 使用量 + 作者阅读数据汇总。

## 4. UI · UX 需求

- **形态**：竖屏优先、移动端自适应；底部 Tab 沿用小程序五栏「首页 / 人格 / 报告 / 书架 / 我的」（桌面宽屏可转顶部导航或左栏）。
- **风格**：与插件、官网、小程序一致的品牌色与圆角卡片；大数字 + 卡片 + 折叠区。
- **必备状态**：加载中（骨架屏）、空态（引导配 Key）、错误态（可重试）、未配 Key 拦截态。
- **性能**：首屏 1 屏内出关键数字；重数据异步加载；接口结果本机缓存，避免重复请求。
- **分享友好**：作为「可分享链接」打开时，首屏即为数据概览（不做必须先登录的墙）。

## 5. 技术实现方案

### 5.1 技术栈

- 前端：**原生 HTML / CSS / JS**（延续「零外部依赖」项目原则），可用 canvas / SVG 画图；可选打包为 **PWA**（添加到主屏）。

### 5.3 数据流

```
H5 页面
  → 读本机 deviceId（localStorage）
  → fetch(云函数 HTTP 入口, {action:'relay', deviceId, apiName, params})
      → 云函数按 deviceId 取托管 Key（+ 补 Authorization / skill_version）
      → 转发 i.weread.qq.com → 返回 {ok, data}
  → 页面 / core 模块做纯计算与渲染
AI 同理：{action:'ai', deviceId, messages} → 云函数取 Key → DeepSeek → {ok, text}
```

### 5.4 部署

- **静态托管**：可挂在现有帽子云 / Vercel（与官网同域或独立子域）；
- **中转**：微信云开发 → 云函数 `wereadProxy` 的 HTTP 访问服务增加绑定路径（如 `/h5`）；
- **跨域**：云函数响应头把 `Access-Control-Allow-Origin` 从 `*` 收敛为本站域名。

## 8. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| **Key 服务端托管** | 项目密钥红线已放开（允许按需托管），但托管本身有风险 | 用户**明示同意**后才托管；应用层加密 + 集合仅管理端可读写；日志只掩码；可一键清除；隐私政策如实声明 |
| `deviceId`（账户码）被他人获取 | 无登录，账户码即账号，泄露可冒用 | 随机 32 位十六进制、仅存本机；页面默认只显示掩码（点「显示完整」才展开）；服务端仅回 Key 掩码；「退出登录」可换新身份 |
| CORS 开放过宽 | 现有 HTTP 入口 `Origin: *`，第三方站点可盗用中转 | 收敛为本站域名白名单 |
| 云开发费用 / 额度 | 云函数按量计费 | 接口缓存与合并，减少调用；Key 托管不额外增加调用量 |
| AI 成本 / 限流 | H10–H12 会调用 DeepSeek | Key 由用户自付（托管而已），自然限流；失败降级提示 |
| 官方网关变更 / Key 风控 | 网关接口 / `skill_version` 变化 | `skill_version` 集中一处；错误码统一降级 |
| 移动浏览器 TTS 差异 | iOS Safari 需用户手势触发、语音包不一 | 播放由点击触发；无中文语音时给提示；失败不假装在播 |
| 分享能力差异 | `navigator.share` 兼容性不一 | 退化「下载图片 + 复制链接」；微信内可提示「长按保存」 |
| 与小程序算法漂移 | 多端共享计算逻辑 | `core` 模块单一来源，两端引用同一份纯函数 |

## 9. 已确认决策

> 账户 / 登录的汇总索引（散落信息收敛）见 [账户体系_说明.md](./账户体系_说明.md)。

1. **代码落点**：新建**独立 `h5/` 目录**（与 `mobile/`、`web/` 平级），独立构建与部署，不与官网代码混用。
2. **数据中转**：**复用现有微信云函数 `wereadProxy`**（HTTP 访问服务入口），不新写后端服务。
3. **AI Key 形态**：用户自填 `sk-` Key —— 按用户要求**服务端记住保存**（项目密钥红线已同步放开：「不提交到代码仓库、不写日志；可按需服务端加密托管 + 隐私政策声明 + 可一键清除」）。
4. **AI 保留**：H5 **完整保留 AI**（人格画像 / 每日卡片 / 灵感漫游），作为小程序 M15 去 AI 后的「web 侧出口」之一。
5. **身份**：无登录，采用**匿名 `deviceId`**，以「账户码」形式交给用户自持，用于跨设备登录（H8）。
6. **昵称 / 头像**：昵称可托管（非敏感、跨设备同步），头像不上传图片、用昵称首字渲染（首字，不存图）。
7. **微信登录（未来）**：不引入公众号 / 开放平台依赖；如需，优先走「小程序 `web-view` 免费取 openid」，账户模型已预留 `openid` 绑定位。
8. **网站 + H5 同一套账户**（2026-10-07）：官网（`/`）与网页版（`/app/`）**同域名同 origin，共用同一套账户与登录系统**——统一存储键 `wre_account_id / _endpoint / _mask / _profile`（旧 `wre_h5_*` 首次加载自动迁移，登录态不丢）；官网新增「我的账户」页 `/account/`，**直接复用 `h5/src/`（线上 `/app/src/`）的 `store / api / ui` 模块**（单一实现，避免两套逻辑漂移），登录态天然互通、无需任何同步机制。方向是「官网依赖 h5 模块」，h5 本身不反向依赖官网，仍可独立构建与部署。
9. **退出登录先「自保」账户码**（2026-10-08）：账户码 = 账号 + 登录凭证（本机唯一持有），退出 = 丢弃本机账户码、下次访问自动生成新账户。为防用户没抄号码就退出导致旧账户永久失联，退出登录**不再用系统 `window.confirm`**，改为**站内确认弹层**（共用实现：`ui.js` 的 `confirmSignOut()`）——弹出时**完整账户码 + 一键复制**，用户须点「我已保存，退出登录」才真正退出。官网 `/account/`（[account.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/web/assets/account.js)）与网页版「我的账户」页（[me.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/views/me.js)）均走此弹层，「清除 Key」等其它确认仍用系统确认框。
