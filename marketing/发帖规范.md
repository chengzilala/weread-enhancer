# 发帖规范（跨平台通用 · 以小红书为基准）

> **这份文档解决什么**：把「发一条帖子要满足哪些要求」抽出来，做成**一份所有渠道共用**的规范。
> 以后新开渠道（知乎 / 少数派 / 微信读书 App / 朋友圈 / 群 / 公众号 / B 站…）**先读第 1 章通用要求，再看第 4 章有没有该渠道的「差异」**，其余照搬，不用重新发明。
> **基准范例**：小红书（第 3 章，规则最完整）。其他平台**只写「和通用要求不一样的地方」**，一样的部分不重复。
> **最后更新**：2026-10-14

---

## 0. 怎么用这份文档

| 你要做的事 | 看哪里 |
|---|---|
| 新开一个渠道 | 第 1 章（通用要求）→ 第 4 章（该渠道差异，若有）→ 第 2 章清单逐条过 |
| 写文案 / 出图 | 第 1 章 1.4 / 1.5 + 该渠道目录下的 `<渠道>文案.md` |
| 发布前自查 | 第 2 章「发布前校验清单」 |
| 想看小红书完整规则 | 第 3 章 |
| 改口径 / 改入口（一次改，全渠道生效） | 第 1 章 1.1 / 1.2 |
| 了解发布方式（全自动 / 安全闸） | 第 1 章 1.7 |

**每个渠道一套「三件套」**（放 `marketing/<渠道>/`）：

| 文件 | 作用 | 必填 |
|---|---|---|
| `<渠道>文案.md` | 可复制的标题 / 正文 / 话题 / 配图清单，**单一事实源** | ✅ |
| `<渠道>运营计划.md` | 分析 → 架构 → 计划 → 逐日排期 | ✅ |
| `说明.txt` | 打包发用（素材包说明） | 可选 |

配图统一登记在 `screenshots/素材清单.md`；渠道登记在 `marketing/README.md`。

## 1. 通用要求（所有渠道一致）

### 1.1 事实口径红线（最优先，任何渠道不得突破）

| 项 | 口径 |
|---|---|
| 功能 | 只讲**已实现**的功能，不夸大、不预告 |
| 快捷键 | 仅 `空格 / D / F / ?`（**不写 T**） |
| 语音类功能 | 一律写「朗读 / 听」（不写 TTS / 语音合成） |
| 大模型 | 只列 **6 家国产**，不写国外模型 |
| 隐私 | 只说「不上传你的阅读数据」；匿名统计提「默认开、可关」 |
| 小程序 | 「悦读且住」**每个帖子底部固定带一行**（`🔍 微信小程序：微信搜「悦读且住」`）——**即使尚未上线也写**；**⚠️ 小红书例外**：正文 / 评论**不出现**（含"微信搜"），只在**私信**给 |
| 绝对化表述 | 不写「永久免费 / 绝对无广告」等 |
| **唯一例外** | F 类「心路 / 品牌」＝作者本人原文照录、一字不改（含 `https://` 链接、小程序入口、`Claude` 等），发布前单独确认 |

> 口径冲突时**以代码为准**（`content.js`、`manifest.json`）。改口径**先改本节**，再同步各渠道文案。

### 1.2 入口五件套（所有渠道统一，复制即用）

| 端 | 名称 / 入口 |
|---|---|
| 电脑插件 | Edge 商店搜「微信悦读」（Chrome 同款） |
| 产品官网 / 教程 | reader.chesterlee.cn |
| 手机网页版 H5 | reader.chesterlee.cn/app/ |
| 微信小程序 | 「悦读且住」——`🔍 微信小程序：微信搜「悦读且住」` |
| 作者主页 | chesterlee.cn |

> **小程序行＝每帖必带（硬规则）**：**每个帖子底部都要带这一行**，**即使小程序还没上线也写**（按「直接用」口吻，**不写**「即将上线 / 敬请期待」）。正文底部 / 获取方式区 / 评论区置顶里各放一份。
>
> ⚠️ **小红书例外（防限流）**：小红书**不写"微信搜"**、正文**不留任何入口**——正文只放**软引导**（"想要的说一声 / 私信我"），**完整入口只在私信给**。详见 3.1.1。

- **正文 / 图片里**用「**纯文字域名**」：`reader.chesterlee.cn`、`reader.chesterlee.cn/app/`、`chesterlee.cn`——**不带 `https://`**（微信生态的 `https://` 易被判外链限流）。**⚠️ 小红书例外：正文 / 图片里连域名也不写**（小红书对"站外引导"极严）。
- **完整可点链接**只放：**评论区置顶 / 私信 / 文末下载区**（**少数派 / 知乎这类允许放链接的平台**）。**⚠️ 小红书例外：评论区 / 主页也不放，只在私信给**（平台明确把"评论区、个人主页"列为需清理场景）。

### 1.3 配图要求（宁多勿少，放弃单图思维）

- **一篇至少 5 张、能多则多**：手机竖屏平台（小红书 / 微信读书 App）定 **5–8 张**；长文平台（知乎 / 少数派）图文并茂、随文配足。
- **第一张 = 封面**，直接决定点击率（大字提问式 + 一句钩子，别把字堆满）。
- **必须是真实界面截图**：源图来自 `screenshots/auto/`（`tools/autoshot.py` 抓，2 倍高清）或 `screenshots/store/`；**不摆拍、不用网络图、不用占位图**。
- **规格按平台**（见第 3、4 章）；**一图多用、不重复出图**（见第 5 章）。
- **已生成的图按帖子分文件夹**：每篇一个文件夹 `帖子/<编号>-<短标题>/`，里面放**该篇要用的那几张**（文件名带 `01-`、`02-` 上传序号，**第一张 = 封面**）。这样发帖时只打开一个文件夹就能传图，不用在几十张母版里挑。
  - **母版图留在原地不动**（脚本 / 平台配置都依赖母版路径）；帖子文件夹是**从母版复制**出来的，可随时重跑重建，**不入库**。
  - 文案里的 `（配 …）` 是唯一依据：改了文案就重跑生成脚本，文件夹自动跟着变。
- 文案里写清每篇用哪几张（标题行 `（配 …）`），发布脚本自动按此上传。

### 1.4 文案要求

- **第一人称亲测口吻**：先讲痛点 / 场景，再讲功能；不做产品说明书。
- **口语 + emoji**，适当情绪词（踩过的坑、真香瞬间）。
- **一条内容只讲一件事**，钩子写在最前面。
- **结尾抛问题**拉评论（「你读了多少？」），每篇末尾带统一收尾：小红书＝**软引导**（见 3.1.1）；其它渠道＝「入口区块」/「获取方式」区。
- **正文换行必须保留（硬规则）**：**不要用逐行 `Shift+Enter` 软换行**——小红书等富文本编辑器不渲染软换行，会把全文**挤成一坨**；正确做法是**把正文（含 `\n`）整段写入剪贴板、一次粘贴**（`tools/xhs_publish.py` 已内置此逻辑）。手动粘贴同理，贴完**先看分段是否正常**再发。

### 1.5 内容配比与节奏（3 周铺满）

| 层 | 作用 | 占比 | 带产品？ |
|---|---|---|---|
| **破圈层** | 涨粉 / 破圈 / 立人设 | 50% | 不带（末尾最多轻带） |
| **种草层** | 建立「我也想要」 | 30% | 带，弱转化 |
| **转化层** | 安装 / 使用 | 20% | 强引导 |

- **首篇＝「综合全面版」（全面介绍为主）**：每个渠道的**第一篇帖子**都把能做的事**一次讲全**，给账号立一个「完整认知」的锚点——小红书＝综合全面版 16 图连发；知乎＝综合全面版回答（§2）；少数派＝产品体验主文（§2）；微信读书 App＝综合全面版想法。**首篇之后**再按「破圈 → 种草 → 转化」铺开。
- **首篇之后养号**：冷启动期以破圈层为主，先把账号养起来、让平台打上「读书」标签，再上产品内容。
- **同账号一天最多 2 篇、两篇间隔 ≥ 4 小时**；先保封面标题质量，再提数量。
- **发布时段**：读书 / 学习类选 **12:00–13:00、21:00–23:00**（睡前）最佳。
- **节点加更**（提前 3 天备稿）：世界读书日（4/23）、开学季、考研季、年末年度报告。

### 1.6 单一事实源与复盘

- 正文**只写在** `marketing/<渠道>/<渠道>文案.md` 一处；发布脚本 / 打包说明都从它读，**改文案即自动同步**，不另存副本。
- **发布后立刻**发「评论区置顶」并置顶；主动回复前 20 条评论。（小红书＝**软引导、不放链接**；少数派 / 知乎等可放完整链接。）
- **3 天 / 7 天复盘**：看曝光、点击率、赞藏评、涨粉、搜索进店词；把跑得好的风格回灌文案，形成「爆款模板」。

### 1.7 发布方式：全程接管浏览器 · 全自动化

- **默认全自动**：每次发布，我都**接管浏览器**把流程从头跑到尾——打开创作页 → 切到正确的发布形态 → 传图 → 填标题 / 正文 / 话题 → 勾选设置，**中途无需你操作**。
- **唯一安全闸**：**脚本填完停在「发布」按钮前，由你亲手点最后一下**（避免全自动发布会触发平台风控）。核对无误再点。
- **必须人工的环节**：扫码登录、验证码 / 风控挑战、平台强制的实人验证——这些由你完成，其余交给我。
- **适用范围**：**浏览器类渠道全部适用**（小红书、知乎、少数派…）；**非浏览器场景仍手动**——微信读书 App（移动端）、朋友圈 / 群（微信生态）。
- **前提**：目标渠道的发布脚本 / 流程先就绪（小红书＝`tools/xhs_publish.py`）；尚未有脚本的渠道，**先补自动化脚本**再纳入全自动。

## 2. 发布前校验清单（每篇发之前逐条过）

- [ ] 事实口径：功能没夸大；快捷键只 `空格 / D / F / ?`；语音写「朗读 / 听」；大模型只 6 家国产
- [ ] 隐私口径：只说「不上传你的阅读数据」；匿名统计「默认开、可关」
- [ ] 帖子底部已带小程序入口（`🔍 微信小程序：微信搜「悦读且住」`，**未上线也写**）——**⚠️ 小红书例外：不带"微信搜"、正文不放，只在私信给**
- [ ] 没写「永久免费 / 绝对无广告」等绝对化表述
- [ ] 入口处理：**小红书**＝正文只留**软引导**（零域名 / 零"搜" / 零其他平台名），入口只走私信；**其它渠道**＝正文末尾统一「入口区块」/「获取方式」区（纯文字域名、无 `https://`）
- [ ] 正文无外链、无二维码；没有诱导点赞收藏
- [ ] 配图 **≥5 张**、第一张为封面、**全是真实界面截图**、规格符合该平台
- [ ] 该帖的 `帖子/<编号>-<短标题>/` 文件夹已生成，里面的图与该帖文案 `（配 …）` 完全一致
- [ ] 标题钩子在前；结尾有问题引导评论
- [ ] **正文分段正常（没被挤成一坨）**：自动 / 手动填完先肉眼过一遍换行
- [ ] 话题 / 标签不超平台上限（小红书 `#` ≤20）
- [ ] 发布＝**全程接管浏览器全自动**：传图 / 标题 / 正文 / 话题都由脚本填好，**只留最后「发布」一步给你点**（安全闸）
- [ ] 发布后立刻「评论区置顶」并置顶（**小红书＝软引导、不放链接**）

## 3. 小红书（基准范例 · 规则最全）

### 3.1 规格

| 项 | 要求 |
|---|---|
| 形式 | 图文笔记（手机竖屏为主） |
| 图片 | **3:4 竖版 1080×1440**；每篇 **5–8 张**（综合全面版 16 张连发）；**首张 = 封面** |
| 标题 | ≤ **20 字**，塞搜索词（微信读书 / 微信读书插件 / 阅读人格 / 读书笔记…） |
| 正文 | ≤ **1000 字**；首屏信息必须够勾人 |
| 话题 | `#` 最多 **20 个** |
| 外链 | **正文不可放可点外链**；**连"纯文字域名 / 商店搜 / 其他平台名"也不写**（会被判站外引导限流） |
| 限流雷区 | 硬广口吻、二维码、外链、**站外引导（域名 / "搜 XXX" / 其他平台名）**、诱导互动、大段重复搬运 → 全部规避 |

### 3.1.1 防限流硬规则（2026-10-14 A2 被判「站外引导」后立规）

- **绝不出现站外引导**：正文 / 评论区 / 主页 / 图片里**一律不写** ① 域名网址（`reader.chesterlee.cn`…）②「商店搜 / 微信搜 / 下载」③ 其他平台名 + 「搜 / 下载」。→ 本次 A2 就是被正文结尾「Edge 商店搜 / 域名 / 微信搜」三连判的。
- **正文末尾只留软引导**：`想要的话评论区吱一声，或者私信我～`（**零域名、零"搜"**）。
- **完整入口只走私信**：有人评论问 → 私信 1 对 1 发。
- **小程序行**：小红书**不带"微信搜"**、正文**连小程序名也不写**（只在私信给）。
- **评论 / 主页同样规避**（平台明说这三处都要清理）；主页简介用谐音 / 关键词，不写域名。
- **被判后怎么办**：不用申诉，直接「**修改笔记**」删掉站外信息、重新提交（限流只影响推荐 / 搜索，不会自动恢复）。

### 3.2 素材与文件

| 内容 | 位置 |
|---|---|
| 文案（47 篇：综合 1 + 系列 8 + 扩展 38） | `marketing/小红书/小红书文案.md` |
| 运营计划 + 逐日排期 | `marketing/小红书/小红书运营计划.md` |
| 配图 29 张（1080×1440 竖版） | `marketing/小红书/配图-*.png` |
| **按帖子分好的发帖文件夹**（每篇 6–7 张，带上传序号） | `marketing/小红书/帖子/<编号>-<短标题>/` ← `python3 tools/xhs_post_folders.py` 生成（不入库） |
| 打包说明 | `marketing/小红书/说明.txt` |
| 发布脚本（**全自动** · 停在发布前） | `tools/xhs_publish.py` |

### 3.3 发布流程

1. **出图**：`python3 tools/autoshot.py --url "<书页网址>"`（重抓真实界面）→ `python3 promo.py` → `python3 tools/xhs_post_folders.py`（按帖子分好文件夹）
2. **选篇 + 核对**：`python3 tools/xhs_publish.py --post A1 --dry`（只打印，不操作）
3. **全自动发布（接管浏览器）**：`python3 tools/xhs_publish.py --post A1` → 你扫码登录（唯一人工环节）→ 脚本**全程接管浏览器**：自动切「上传图文」→ 传图 → 填标题 / 正文 / 话题（**正文用「整段粘贴」保留换行，不会挤成一坨**）→ **停在「发布」按钮前，你核对后自己点**（安全闸）
4. **发布后**：评论区置顶完整链接（模板见 `小红书文案.md` 第 0 节）
5. **勾选排期**：`小红书运营计划.md` 第四节对应 `- [ ]` 改为 `- [x]`
- **降级方案**：脚本受页面改版影响时，改手动上传（素材已就绪）。

## 4. 其他平台差异对照（只列与通用要求**不同**的地方）

### 4.1 知乎

| 项 | 与通用要求的差异 |
|---|---|
| 形式 | 回答（主战场）/ 文章（沉淀）/ 想法（日常）/ 提问（破圈）/ 主页（承接）——**不是日更笔记** |
| 配图 | **横版为主**：`screenshots/store/store-01…11-1280x800.png`、`screenshots/promo/github-banner.png`；需要竖版再复用小红书 3:4 |
| 入口 | 站内**外链管控严**：正文只写纯文字域名；完整链接放**评论区 / 私信** |
| 口吻 | 第一人称亲测 + **亮明「自己做的开源工具」**，不装第三方推荐 |
| 节奏 | **一天最多认真答 1 题**；宁可少而精（水答会被折叠、反而伤权重） |
| 发布 | 目标＝**全自动接管浏览器**（搜问题 → 写回答 / 文章 → 配图 → 停在「发布」前）；该渠道发布脚本待补，未就绪前先用 `帖子/` 素材手动 |
| 文件 | `marketing/知乎/知乎文案.md` + `知乎运营计划.md`；发帖文件夹 `marketing/知乎/帖子/<篇号>-<短标题>/`（`tools/zhihu_post_folders.py` 生成，不入库） |

### 4.2 少数派

| 项 | 与通用要求的差异 |
|---|---|
| 形式 | **编辑审稿制长文**：先发 Matrix 社区，争取被推荐上主站；也可主动投稿 |
| 配图 | 横版长图 `screenshots/store/store-01…11-1280x800.png`、`promo/github-banner.png`；图文并茂 |
| 入口 | **相对允许放链接**：把官网 / 商店地址放**文末自然的下载区**，别堆在正文中间（仍以审核为准） |
| 口吻 | 「我用它解决了什么问题」的体验口吻，先痛点场景、再功能；**自我宣传须在编辑器如实披露利益相关**（准确披露是被精选 / 上首页的前提） |
| 节奏 | **一篇好文 > 一百篇水帖**，重质不重量 |
| 发布 | **全自动接管浏览器**（`tools/sspai_publish.py`）：打开编辑器 → 填标题 → 粘正文 → 传图 → 填标签，**停在「发布」前**；侧栏「利益相关声明」与最后一下仍由你点 |

## 6. 维护约定

- **改口径 / 改入口**：先改本文第 1.1 / 1.2，再同步各渠道文案（一次改，全渠道生效）。
- **新增渠道**：建 `marketing/<渠道>/` 三件套 → 本文补一节「第 4 章差异」→ `marketing/README.md` 索引补一行。
- **文案改动**：只改 `<渠道>文案.md`；脚本 / 说明从它读，别在别处另存副本。
- **图片改动**：只改 `promo.py` / `autoshot.py`，重跑出图；别手工 P 图。**出图后跑一次**按帖子分文件夹的脚本（小红书＝`python3 tools/xhs_post_folders.py`）。
- **新增渠道的发布自动化**：先补该渠道发布脚本（沿用 `tools/xhs_publish.py` 的「接管浏览器 → 停在发布前」范式），再按 §1.7 纳入全自动。
- **帖子文件夹**：是生成物（复制件），**不入库**；新增渠道照此约定在 `<渠道>/帖子/` 下生成。
