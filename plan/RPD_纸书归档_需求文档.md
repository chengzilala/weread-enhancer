# RPD 需求文档 · 纸书归档（拍书）与微信读书联动

> **版本**：v0.5（2026-10-08；小程序侧 S1–S4 全部落地：扫码 / 拍照识码 / 关联 / 状态与标签 / 感想 / 纸质位置 / 导出；仅剩浏览器扩展面板未做）
> **定位（已确认）**：**先给自己用**——私人工具，不发布、不商用。
> **形态（建议）**：复用现有「微信悦读」小程序，**新增一个「📚 纸书」页**；自用走**体验版**，可免 ICP 备案。
> **前置**：可行性结论见同目录 `可行性分析_纸书归档.md`（含硬边界与最小验证清单）。
> **红线**：只做"建档（元数据）+ 关联"，**不复制书中正文**，不做"拍照 OCR 成电子书文库"。

---

## 0. 需求三件事（请先确认）

### 用户目标
把自己家里成堆的纸质书，**快速变成一份可检索、可整理的清单**；并且每本纸书能**关联到微信读书的电子版数据**（有没有电子版、我的划线/想法、书评、推荐、阅读进度），不再是"死档案"。

### 输入 / 输出
| | 内容 |
|---|---|
| **输入** | ① 手机对着书背**扫条码（ISBN）**；② 拍书封/版权页照片（兜底）；③ 必要时手动输入书名 |
| **处理** | 拿 ISBN/书名 → 查元数据（优先微信读书 `/store/search`）→ 存入「我的纸书」库 → 标记与微信读书的关联 |
| **输出** | 一份「我的纸书」列表（封面/书名/作者/分类/标签/状态），每本可展开看到微信读书关联信息，可搜索、可导出 |

### 成功标准
1. 拿 **20 本**自己的纸书实测：扫码一次性识别成功 **≥18 本**（90%）。
2. 每本书条目里能明确回答："**微信读书有没有电子版**"；有的可**一键跳转**到电子版。
3. 我在微信读书有笔记的书，纸书条目下能看到**笔记条数**并能进入查看。
4. 全程 **`wrk-` Key 不出现在日志、不外传**（沿用现有红线）。

### 已确认的 3 项假设（2026-10-07 用户确认）
1. **"笔记关联"指哪种笔记？** → **两者都做**：纸书条目下并列展示「我在微信读书的划线/想法」+「我自己在纸书上写的感想」（后者手动录入）。
2. **纸书库存哪？** → **本机 storage 为主 + 云开发集合同步备份**（换手机可拉回，不丢藏书）。
3. **要不要"纸质位置"字段？** → **P1 再做**，P0 不做（避免录入变慢，违背"快"的初衷）。

## 3. 详细功能需求

### M1 扫码建档（P0）
- **需求**：进入「纸书」页点"扫书"，连续扫条码，每扫到一本即刻识别并暂存，可批量确认入库。
- **交互**：`wx.scanCode({ scanType: ['barCode'], onlyFromCamera: true })`；扫完停留在扫码页可继续扫（连续录入）。
- **参数**：ISBN（EAN-13）。
- **边界**：
  - 非 ISBN 条码（如商品码）→ 提示"这不像是书的条码"，不入库；
  - 同一 ISBN 已在库 → 提示"这本书已在你的纸书库"，不重复入库；
  - 无条码/条码磨损的旧书 → 引导走 M2 或 M3 手输。

### M2 拍摄兜底（P0）
- **需求**：拍照（或相册选图）识别书上的条码。
- **实现**：选图/拍照（`wx.chooseMedia`）→ 超 2M 先 `wx.compressImage` 压缩 → 上传云存储 → 云函数 `imgScan` 下载图片，以 `img` 媒体参数云调用 `openapi.img.scanQRCode` 识别条码；识别后**删除临时图**（不留用户照片）。
- **边界**：图片 **< 2M**（超限先压缩）；识别不到 → 转手输。

### M3 元数据获取（P0）
- **需求**：拿到 ISBN/书名后，补齐"书名 / 作者 / 封面"。
- **取数优先级**：
  1. 用 **书名** 调微信读书 `/store/search` → 命中则取官方书名/作者/封面 + `bookId`；
  2. 未命中 → 只存 ISBN + 书名，**允许手动补录**；
  3. （P1 再评估）是否引入第三方 ISBN 元数据接口。
- **边界**：ISBN 直查 `/store/search` **是否可用待实测**（见可行性 V1/V2）；不可用则一律"先按书名搜"。

### M4 我的纸书列表（P0）
- **需求**：封面墙 + 列表两种视图；关键字搜索（书名/作者）；筛选（有电子版 / 无电子版 / 已读状态）。
- **边界**：封面缺失用占位图；列表分页加载。

### M5 微信读书关联（P0）
- **需求**：点开某本纸书，展示：
  - 微信读书**是否有电子版**（有 → 显示封面 + 「去微信读书读」按钮）；
  - 我在该书的**笔记条数**（划线 / 想法），可进入查看明细（复用现有笔记模块的归一化逻辑）；
  - 阅读**进度**（读过电子版时）；
  - **书评** / **相似书**（可选展示）。
- **实现**：`/store/search` 拿 bookId → `/book/info`、`/book/bookmarklist`、`/review/list/mine`、`/book/similar`。
- **兜底**：自动匹配不到 / 匹配错时，走 **M10 手动关联** 人工挑一本。
- **边界**：无电子版 → 该区块整体不出现（不显示"0"）；未配 Key → 给中文引导，不报错。
- **跳转说明（小程序限制）**：官方 `deepLink` 是 `weread://` 手机端 scheme，小程序**打不开**；故「去微信读书读」实现为**复制书名/链接到剪贴板 + 提示去微信读书 App 搜索**（**严禁自行拼接 `weread://` 链接**，沿用插件既有红线）。

### M6 我的读书感想（P1）
- **需求**：给纸书写感想（纯文字；可选拍照附一页）。在纸书详情里与微信读书笔记**分开展示**（避免混淆来源）。

### M7 分类与标签（P1）
- **需求**：自定义标签（如"借出中""一号书柜"）、阅读状态（已读/在读/想读）。

### M8 导出（P1）
- **需求**：导出 Markdown / CSV 备份（含 ISBN、书名、状态、标签）。

### M9 纸质位置（P2）
- **需求**：记录纸质书摆放位置，便于找书。

### M10 手动关联电子书（P0）
- **为什么必须做**：`/store/search` 按 **ISBN 直查大概率不命中**（待实测），按书名搜又可能搜到多本同名书——所以"人工挑一本"是**让整个关联闭环成立的兜底**，不是可选功能。
- **需求**：
  1. 纸书详情页提供「**手动关联电子书**」按钮；
  2. 点开 → 输入书名（或作者）→ 调 `/store/search`（`scope: 10`）→ 展示候选列表（封面 / 书名 / 作者 / 在读人数）；
  3. 用户点选一本 → 绑定该纸书条目的 `bookId` + `deepLink` + 关联书名/封面，标记 `linkManual: true`；
  4. 展示上把"自动匹配"与"手动关联"区分开（手动关联标注"手动"），并允许**解除关联** / **重新关联**。
- **交互**：搜索框默认预填纸书书名（省一步输入）；候选为空时提示"微信读书可能没有这本的电子版"。
- **边界**：
  - 未配 Key → 按钮置灰并提示先去配置 Key；
  - 搜索失败（网络/Key 失效）→ 提示重试，不破坏已有档案；
  - 重新关联会覆盖旧的 `bookId`，需二次确认。
- **与 M3 的关系**：M3 是"自动尝试"，M10 是"人工兜底/纠正"，两者共用同一套搜书逻辑。

## 4. UI / UX 需求

- 新增入口：小程序底部或首页「📚 纸书」（与现有"书架"页区分：现有「书架」= 微信读书电子书架，新页 = **我的纸书**，命名必须能一眼区分，建议叫「📚 我的纸书」）。
- 主操作：**首屏一个大按钮「扫书」**，进来即可扫（首次需相机授权，一次性）。
- 反馈：每扫一本即时"叮"一声 + 缩略卡出现，**连续扫不打断**。
- 空态：无纸书时给"扫第一本书试试"的引导。
- 视觉：沿用现有小程序样式体系，不引入新 UI 库。

## 5. 技术实现方案

| 层 | 方案 |
|---|---|
| 前端 | 复用 `mobile/miniprogram`；新增 `pages/paperbook/`（列表/详情/扫码/手补/笔记明细）；共享模块按职责拆分为 `shared/paperbook-store.js`（本机+云存储）、`paperbook-data.js`（联网搜书/取笔记/拍照识码）、`paperbook-core.js`（匹配决策）、`paperbook-share.js`（导出 Markdown/分享）；复用 `shared/gateway.js` 的 `callGateway` |
| 云函数 | 复用 `wereadProxy`；**新增** `action: 'imgScan'`（云调用 `openapi.img.scanQRCode`，识别图片条码）；网关 relay 沿用现状 |
| 数据 | **本机 storage 为主**（`wre_paperbooks`）+ **云开发集合 `wre_paperbooks` 备份**（按 openid 隔离，换机可拉回）；字段：id、isbn、title、author、cover、bookId、deepLink、linkTitle、linkManual、status、tags、feeling、location、createdAt |
| 关联 | `/store/search`（`scope: 10`）→ 取官方数字 `bookId` + `deepLink`（自动 M3 / 手动 M10 共用）；后续 `/book/bookmarklist`、`/review/list/mine` |
| 依赖 | **零外部依赖**（沿用项目红线）；拍照识别走微信原生云调用，不引第三方 OCR 库 |
| 权限 | 小程序需 `scope.camera`（扫码）、相册/相机（拍照）；无新增隐私数据类型 |

1. 扫 20 本真书，**一次识别成功 ≥18 本**，入库无重复。
2. 任意一本纸书详情页 3 秒内回答："**微信读书有没有电子版**"。
3. 微信读书有笔记的书，能一键进入笔记明细。
4. `wrk-` Key 全程不落日志、不外传（复用现有隐私红线）。
5. 录入速度：单本**≤5 秒**（扫码 → 入库）。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 微信读书没电子版的纸书占比高 | "关联"闭环感弱 | S0-V2 先实测命中率；命中低则以"本地档案 + 手补元数据"为主，关联作锦上添花 |
| `/store/search` 不支持 ISBN 直查 | M3 需多一步"按书名搜" | 走书名搜索；书名重复时给候选让用户选 |
| 免费 ISBN 元数据不可用（豆瓣已死） | 封面/作者缺失 | P0 允许手动补录；P1 再评估是否买商业接口 |
| 旧书无条码/条码磨损 | 扫不出来 | M2 拍照 + M3 手输兜底 |
| 官方接口变更 / `upgrade_info` 强制升级 | 关联功能失效 | 以 `{"api_name":"/_list"}` 为准；回包带 `upgrade_info` 时按官方指引升级 |
| 版权红线被误踩 | 法律风险 | 明确只做"建档 + 关联"，**绝不 OCR 正文**（写入产品定位） |
| 自用沉淀成产品后需合规 | 需备案/类目/隐私政策 | 本次不做；若日后发布，另立 RPD，先走 ICP 备案 |
