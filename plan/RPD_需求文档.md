## 1. 项目概述

### 1.1 产品定位
这是一个专为微信读书网页版（weread.qq.com）打造的浏览器扩展插件，旨在提升阅读体验，提供更丰富的自定义设置和快捷操作。

### 1.2 目标用户
- 微信读书网页版的重度用户
- 追求个性化阅读体验的用户
- 需要便捷快捷键操作的用户

## 3. 详细功能需求

### 3.1 左侧悬浮入口

**需求描述**：
- 在页面左侧显示一个悬浮图标按钮（FAB，🤖）
- **鼠标悬停图标即展开主菜单，无需点击**；鼠标移开约 0.25s 后自动收起
- 支持勿扰模式：平时隐藏，鼠标悬停时显示

**交互细节**：
- 图标位置：左侧边缘，可自定义上下位置
- 悬停图标 / 悬停菜单 → 展开下拉菜单（两者之间移动不会误收）
- 鼠标离开图标与菜单 → 延迟 250ms 收起菜单
- 点击图标 → 保持展开（不再切换收起，避免"点一下反而收起"）
- 点击页面其他位置 / 点击任一菜单项 → 收起菜单
- 勿扰模式下：图标透明，鼠标移到左侧区域才显示

### 3.3 阅读设置面板

#### 3.3.1 屏占比调节
- **需求**：支持自由调节阅读区域的宽度
- **实现方式**：滑块控制，实时预览
- **范围**：50% - 100%
- **默认值**：微信读书默认宽度

#### 3.3.2 自动阅读
- **需求**：自动滚动页面，解放双手
- **参数**：
  - 滚动速度（慢速/中速/快速，或自定义数值）
  - 滚动方向（向上/向下）
  - 开始/暂停控制
- **交互**：点击开始按钮启动，再次点击暂停

#### 3.3.3 翻页设置
- **需求**：自定义滚轮翻页行为
- **参数**：
  - 滚轮灵敏度
  - 翻页动画开关
  - 每页滚动距离
#### 3.3.4 屏占比与目录、字号等功能同步

**背景**：当屏占比 ≥90% 时，微信读书原生的顶部工具栏（readerTopBar）和右侧功能按钮（readerControls，包含目录、字号、主题等）会被推出视口，导致无法操作。

**实现方案**：

- **触发条件**：双条件触发，任意满足即启用——
  - ① 屏占比 >85%（86% 及以上触发浮动，85% 刚好能放下工具栏保持原生）
  - ② 元素实际溢出视口（兜底，处理小屏、缩放等边缘情况）
- **顶部工具栏**：
  - JS 计算精确 pixel 位置，钉在视口顶部居中（position: fixed + transform: none），保持原始宽度不变形
  - 默认透明隐藏，鼠标移到浏览器顶部 100px 范围内淡入显示，移开后 0.4s 延迟淡出
- **右侧功能按钮**：
  - 通过 inline style（最高优先级）覆盖原生 margin-left，固定在视口右侧 20px 处
  - 保持 position: absolute 不变，确保字号/目录等弹窗菜单定位正确
  - 默认透明隐藏，鼠标移入右侧 120px 感应区淡入显示，移开后 0.4s 延迟淡出
- **感应方式（v0.8.3 修正）**：感应不使用任何覆盖层元素，改为监听 `document` 的 `mousemove` 判断鼠标是否贴近顶部/右侧边缘。此前的透明感应层虽是全透明 div，但位于页面之上会吃掉点击，正好压住官方「下一页」点击区，导致翻页点不中
- **互不干扰**：顶部和右侧各自独立感应阈值和 CSS 类名（wre-show-topbar / wre-show-controls），鼠标放哪边只显示哪边
- **退出条件**：屏占比 ≤85% 且无元素溢出时关闭浮动，还原原生布局

## 5. 技术实现方案

### 5.1 技术栈
- **Manifest Version**: V3
- **语言**: 原生 HTML/CSS/JavaScript
- **依赖**: 零外部依赖，纯原生实现

### 5.2 文件结构
```
微信读书插件/
├── manifest.json      # 插件配置
├── content.js         # 核心逻辑（UI 生成、事件处理）
├── content.css        # 样式文件
├── README.md          # 项目说明
├── Running.md         # 安装运行说明
└── RPD_需求文档.md    # 本文档
```

### 5.3 实现关键点

#### 5.3.1 Content Script 注入
- 在微信读书页面加载完成后注入
- 使用 `document_end` 时机
- 避免与页面原有代码冲突

#### 5.3.2 UI 隔离
- 使用 Shadow DOM 或独立的根元素
- CSS 类名加前缀（`wre-`）防止样式污染

#### 5.3.3 事件处理
- 防抖处理，防止重复触发
- 阻止事件冒泡，避免影响页面原有行为

### 9.4 代码模块化重构（P1）

#### 9.4.1 当前问题
- `content.js` 单文件 **3200+ 行**，涵盖 UI 生成、屏占比计算、自动阅读、快捷键、调试日志等所有逻辑
- 维护困难，新人难以理解代码结构
- 新增功能无处安放，只能在文件末尾堆砌

#### 9.4.2 重构目标
- **原则**：不重写旧代码，新增功能使用新模块；旧代码只在必要时提取
- **新文件结构**：
```
微信读书插件/
├── manifest.json
├── content.js              # 入口 + 初始化 + 旧逻辑（保持不动）
├── content.css             # 样式（保持不动）
├── modules/                # 新增模块目录
│   ├── stats.js            # 阅读统计与导出
│   ├── notes.js            # 笔记增强（划线复制、导出、批注聚合）
│   └── utils.js            # 通用工具函数（防抖、存储、DOM 操作等）
├── README.md
├── Running.md
└── plan/
    └── RPD_需求文档.md
```

#### 9.4.3 模块加载方式
- content.js 通过动态 `<script>` 标签注入模块文件
- 或通过 `chrome.runtime.getURL()` 加载模块
- manifest.json 中声明 `web_accessible_resources` 暴露 modules 目录

#### 9.4.4 重构分期
| 阶段 | 内容 | 说明 |

## 10. 官方 Agent Skill 接入（🪞 阅读洞察）— 规划中，目标 v0.11.0

> **状态：需求已定，未开发**（本章是开发前基线；接口事实取自微信读书官方 skill 包 `weread-skills.zip`，其 `version: 1.0.4`）
> **需求确认：2026-09-29**

### 10.0 需求三件事（先对齐）

**用户目标**
让用户在插件里**粘贴自己的 `wrk-` Key**，插件就用**微信读书官方 Agent Skill 网关**的官方数据，在**本机**为其生成一份**全面的阅读行为分析报告**（时长与天数趋势 / 偏好画像 / 书架结构 / 笔记行为），并支持可视化、周期环比、一键导出与规律建议。

**输入输出**
- 输入：用户粘贴自己扫码换来的 `wrk-` 开头个人 API Key（**只存本地**）＋ 报告周期选择（周 / 月 / 年 / 累计）
- 输出：① 面板内**可视化阅读行为报告**；② 一键导出的 **Markdown / 自包含 HTML** 报告；③（附带能力）书架概览、笔记划线导出、搜书 / 书评 / 推荐
- 处理位置：**全部在本机浏览器内计算**；除向 `i.weread.qq.com` 取原始数据外，不向任何地方发送数据

**成功标准（可判定）**
1. 未配置 Key 时：面板明确提示「未配置」并给一键跳转，不静默失败、不报错崩溃
2. Key 只存 `chrome.storage.local`；不进日志、不进 release 包、不发给除 `i.weread.qq.com` 以外任何域名
3. 报告四段均能基于真实官方数据生成（时长秒→「x 小时 y 分钟」、时间戳→`YYYY-MM-DD`，数字与官方口径一致）
4. 周期切换（周/月/年/累计）正常，环比取自官方 `compare`；数据不足时显示空态而非 0
5. 一键导出 Markdown / HTML 可用，内容与面板一致
6. 任一接口失败有中文提示 + 降级回退（本地统计 / 网页同源接口 / DOM 抓取），不影响原有功能
7. 现有「阅读统计」「笔记」功能行为不变（回归通过）

### 10.1 官方网关事实基线（以官方 skill 包为准）

- 统一入口：`POST https://i.weread.qq.com/api/agent/gateway`
- 鉴权：Header `Authorization: Bearer wrk-xxxx`（Key 已绑定用户身份，**无需传 vid**）
- 请求体：`{ "api_name": "...", 业务参数…, "skill_version": "1.0.4" }`；**业务参数必须平铺在顶层**，不能包进 `params`/`data`/`body`
- 回包：JSON；`errcode != 0` 表示错误（给中文提示）；回包出现 `upgrade_info` 时**必须**提示升级，不得忽略
- 自查接口：发 `{"api_name":"/_list"}` 可取全部可用接口及参数定义
- 单位红线：**所有时长字段单位是秒**；Unix 时间戳展示时转 `YYYY-MM-DD`

### 10.2 详细功能需求

#### 10.2.1 Key 管理（P0）
- **面板位置**：主菜单「🔑 API Key」独立入口（放进「设置」分组，v0.14.2 起集中填写两个 Key；不再占用阅读洞察面板的页签）
- **交互**：密码型输入框（可切换明文）＋「保存」＋「清除」＋状态标签（未配置 / 已配置 / 校验失败）
- **保存即校验**：先 `/_list` 探连通，再用轻量接口 `/readdata/detail`（`mode=weekly`）验证 Key 有效；失败给中文原因（网络不通 / Key 无效 / 网关报错）
- **存储**：`chrome.storage.local` → `wreOfficialSkill: { apiKey, savedAt, lastVerifiedAt, skillVersion }`
- **红线**：日志只允许输出掩码（`wrk-****`）；「清除」必须彻底删除该键值

#### 10.2.2 网关调用底座（P0）
- **走扩展后台**：MV3 内容脚本的跨域请求受宿主页面 CORS 限制，故由 `background.js`（service worker）统一转发
- **调用链**：内容脚本 `chrome.runtime.sendMessage({ type:'wre-official-call', apiName, params })` → 后台补 `Authorization` 与 `skill_version` → POST 网关 → 统一处理 `errcode` / HTTP 状态 / 超时（10s）→ 回传
- **安全收益**：明文 Key 只存在于后台，内容脚本与页面拿不到
- **`upgrade_info` 处理**：面板插入醒目提示「官方 skill 需升级到 x.y.z」并给官方 skill 包下载地址；`SKILL_VERSION` 常量化，便于集中升级
- **假设（待实测）**：① 网关是否已放开 CORS（若放开可简化，不必走后台）；② 校验用的最省接口；③ `/_list` 是否要求鉴权

#### 10.2.3 阅读行为分析报告（核心交付，P0）

> 本功能的**最终交付物**：把官方数据在本机算成一份「阅读行为报告」。**纯本地计算，数据不出本机**（除向 `i.weread.qq.com` 取原始数据外，无任何外发）。

- **入口**：打开「🪞 阅读洞察」面板，**默认第一屏就是「📊 阅读行为报告」**（有 Key 且校验通过时）
- **报告章节骨架（V1 已落地；V2·上半已补书架/笔记/人格画像章节，对齐「深度阅读画像」参考文档）**：封面元信息 → 一、执行摘要 → 二、数据全景（2.1 核心指标 / 2.2 书架结构 / 2.3 官方概要 / 2.4 偏好分类）→ 三、阅读轨迹与时间线 → 四、阅读时段分布 → 五、偏好画像（5.1 作者 / 5.2 出版社 / 5.3 版权方）→ 六、读得最多 → 七、书的印象 → 八、成就勋章 → 九、知识脉络 → 十、笔记行为 → 十一、完读率 → 十二、已读完书目 → 十三、阅读人格画像 → 十四、阅读规律与建议 → 附录：数据说明。**采用「表格 + 表格后紧跟解读」的版式**，末尾附「分析局限性」声明。V1 只用 `/readdata/detail` 单接口；**第二步**已接入 `/shelf/sync`（书架）与 `/user/notebooks`（笔记概览）补齐九~十二章，并以**客观规则化类型归类**（完读率 / 笔记密度 / 分类集中度 / 有声书占比 / 时段峰值）落地「十三、阅读人格画像」；仅剩「想法与划线深度解读」「价值取向与精神底色（主观语义层面）」需原文接口，在附录明确标注「尚未覆盖」，不臆造。
- **阅读人格（阶段十四 · 读书人版）**：报告**首屏**新增「🧬 我的阅读人格」卡片，「十四、阅读规律与建议」之后新增「十五、阅读人格（读书人版）」章节；四维模型 / 16 型命名 / 词语分析 / 边界红线的完整需求见 [RPD_阅读人格_需求文档.md](./RPD_阅读人格_需求文档.md)。
- **报告四段（对应四类数据源）**——1、2 在 V1 落地；3、4 于**第二步**接入：
  1. **时长与天数趋势**：总时长（秒→「x 小时 y 分钟」）、阅读天数 `readDays`、自然日均 `dayAverageReadTime`、读得最多 `readLongest`、`readStat` 摘要 —— 来源 `/readdata/detail` ✅ V1
  2. **偏好画像**：偏好分类 `preferCategory`（权重条形）、偏好时段 `preferTime`（24 格，**数组从 6 点开始**）、偏好作者/出版社/版权方、书的印象 `preferBooks`、成就勋章 `medals`、常读标签（`readLongest[].tags`）—— 来源 `/readdata/detail` ✅ V1
  3. **书架结构**：总量（官方口径 `books + albums + mp`）、分类分布、读完率 `finishReading`、置顶 `isTop`、私密占比 `secret` —— 来源 `/shelf/sync` ＋ `/user/notebooks` 概览 ✅ 第二步（已落地「2.2 书架结构 / 九、知识脉络 / 十一、完读率 / 十二、已读完书目」）
  4. **笔记行为**：划线数 `noteCount`、想法/点评数 `reviewCount`、笔记总数（`reviewCount + noteCount + bookmarkCount`）、笔记最多的书、**笔记密度（平均每本 / 想法占比 / 划线占比，v0.16.0 补）** —— 来源 `/user/notebooks` ✅ 第二步（已落地「十、笔记行为」）
- **周期切换**：周 / 月 / 年 / 累计；环比**直接取回包 `compare`**（不自己重算）；`annually` 跨年区间按官方口径拆多次累加
- **规律总结 / 建议文案（规则模板，不引入额外 AI Key）**：只用报告里已有指标写「事实句 + 温和建议」，例如「本月比上月多读 3.2 小时」「你的阅读集中在 21–23 点」；**禁止编造数据、禁止绝对化结论、禁止健康/医疗类建议**
- **可视化**：原生 Canvas + CSS（延续零依赖）；图表：折线（时长趋势）、横向条形（分类权重）、热力格（时段）、环形（读完率）
- **一键导出**：**Markdown**（复用现有导出风格）＋ **自包含 HTML**（样式内联，双击即看）＋ **PDF**（打印视图另存为 PDF，沿用阅读统计模块的做法，零第三方依赖）；**Markdown 与 HTML 共用同一份「报告模型」（`buildReportModel`）渲染，避免两套渲染漂移**；文件名含周期与生成日期；导出文件由用户自行保管，插件不代传
- **性能**：统计/书架结果按周期缓存进 `chrome.storage.local`（带时间戳），二次打开直接渲染、不重复请求；面板提供「刷新」手动拉取
- **边界与红线**：数据不足（新账号、本周 0 分钟）显示「数据不足」空态而非 0；所有百分比标注分母；不输出评判性文案（如「你不自律」）

#### 10.2.4 阅读统计（官方口径）（P0）
- **接口**：`/readdata/detail`；`mode` = `weekly` / `monthly` / `annually` / `overall`，`baseTime` 可查历史周期（0 = 当前周期）
- **展示**：阅读天数 `readDays`、总时长 `totalReadTime`（秒→时分）、自然日均 `dayAverageReadTime`、与上期对比 `compare`、读得最多 `readLongest`（≤10 条，含 `tags`）、`readStat` 摘要、偏好分类 `preferCategory`、偏好时段 `preferTime`
- **口径并列**：与现有「本地计时统计」**并列展示、互不覆盖**，面板显式标注「官方口径 / 本地口径」
- **边界**：`annually` 只返回 `baseTime` 所在自然年，跨年区间按官方文档拆多次查询再累加；`preferTime` 数组**从 6 点开始**（不是 0 点）；`totalReadTime` 严禁当分钟/小时

#### 10.2.5 书架同步（P0）
- **接口**：`/shelf/sync`（无参数）；可选：取 `books[]` 中 `readUpdateTime` 最近 5 本电子书调 `/book/getprogress`
- **数量口径（官方强制）**：总数 = `books.length + albums.length + (mp 非空 ? 1 : 0)`；公开/私密按各条目 `secret` 统计，`mp` 非空时私密额外 +1
- **展示**：书名/作者/封面/分类、置顶 `isTop`、读完 `finishReading`、私密 `secret`、最近阅读时间；条目跳转：官方 `deepLink` 是 `weread://` 移动端 scheme（电脑打不开），改为用书名到**同源** `/web/search/global` 解析出可直接打开的网页版详情页链接（`https://weread.qq.com/web/bookDetail/{哈希}`），解析失败再回退官方原 `deepLink`；专辑/有声书（`albums[]`）单独分区
- **边界**：**禁止**遍历 `books` 逐本调 `/book/info` 判断类型（`/book/info` 不返回 format 且极慢）；专辑不与电子书混算

#### 10.2.6 笔记 / 划线导出（P0）
- **接口**：`/book/bookmarklist`（划线内容，官方已过滤书签）＋ `/review/list/mine`（个人想法/点评，`abstract` = 对应原文、`range` 用于配对）；章节名优先用回包 `chapters`，必要时 `/book/chapterinfo`
- **导出**：Markdown / 纯文本（沿用现有 notes 模块的导出风格）；按章节分组；想法用 `range` 挂到对应划线下方，配不上的单列
- **口径（官方）**：笔记总数 = `reviewCount + noteCount + bookmarkCount`（来自 `/user/notebooks` 概览）；**书签只有数量，不能导出内容**
- **与现有「笔记」模块关系**：有 Key 且成功时用官方数据源；无 Key 或失败时自动回退现有同源接口 / DOM 抓取，并在面板标注数据来源
- **边界（易错）**：`/review/list/mine` 参数是**小写 `bookid`**，`/book/bookmarklist` 是**驼峰 `bookId`**，必须分别处理

#### 10.2.7 搜书 / 书评 / 推荐（P0）
- **搜书** `/store/search`：`keyword` ＋ **显式** `scope`（找书 10 / 泛搜 0 / 网文 16 / 听书 14 / 作者 6 / 全文 12 / 书单 13 / 公众号 2 / 文章 4）；翻页用最后一条 `searchIdx` 作 `maxIdx`
- **书籍详情 / 目录**：`/book/info`、`/book/chapterinfo`
- **公开书评** `/review/list`：`reviewListType`（0 全部 / 1 推荐 / 2 不行 / 3 最新 / 4 一般）；评分 20/40/60/80/100 → 1~5 星；翻页用最后一条 `idx` 作 `maxIdx`
- **推荐**：`/book/recommend`（个性化，翻页用 `searchIdx`）、`/book/similar`（相似书，**必须显式传 `count` 与 `maxIdx`**，翻页带 `sessionId`）
- **展示**：编号列表；书名/作者/评分/在读人数/分类；跳转：官方 `deepLink` 是 `weread://` 移动端 scheme（电脑打不开），改为用书名到**同源** `/web/search/global` 解析出可直接打开的网页版详情页链接（`https://weread.qq.com/web/bookDetail/{哈希}`），解析失败再回退官方原 `deepLink`（**禁止**自行拼 `weread://` 链接）
- **边界**：搜索结果是分页片段，文案不得用「共有 / 一共 / 总共」

#### 10.2.8 储备（P1，本轮不做）
- 热门划线 `/book/bestbookmarks`、章节划线热度 `/book/underlines`、划线下的想法 `/book/readreviews`、单条想法 `/review/single`
- 社交维度：好友排行（`/readdata/detail` 回包 `rank`）、官方「年度报告」风格长图
- 官方口径数据并入现有「阅读统计」的五种导出（JSON/CSV/MD/HTML/PDF）

#### 10.2.9 AI 人格化执行摘要（可选，DeepSeek，v0.14.0）
> **方案（用户选定）**：客观数据本机算准、人格化文字交给 DeepSeek 生成——数字不在 AI 侧计算，AI 只把已算好的客观统计写成「人格化执行摘要」，最接近 workbuddy 效果。

- **可选、独立开关**：「🔑 API Key」面板新增「AI 增强（DeepSeek，可选）」区，独立于 `wrk-` 官方 Key；不配置则报告「一、执行摘要」继续用规则化摘要，不影响其它章节
- **Key 管理**：`chrome.storage.local` → `wreDeepSeekKey: { apiKey, savedAt }`；须 `sk-` 开头；日志只留掩码；「清除」彻底删除
- **后台转发**：`background.js` 新增 `callDeepSeek()`（POST `api.deepseek.com/chat/completions`，`deepseek-chat`，30s 超时）＋ `wre-ai-status` / `wre-ai-save` / `wre-ai-clear` / `wre-ai-chat` 四个消息；`manifest.json` `host_permissions` 增 `https://api.deepseek.com/*`
- **数据链**：点击「导出」时按需触发 `runAIEnhance()`（打开报告**不**调用 DeepSeek，避免浪费 token）——`fetchAnnualTrend()`（最近 4 年 `/readdata/detail?mode=annually`）＋ `fetchBookContents()`（笔记最多前 5 本书的 `/book/bookmarklist` 划线 + `/review/list/mine` 想法原文样本，各最多 6 条）→ `buildAIPrompt()` 拼「书架 / 累计阅读 / 笔记 / 完读 / 分类偏好 / 原文样本 / 年度趋势」事实句 → DeepSeek → `splitParagraphs()` 分段 → `aiSummary` 写入「一、执行摘要」
- **分析口径（v0.14.7 起，用户选定）**：执行摘要与人格分析**固定基于「累计（总体）」数据**（`mode=overall`），**不随顶部周期切换变化**；报告页打开时并行预取累计数据（`loadOverallData()`，带 10 分钟缓存），导出时 AI 直接复用；正文各章节仍按所选周期统计。切换周期时若 AI 已生成成功则**保留结果不重复调用**（`aiState==='ok'` 时不重置），避免重复消耗 token
- **system prompt 约束**：克制客观、严格基于所给数据、不得虚构数字、不得杜撰用户没做过的事、直接输出正文自然段（不加标题/序号/Markdown）
- **失败兜底**：未配 Key / 生成失败 / 返回为空 → `aiState='skipped'|'error'`，退回规则化摘要；生成失败时报告内注明「AI 解读生成失败（原因），已退回规则化摘要」；**未配 Key 时**报告内注明「未配置 DeepSeek Key，配置后可生成人格化执行摘要与人性化人格分析」；**不阻塞报告主体**
- **隐私红线**：启用后仅把「笔记最多几本书」的划线/想法原文样本发给 `api.deepseek.com` 生成文字；「🔑 API Key」面板与 `release/privacy.md` / 网站隐私页同步明示；报告本身仍在本机生成

#### 10.2.10 AI 人性化人格分析（可选，DeepSeek，v0.14.3）
> **方案（用户选定）**：用 DeepSeek 生成一段「人性化人格分析」，像朋友口吻描述这位读者关心什么、怎么思考、是什么气质的读者，放在导出报告**最上方**（紧跟执行摘要）。

- **位置**：放在导出报告**最上方**——紧跟「一、执行摘要」之后（DeepSeek 的两段内容集中于此）；「十三、阅读人格画像」只保留客观标签表，并加提示「更深层的人性化解读见文档开头」
- **调用时机**：与执行摘要一致，点击「导出」时按需生成（打开报告不消耗 token）；两段 AI 内容**串行**调用——先执行摘要、再人格分析，避免并发触发限流；人格分析失败只记 `aiPersonaError` 并在面板提示，不影响报告主体；两段内容**固定基于累计（总体）数据**，与顶部周期无关，切换周期不重复调用
- **数据链**：复用 `runAIEnhance()` 已拼好的 `buildAIPrompt()` 事实句，用独立 system prompt（`AI_PERSONA_PROMPT`）串行调用第二次 `wre-ai-chat` → `splitPersonaPoints()` 解析为分点 → `aiPersona` 写入报告
- **输出结构（参考《深度阅读画像》样例）**：**分点呈现**——每个要点揭示一个最鲜明的阅读/思维特质，格式为「第N、小标题（2~6 字）＋论述正文」；渲染成四级小标题＋段落（类似样例中「第一性原理思维 / 系统化构建倾向 / 实践验证意识 / 自我观察习惯」的结构）
- **system prompt 约束**：克制客观、真诚有洞察、像朋友口吻；严格基于所给数据与原文、不得虚构事实；**做深挖而非概述**——每个论断落到具体证据（具体书名 + 划线/想法条数 + 原文或年度数字）；输出 4~6 个要点
- **失败兜底**：人格分析失败 / 返回为空 → `aiPersona=null`，该子小节静默省略，仅保留客观画像；**不影响执行摘要与报告主体**
- **边界声明**：人格分析段落下方注明「由 DeepSeek AI 基于客观数据与原文样本生成的参考性解读，不构成专业心理或性格鉴定」

### 10.6 风险与应对

| 风险 | 应对措施 |
|-----|---------|
| MV3 跨域：内容脚本直连 `i.weread.qq.com` 可能被 CORS 拦 | 统一走后台 service worker（配 `host_permissions`）；实测若网关已放开 CORS 则简化 |
| 新增 `host_permissions` 会触发安装/更新的权限提示 | 同步更新 README、`release/privacy.md` 与商店文案；权限只限 `i.weread.qq.com` |
| API Key 泄漏（日志 / 仓库 / release 包） | 只存 `chrome.storage.local`；日志掩码；打包前自查；文档不写真实 Key |
| 官方 `skill_version` 升级导致请求被拒 | 回包 `upgrade_info` 必须醒目提示；`SKILL_VERSION` 集中一处便于升级 |
| 字段口径误读（`noteCount` 是划线数、时长单位秒、`progress` 1=1%） | 以官方说明文件为准，写进代码注释与测试清单，禁止按字段名直译 |
| 与现有「本地口径统计」打架 | 两套口径并列标注、绝不合并覆盖；面板标数据来源 |
| 私密书籍也会被接口返回（`secret=1`） | 按官方口径展示并打「私密」标记，不额外过滤、不外传 |
| 「全面分析」被做成绝对化 / 评判性结论，或编造数据 | 只用报告已有指标写事实句；禁止绝对化、评判性、健康类建议；数据不足显示空态 |
| 报告依赖多个接口，任一失败导致整页空白 | 四段独立容错：某段失败只在该段提示「该维度暂不可用」，其余照常渲染 |
| 用户误以为 Key / 数据被上传 | 「报告」页固定一行「本机生成、数据不上传」；README 与 `release/privacy.md` 同步写明 |
| DeepSeek 生成文字会外发原文样本 | 明示为**可选**开关，未配置绝不外发；启用时设置页与隐私政策写清「仅发送笔记最多几本书的划线/想法样本到 api.deepseek.com」；样本条数封顶（每本 6 条） |
| DeepSeek Key 泄漏 | 与官方 Key 同策略：只存 `chrome.storage.local`、日志掩码、不落盘、可一键清除 |
| DeepSeek 输出幻觉 / 编造数字 | system prompt 强约束「严格基于所给数据、不得虚构数字、不得杜撰用户行为」；正文各章节数字仍为本机规则化统计，AI 摘要下方注明「具体数字以正文各章节的规则化统计为准」 |

### 11.0 可行性三问（结论先行）

| 问题 | 结论 |
|-----|-----|
| 可行性是什么 | **技术完全可行**——书架 `/shelf/sync`、笔记 `/user/notebooks`、搜书 `/store/search` 与网关底座在 `modules/official.js` 已跑通，可直接复用；「打标签」本质是在本机存一张「书 ↔ 标签」映射表 |
| 能不能做 | **能做**。第一版 = 拉书架 → 打标签 → 多维度搜索 → 导出防丢，就这几件事 |
| 有没有意义 | **有**。补的正是微信读书短板：它只有「文件夹式分组」（一本文只能进一个抽屉），标签可给一本文挂多个维度；且能搜「自己划过的句子 / 记过笔记的书 / 读完状态」，为官方所不能 |

> ⚠️ **唯一必须接受的现实**：官方 Agent 网关为**只读**（官方原文：「目前仅支持读取个人阅读数据，暂不支持自动加书架、同步笔记回传等写入操作」），标签**不能写回微信读书**，只存在于本机插件侧。这个代价换来的正是零上传、零权限、零风险。

### 11.1 需求三件事（先对齐）

**用户目标**：书架找书更快；用**标签**建立更多连接（而非只有文件夹式分组），让任意一个「记得的线索」都能定位到书。

**输入输出**
- 输入：本机登录账号的书架书目（`/shelf/sync`）＋ 用户自建标签（纯手工）
- 输出：一个「找书」面板——可打/管标签，可按书名 / 作者 / 标签 / 划线内容 / 笔记数 / 阅读状态等多维度搜索并定位
- 处理位置：**全部在本机**；标签只存 `chrome.storage.local`，不上传

**成功标准（可判定）**
1. 打开面板能看到完整书架清单，每本书可增删标签
2. 任一维度（书名 / 作者 / 标签 / 划线内容 / 有无笔记 / 阅读状态）都能搜到目标书
3. 标签支持多标签组合筛选（同时命中，如「认知科学」+「未读」）
4. 标签可重命名 / 删除 / 合并
5. 一键导出、导入 JSON；导入后标签完整还原
6. 全程零上传、不新增浏览器权限；现有功能（阅读统计 / 笔记 / 阅读洞察）行为不变

### 12.0 需求三件事（先对齐）

**输入输出**
- 输入：当前阅读页的书籍 ID ＋ 当前章节 ID（本机浏览器登录态，**无需 API Key**）
- 输出：阅读页**右侧可折叠侧栏**，按「当前章节」展示他人评论（头像 / 昵称 / 时间 / 正文），每条可展开其**引用的原文段落**

**成功标准（可判定）**
1. 打开阅读页后，右侧出现评论侧栏（可一键收起 / 展开），不影响正常阅读与翻页
2. 侧栏展示的是**当前章节**的他人评论，条数、内容与微信读书移动端「想法」一致（以接口实测为准）
3. 切换章节（点目录 / 上下一章 / 翻页）后，侧栏**自动刷新**为对应章节评论，无需手动操作
4. 每条带引用原文的评论，可**展开 / 收起**原文段落
5. 加载中 / 无评论 / 接口失败均有中文空态或提示，不阻断阅读、不报错崩溃
6. **不新增任何浏览器权限、不配置任何 Key、不上传任何数据**；现有功能（阅读统计 / 笔记 / 阅读洞察 / 屏占比）行为不变

> **背景**：现有 AI 增强（阅读报告的执行摘要 / 人格化文字）**只支持 DeepSeek**；但用户可能已经在用别家国产大模型（Key 在手），希望直接用自己习惯的那家，而不是被迫再注册 DeepSeek。

### 13.0 需求三件事（先对齐）

**用户目标**：AI 增强不再绑定 DeepSeek 一家——用户可自选国产大模型（填自己的 Key），也能继续用 DeepSeek。

**输入输出**
- 输入：用户在「🔑 API Key → AI 增强」里选定「提供商 ＋ 模型」并填该家 Key
- 输出：报告的执行摘要 / 人格化文字，由**用户选定的模型**生成
- 位置：**全部在本机**；Key 仅存 `chrome.storage.local`，不上传

**成功标准（可判定）**
1. 设置里可切换提供商（下拉）并填该家 Key；已配置的多家 Key **各自保留**、可来回切换
2. 切换后生成的文案确实来自所选模型（可用日志与模型名验证）
3. 未配置 Key 时明确中文提示，不报错、不阻塞报告其余部分
4. 现有 DeepSeek 用户升级后**无感**：原 Key、原行为不变，DeepSeek 为默认
5. **不出现任何国外模型入口**（OpenAI / Claude / Gemini / OpenRouter 等）
6. 不新增与所选提供商无关的权限

### 13.1 关键决策（已与用户确认，2026-10-05）

| 决策项 | 结论 | 影响 |
|-----|-----|-----|
| 模型范围 | **只用国产大模型**（明确排除国外） | 下拉与文案中不列任何国外模型 |
| 架构 | **一套「OpenAI 兼容」内核 ＋ 预设表**，不逐家写适配 | 加新厂商 = 加一行预设，不写新代码 |
| 内置预设 | **6 家**：DeepSeek（默认）/ 通义千问 / Kimi / 智谱 GLM / 豆包（火山方舟）/ 硅基流动 | 覆盖流行度与匹配度最高的国产阵营 |
| 自定义 | 提供「自定义 OpenAI 兼容端点」，**限国产厂商** | 覆盖 MiniMax / 阶跃星辰 / 百度千帆 / 腾讯混元 / 讯飞星火等，新厂商无需改代码 |
| 权限 | 内置家写 `host_permissions`（明确域名）；自定义走 `optional_host_permissions`，用到才授权 | 不滥权，商店审核可控 |

## 14. 语音复习（听自己的笔记 · 插件端）— 已实现（v0.24.0）

> **状态：已开发**（`modules/tts.js` ＋ `modules/tts.css`，接入 `modules/notes.js`）
> **决策日期：2026-10-06**
> **背景**：用户提出「把一段文字用语音读出来、用听觉复习 / 学习」的需求，对标汤质《孤岛电台》（kanbenzhi.com）。核对结论：**官方「听书」已覆盖整本书朗读**，我们**不重复**；空位是「**听自己的笔记**」（划线 / 想法）。

### 14.0 需求三件事（先对齐）

**用户目标**：在「不方便看」的场景（通勤 / 走路 / 闭眼）用**听觉复习自己的阅读笔记**。

**输入输出**
- 输入：用户**自己的**素材——单条划线 / 自己的想法 /「📝 笔记」面板里的条目
- 输出：由**浏览器内置 TTS 本机合成**的语音，支持**播放 / 暂停 / 停止 / 上一条 / 下一条**
- 位置：**全部在本机**；不出网、不上传

**成功标准（可判定）**
1. 在「📝 笔记」的划线 / 想法条目上可点「▶ 听」逐条朗读
2. 可「连续朗读」（把当前筛选结果按章节顺序串起来），支持播放 / 暂停 / 停止 / 上一条 / 下一条
3. **未联网、未配置任何外部服务**也能朗读（走浏览器内置语音）
4. 关面板 / 切页签 / 关页面 → **立即停止**，不在后台偷偷播
5. 文案只用「**朗读 / 听**」，**不得出现「听书 / 电台 / 节目」**

### 14.1 关键决策（已与用户确认，2026-10-06）

| 决策项 | 结论 | 影响 |
|-----|-----|-----|
| 技术方案 | **Web Speech API**（`speechSynthesis` ＋ `SpeechSynthesisUtterance`） | 零依赖 / 零成本 / 不联网 / **不新增权限** |
| 端优先级 | **插件端先做**（本章）；移动端为**可选增量**（见移动端文档 M14，P2） | 移动端无内置任意文本 TTS，需额外依赖与成本 |
| 范围 | **A ＋ B 档，去 C**（见 14.2） | 不做人格播报 / 报告摘要朗读 |
| 入口 | **不新增主菜单**；在**已有内容处就地加「▶ 听」** | 符合「旧代码不改，就地增强」 |
| 版权 | **不提供书摘音频分享 / 导出** | 划线属书中原文，本机自听可、公开传播有版权风险 |

### 14.2 朗读范围（A ＋ B 档，去 C）

- **A 档（第一版）**
  - **单条划线**：「📝 笔记」每个划线条目加「▶ 听」
  - **自己的想法**：每个想法 / 批注条目加「▶ 听」
  - **连续朗读**：把当前页签 / 当前搜索结果**按章节顺序串读**（如「《XX》我的 10 条划线」）
- **B 档（第二版）**
  - **面板级「听全部」**：一键把当前书的划线 / 想法排队朗读
  - **「只听想法」模式**：只读用户自己写的
  - （若插件端后续引入移动端 M11 / M12 的回顾产物，一并对接；**本期不做**）
- **C 档（不做）**：人格播报、报告摘要朗读

### 14.3 详细功能需求

#### 14.3.1 单条朗读（P0）
- 「📝 笔记」的划线 / 想法条目右侧加「▶ 听」小按钮（类名统一 `wre-` 前缀）
- 点击即朗读该条正文；朗读中按钮变「⏸」，再点暂停 / 继续
- 同一时刻**只播一条**；点新的一条，自动停掉上一条

#### 14.3.2 连续朗读（P0）
- 面板工具条加「▶ 连续朗读」：按**当前可见顺序**（章节分组 → 组内顺序）建立播放队列
- 控制条：播放 / 暂停 / 停止 / 上一条 / 下一条 ＋ 显示「第 N / 共 M 条」
- 朗读中滚动到当前条目（可选）

#### 14.3.3 停止与边界（P0）
- 关闭面板 / 切换页签 / 关闭页面 → **立即 `speechSynthesis.cancel()`**
- 浏览器不支持 `speechSynthesis` → **隐藏「▶ 听」** 并给一句中文说明，不影响其它功能
- 多标签页各自播放互不串（不做跨页同步）

### 14.4 UI / UX 需求
- 入口：沿用现有「📝 笔记」面板，**不新增主菜单项**
- 控件：极简——条目级「▶ 听」＋ 面板级「连续朗读」小工具条
- 文案：统一「**朗读 / 听**」；不出现「听书 / 电台 / 节目」
- 明示「**本机朗读，不联网、不上传**」，不显示任何「云端合成」字样

### 14.5 技术实现方案
- **API**：`window.speechSynthesis` ＋ `new SpeechSynthesisUtterance(text)`；中文语音从 `speechSynthesis.getVoices()` 里挑 `zh-CN`（取不到用默认）
- **新增模块**：`modules/tts.js`（＋ `modules/tts.css`），封装「单条 / 队列播放 / 暂停 / 停止 / 上一条 / 下一条」；沿用既有统一日志 `log()`（前缀 `[TTS]`），不新增旁路打印
- **接入点**：`modules/notes.js` 渲染划线 / 想法条目时挂「▶ 听」；面板关闭钩子里调 `tts.stop()`
- **不改旧逻辑**：只加按钮与事件绑定，**不改动**笔记的取数 / 导出 / 搜索 / 定位
- **manifest**：**不新增任何权限 / 主机**（Web Speech API 属浏览器能力）
- **边界**：只读文本、不落盘、不出网

### 14.6 分阶段规划
> 排序原则：先完成再完美。

- [x] 阶段十七-1：`modules/tts.js` 基础（单条朗读 ＋ 暂停 / 停止）＋ 中文语音选择
- [x] 阶段十七-2：「📝 笔记」条目挂「▶ 听」＋ 面板关闭停止
- [x] 阶段十七-3：连续朗读队列 ＋ 控制条（上一条 / 下一条 / 第 N 共 M）
- [x] 阶段十七-4：B 档（听全部 / 只听想法）＋ 文档回灌 ＋ 测试清单

> 实现落点：`modules/tts.js`（`window.WRETTS`：单条 `playOne` / 队列 `playList` / 暂停·停止·上一条·下一条；Web Speech API，中文语音优先本地 `zh-CN`；文本按句分段朗读规避 Chrome 长句截断；切后台 / 关页面即停）、`modules/tts.css`（条目「▶ 听」圆钮 + 弹窗底部控制条）、`modules/notes.js`（工具栏「▶ 连续朗读 / ▶ 听全部 / ▶ 只听想法」+ 条目按钮 + 关闭 / 重绘即停）。

### 14.7 风险与应对

| 风险 | 应对措施 |
|-----|---------|
| 浏览器中文语音缺失 / 发音生硬 | `getVoices()` 优先中文；取不到用默认并提示；不报错 |
| 长时间朗读被浏览器节流 / 卡顿 | 逐条分段朗读 ＋ 页面失焦即停；**不做后台常驻播放** |
| 与官方页面快捷键 / 焦点冲突 | 「▶ 听」走独立按钮点击，不抢全局键盘 |
| 用户误以为要联网 / 收费 | 文案明示「**本机朗读，不联网、不上传**」 |
| 划线属书中原文，音频外传有版权风险 | **不提供音频分享 / 导出**（红线） |
| 与官方「听书」功能重叠 | 明确定位差异：读的是「**自己的**笔记」，不是整本书 |
