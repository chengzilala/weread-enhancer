## 0. 需求三件事

| 项 | 内容 |
|---|---|
| **用户目标** | 在插件 / H5 / 小程序里，能按**微信读书官方的书架分组**看自己的书、筛自己的书——不必再靠插件私有标签重建一份分类 |
| **输入** | 用户自己的 `wrk-` Key 拉到的官方书架 `/shelf/sync`（只读），其中 `archive[]` 即官方分组 |
| **成功标准** | 三端都能：①看到官方分组；②按分组筛选 / 分区浏览；③条目上能看出属于哪个官方分组；④**只读**——不改动、不上传、不上报；⑤旧功能（标签、状态/笔记/时间筛选、缓存、分享图）行为不变 |

## 1. 背景：官方分组能拿到（已实测）

### 1.1 实测结论

`/shelf/sync` 顶层只有 4 个字段：`mp`、`albums`、**`archive`**、`books`。

- **`archive[]` 就是「官方分组」**：每项结构为 `{ name, bookIds[], albumIds[] }` —— 有名字 + 组内书目 id 列表。
- 实测账号：**24 个分组**、709 本电子书、1 个有声专辑。
- **分组是「反着存」的**：不是「每本书写着自己属于哪组」，而是「每组列着有哪些书」。要展示「某书属于哪组」必须**反查** `archive`。
- 书条目本身只有 8 个字段（`bookId / deepLink / title / author / updateTime / secret / finishReading / readUpdateTime`），**不含分组**——所以三端现有 `slimShelf()` 都只挑固定字段、把 `archive` 丢了。

### 1.2 与现有「标签」的区别（务必分清）

| | 官方分组 | 插件本机标签 |
|---|---|---|
| 来源 | 微信读书官方（`/shelf/sync` 的 `archive`） | 插件私有（`chrome.storage.local` → `wreBookTags`） |
| 归属 | 官方规则（一本文通常只在一个组） | 一本文可挂**多个**标签 |
| 可否改 | **只读**（网关不提供写接口） | 可增删改 |
| 跨端 | 三端都能读到同一份 | 仅插件本机（H5/小程序无） |

> 本需求**只读官方分组**，与「标签」并存、互不覆盖。UI 上必须让用户一眼分清（见 §3.4）。

### 1.3 红线

- **只读**：官方分组**不能**在插件里新建 / 重命名 / 移动 / 删除；网关不提供写接口。
- 不新增任何浏览器权限；分组数据只在向 `i.weread.qq.com` 取书架时获得，**不额外请求、不上传**。

## 2. 数据模型（三端统一）

三端共用同一口径：**只在各自 `slimShelf()` 里多解析一个 `groups`，并把分组名反挂到条目上**。

### 2.1 `slimShelf()` 返回结构扩展

```js
slimShelf(data) → {
  books:  [ { ...现有字段, groups: ['分组名', ...] } ],
  albums: [ { ...现有字段, groups: ['分组名', ...] } ],
  groups: [ { name: '分组名', bookIds: [...], albumIds: [...], count: N } ],
  hasMp:   Boolean,
  bookCount: Number,
}
```

### 2.2 归一规则

1. **来源**：`data.archive`（数组）。缺失 / 非数组 → `groups: []`（不报错、不影响旧功能）。
2. **分组项**：取 `name`（`String().trim()`）。`name` 为空的分组**跳过**（不产生无名组）。
3. **反查挂载**：遍历 `groups`，把 `name` push 进对应 `bookIds` / `albumIds` 指向的条目 `groups` 数组（**去重**）。
4. **顺序**：`groups` 保持 `archive[]` 原顺序（即官方排序），不自行重排。
5. **`count`**：`bookIds.length + albumIds.length`（用于 UI 显示组内数量）。
6. **虚拟「未分组」**：由**前端动态计算**（= `books ∪ albums` 中 `groups` 为空的条目），**不写进 `groups` 数组**，以免污染官方口径。

### 2.3 缓存兼容

- 三端书架缓存均为 **30 分钟**（插件 `wreFinderShelfCache` / H5 `overview` / 小程序 `overview`）。
- 升级后若命中**旧缓存**（无 `groups` 字段）：视同「暂无分组数据」——`groups` 取默认空、条目不显示分组；用户下拉刷新 / 点「刷新书架」后即带分组。**不强制清缓存**（避免打断）。

## 3. UI 需求（分端）

> 统一命名：UI 上一律叫「**官方分组**」，与「标签」并列且视觉可区分。

### 3.1 插件（`modules/finder.js`，「🔎 找书」面板）

- **筛选**：在现有「按标签筛选」下方新增一行「**官方分组**」chips（可多选）。
  - 匹配：选中多个分组时**任一命中（OR）**即可（一本文通常只在一组，AND 意义不大，故**不做** AND/OR 切换，保持简单）。
  - 与现有筛选（关键词 / 标签 / 状态 / 笔记 / 最近）**叠加（AND）**。
  - 提供「清除已选」。
- **条目展示**：书卡 / 专辑卡在原有信息行下方，展示所属官方分组（如 `官方分组：财商`；多组用 `、` 连接）。
  - 样式：**中性灰胶囊**，与「本机标签」的**绿色胶囊**明显区分；不加 ×（只读，不可点移除）。
- **关键词搜索**：把**分组名**纳入关键词命中范围（输「财商」能搜到该组下的书）。
- **清空/重置**：官方分组 chips 行提供「清除已选(N)」，一键清空已选分组（与「按标签筛选」的清除已选一致）；打开面板时已选分组与关键词一样从空开始。

### 3.2 H5（`h5/src/views/shelf.js`，书架页）

- **分组分区**：新增「**按官方分组**」区块，按 `groups` 逐组渲染：组名 + 组内数量 + 组内书目（封面 / 书名 / 作者）。
  - 每组默认展示前 N 本（建议 12）+「还有 X 本」占位，避免长列表卡顿。
  - 组内为空则整组不渲染。
- **「未分组」**：若有未分组条目，追加一个「未分组（N）」区块，置于最后。
- **保留原有**：概览卡片、分类分布、最近 20 本、专辑、分享图**全部不变**（分组是**新增区块**）。
- **样式**：复用现有 `wre-card` / `wre-book` / `wre-tag` / `chips` 类，不引入新依赖。

### 3.3 小程序（`mobile/miniprogram/pages/shelf/*`，书架页）

- **分组分区**：同 H5——按 `groups` 逐组渲染「组名 + 数量 + 组内条目」，外加末尾「未分组」。
- **数量上限**：沿用 `SHELF_MAX = 100` 的**单次渲染**保护；分组视图下改为「**每组**上限 N 本 + 组内『还有 X 本』」，总渲染量仍受控。
- **交互**：点条目仍是复制「书名 · 作者」（小程序无法外跳）；分组名可点展开 / 收起。
- **保留原有**：概览卡片、分类分布、分享图生成**不变**。

### 3.4 三端一致约定

| 约定 | 说明 |
|---|---|
| 名称 | 统一叫「官方分组」 |
| 只读 | 无任何编辑入口；不显示 × / 重命名等 |
| 与标签区分 | 官方分组用**中性灰**；本机标签用**主题绿** |
| 空态 | 账号无分组时，该区块整体隐藏（不显示空壳） |
| 顺序 | 按官方 `archive[]` 原顺序 |
| 文案 | 不夸大；如实说明「只读、来自官方书架」 |

## 4. 边界与红线

- **只读**：不改官方分组；不调用任何写接口。
- **无新权限**：复用现有 `storage` 权限；不新增 host 权限。
- **不影响旧功能**：三端原有书架展示、标签、筛选、缓存、分享图行为必须回归通过。
- **旧代码不改**：插件侧沿用「新功能进 `modules/`」约定；本次在 `finder.js` 内扩展，不重写既有逻辑。
- **日志**：沿用各自既有日志（插件 `logFinder`），只记分组数量等，**不打印整份书目明细**。
- **隐私**：分组仅本机展示；与现有书架数据同等对待，不上传。

## 5. 待确认 / 风险（实现前自检）

| # | 事项 | 处理 |
|---|---|---|
| R1 | `archive[].bookIds` 与 `books[].bookId` 是否**同一 id 空间**（实测书 id 形如 `CB_...`，与旧「纯数字」口径不同） | 实现时先加一次性自检日志，确认能对上；对不上则改用 `deepLink` 哈希或书名兜底。**已实现**：插件 `slimShelf()` 记 `[finder] 官方分组解析` 日志（groups / archiveBookIds / matchedBooks / archiveAlbumIds / matchedAlbums），真机核对 `matchedBooks` 是否接近 `archiveBookIds` |
| R2 | `archive[].albumIds` 与 `albums[].albumInfo.albumId` 是否同空间 | 同上（同一日志的 `archiveAlbumIds` / `matchedAlbums`） |
| R3 | 一本书是否可能属于**多个**分组 | 按「可多个」处理（数组显示）；若实测恒为 1，UI 自然退化为单值 |
| R4 | `archive` 是否含「全部 / 默认分组」之类的系统项 | 若含，需识别并跳过 |
| R5 | 分组名是否可能重复 | 若重复，按名字合并展示（挂载时取并集） |
