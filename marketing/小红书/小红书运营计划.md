## 一、分析

### 1.1 平台特性（决定「怎么写、怎么发」）

| 特性 | 对本次推广的含义 |
|---|---|
| 图文笔记为主，**3:4 竖版**最佳 | 首图即封面，直接决定点击率 → 用 `配图-01-封面` 当封面 |
| 用户偏 18–35 岁、女性占比高，**读书 / 自我提升 / 效率工具 / 学习**是热门赛道 | 微信读书用户与小红书受众高度重叠，属「种子人群」 |
| 双流量入口：**推荐 + 搜索** | 标题塞进「微信读书 / 阅读 / 插件」等搜索词；话题 ≤20 个 |
| 正文 ≤ 1000 字；标题 ≤ 20 字 | 正文已按此裁剪；首屏信息必须够勾人 |
| **弱外链**：正文不能放可点外链 | **且连"纯文字域名 / 商店搜"也不要写**（会被判站外引导）→ 正文只留软引导，入口走私信 |
| 限流雷区 | 硬广口吻、二维码、外链、诱导点赞收藏、大段重复搬运 → 全部规避 |
| 传播链 | 点击（封面+标题）→ 互动（赞藏评）→ 涨粉 / 搜索沉淀 |

### 1.2 产品 × 平台匹配度

- **强匹配**：「微信读书」是国民级读书 App，小红书读书/学习赛道天然吃这套内容，无需教育用户。
- **卖点翻译成「小红书语言」**（决定文案风格）：
  - 屏占比 / 沉浸阅读 → 「网页版太挤，我给它瘦了身」
  - 阅读人格 MBTI → **自带分享图 + 蹭 MBTI 热度**，是最可能的爆点
  - 笔记聚合 / 导出 / 朗读 → 「划过的线，别再躺着睡觉」
  - 隐私与本地存储 → 建立信任、降低「装插件怕不安全」的顾虑
- **风险 / 短板**：
  1. 插件是**电脑端**，而小红书以手机用户为主 → 用「手机版 H5」在文案里接住手机流量；
  2. 「插件 / API Key / 大模型」偏技术，需**用生活化例子讲**，避免劝退；
  3. 平台对「工具类硬广」敏感 → 全程用**第一人称亲测口吻**，弱化广告感。

### 1.3 目标受众分层（决定选题优先级）

| 分层 | 画像 | 最吃的卖点 |
|---|---|---|
| A 读书打卡党 | 学生 / 考研 / 考公 | 统计、笔记、专注勿扰 |
| B 效率工具控 | 白领 / 产品 / 开发 | 屏占比、导出、找书、快捷键 |
| C MBTI / 自我探索 | 泛人群（传播面最大） | 阅读人格、分享图 |
| D 微信读书重度用户 | 各年龄段 | 全功能、隐私、手机版 |

### 1.4 结论（分析落点）

> **钩子 = 痛点（网页版难用）+ 亲测口吻 + 人格图传播**；
> **首发用「综合全面版」建立完整认知，再用「阅读人格」单篇冲量，最后靠系列分篇承接搜索长尾。**

### 2.5 发布操作（最后一步：浏览器）

- **发布素材包**：即本目录（29 张配图 + `小红书文案.md` + 本计划 + `说明.txt`），发布即用。
- **按帖子分好文件夹（发帖直接用这个）**：`python3 tools/xhs_post_folders.py` → 本目录 `帖子/<编号>-<短标题>/`，每篇一个文件夹、只放该篇要用的 6–7 张，文件名带 `01-` / `02-` 上传序号（第一张即封面）。文案改了重跑一次即可刷新；该文件夹是复制件、不入库。
- **半自动脚本（本项目首选）**：`tools/xhs_publish.py`
  1. 脚本打开小红书创作服务平台（Playwright + Chrome for Testing，复用项目现有环境）；
  2. **你扫码登录**（登录态存入 `.autoshot/xhs-profile/`，之后免登）；
  3. 脚本自动切「上传图文」→ 上传该篇配图（主推 16 张；`--post A1` 等只传本篇引用的图）→ 填好标题 / 正文 / 话题；
  4. **停在「发布」按钮前**，你核对后自己点「发布」。
  5. **发布后立刻**：发第一条评论（＝**软引导**，见文案「评论区置顶」模板）并**置顶**；**不放链接**，有人问再私信发入口。
  - 选篇：`--list`（列出全部）/ `--list A`（按分类）/ `--post A1`（按编号）/ `--post "篇 1"`（系列分篇）。
  - 正文来源＝本目录 `小红书文案.md`（综合 §2 / 系列 §3 / 扩展 §3.5），**单一事实源，改文案自动同步**；正文末尾已统一带**软引导**句（零站外信息）。
  - 备用：`python3 tools/xhs_publish.py --post A1 --dry` 只打印内容不操作，便于先核对。
- **降级方案**：若脚本受页面改版影响，改用「浏览器助手逐步操作」或人工上传（素材已就绪）。

## 三、内容扩展与引流策略（从 9 篇 → 45 篇）

> **一句话**：小红书不是「发广告能爆」的地方。**先把账号养起来（垂直度 + 互动），再谈转化**——所以本次把内容从「9 篇讲产品」扩成「45 篇引流矩阵」，其中一半是**不带产品的破圈内容**。

### 3.1 核心思路：先涨粉、再种草、后转化（配比 5 : 3 : 2）

| 层 | 作用 | 占比 | 特征 | 带产品？ |
|---|---|---|---|---|
| **破圈层** | 涨粉 / 破圈 / 立人设 | 50% | 趣味测试、痛点共鸣、读书干货 | 不带（最多末尾轻带） |
| **种草层** | 建立「我也想要」 | 30% | 第一人称亲测功能演示 | 带，弱转化 |
| **转化层** | 安装 / 使用 | 20% | 教程、入口、工具合集 | 强引导 |

> **首篇发「综合全面版」（全面介绍为主）、其后冷启动期「只发破圈层」**：先用一篇综合全面版把功能一次讲全、立住「完整认知」，再把账号做成「读书人号」，涨粉 + 让系统打上「读书」标签后，再上更多产品内容。

### 3.5 引流闭环（把流量接住）

1. **账号装修**：昵称含「读书」词；简介含「微信读书网页版增强」（**不写域名**）；背景图用横版展示图。
2. **搜索词布局**（吃搜索长尾）：标题 / 正文塞 `微信读书`、`微信读书插件`、`微信读书网页版`、`读书笔记`、`阅读工具`、`浏览器插件`、`阅读人格`、`MBTI 读书`。
3. **主页置顶**：把「综合全面版」或跑得最好的破圈笔记置顶。
4. **评论区承接**：每篇发布后立刻**置顶软引导**（见文案第 0 节模板，**不放链接**）；有人问就**私信**发入口；主动回复前 20 条评论。
5. **私信 / 关键词**：简介写「想装评论『悦读』」，评论区引导，**别在正文堆链接**。
6. **跨篇导流**：每篇末尾提「主页还有 XX 篇」，把爆款流量导给转化篇。
7. **节点蹭流量**：世界读书日（4/23）、开学季、年末年度报告、考研季——提前 3 天备稿。

### 3.6 快速见效的 5 个关键动作

1. **封面 + 标题决定 80% 点击**：封面用大字提问式（「你的阅读人格是？」），标题带情绪 + 关键词。
2. **首图即封面**：留白 + 一句话，别把字堆满。
3. **发布时段**：读书 / 学习类选 12:00–13:00、21:00–23:00（睡前）最佳。
4. **结尾抛问题**（「你读了多少？」），拉高评论率推动推荐。
5. **A/B 复用**：一个爆款换标题 / 封面再发，边际成本最低。
