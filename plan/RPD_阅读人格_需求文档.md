# RPD — 阅读人格（读书人版 MBTI）

> **性质**：插件「🪞 阅读洞察」的延伸模块（阶段十四）。基于用户自己的官方阅读数据，在本机推出一套**16 型「读书人」人格**，并输出**一个人格化的人和一份词语分析**。
> **同源文档**：插件主需求见 [RPD_需求文档.md](./RPD_需求文档.md)（第 10 章阅读洞察、10.2.9/10.2.10 已有的 AI 人格化文案不重复、不覆盖）；网站生态见 [RPD_网站生态_需求文档.md](./RPD_网站生态_需求文档.md)。

**文档版本：v0.3.3（人物替换：法布尔 → 李时珍）**
**最后更新：2026-10-04**
**状态：V1 已落地（插件 v0.18.0 人格 + v0.19.0 分享图人物插画；网站栏目 v0.3.1 已落地）**

## 0. 需求三件事

| 项 | 内容 |
|---|---|
| **用户目标** | 用自己真实的阅读数据，得出一个**具体、可分享、有代入感**的「阅读人格」：我是哪种读书人、我关心的词是什么 |
| **输入** | 用户自己的 `wrk-` Key 拉到的官方数据（阅读时长/天数/偏好分类/时段/书架/笔记划线想法原文）；可选 DeepSeek Key |
| **输出** | ① 4 字母「阅读人格代码」+ 主称号（16 型之一）② 一段「人格化的人」画像（称号卡 + 三个特质绰号 + 一句定调 + 画像正文 + 数据/原文佐证）③ **词语分析**（高频词 TOP10 / 情绪比例 / 你的口头禅 / 主题词）④ 词云（可选）⑤ **手机版分享图**（竖版 PNG：**人物插画** + 人格卡主体 + 词语亮点 + 数据证据 + 品牌署名，一键复制 / 下载） |
| **成功标准** | 任意有足够数据的账号能算出结果，且**每一维都能点出具体数据佐证**；数据不足时**明确说明**而不是硬出结论；**不配 AI 也完整可用**；**一键生成手机版分享图并可复制/下载**；不出现被冒犯的表述 |

## 1. 概述

### 1.1 这是什么

一句话：**给读书人做的 MBTI——不是问你喜欢内向还是外向，而是从你真正读过的书、划过的线、写下的想法里，把你这个人推出来。**

它和现有功能的关系：

| 现有 | 本需求 | 关系 |
|---|---|---|
| 10.2.10「AI 人性化人格分析」（v0.14.3）：一段散文式 AI 解读，分 4~6 个要点 | 本需求 | **升级为结构化体系**：先有 4 维判定（可解释、可复算），再生成文案；AI 从「主力」降为「润色」 |
| 十三章「阅读人格画像」：规则化客观标签表（笔记投入型 / 主题聚焦度…） | 本需求 | **复用其指标**，升格为 16 型体系里的「三个特质绰号」 |
| 10.2.9「AI 人格化执行摘要」 | 本需求 | 不冲突，保持独立 |

**红线**：不覆盖、不删除上面两者；本需求是新增章节，旧内容原样保留。

### 1.2 复刻对象（网上已有先例，直接照抄骨架）

| 参考 | 它的做法 | 我们借什么 |
|---|---|---|
| `wereadwave.cn`「阅读人格画像 · 基于微信读书」 | MBTI + 大五开放性 + 认知闭合需求；输出「建构主义者 · 权力解剖师 · 概率思维者」三个绰号 + 每个特质的**原文引用证据** | ①「一个主称号 + 若干特质绰号」的呈现结构 ②**每个论断必须挂原文/数据证据** ③「你读过的书是一面没有滤镜的镜子」的克制口吻 |
| 有人在微信读书 API 上设计的 **SLCP 四维框架** | 能量获取 S/M（单本深潜 / 多线并行）、信息处理 L/F（逻辑 / 感性）、决策 A/C（认同 / 批判）、组织 P/D（计划 / 漂流） | 「四维不用 MBTI 原维度、改用**可从阅读数据算出来**的维度」这一核心思路 |
| 通用 MBTI 产品结果页 | 类型名 + 人口占比 + 3 个核心标签 + 3 个优势 + 四维百分比进度条 + 分享海报 | 结果页的**信息骨架**与可视化形式 |
| 现有 `AI_PERSONA_PROMPT`（v0.14.3） | 把客观统计 + 原文样本交给 DeepSeek 写人格分析 | 复用同一套「客观数据本机算、文案交给 AI」的口径与隐私边界 |

### 1.3 为什么不做成 MBTI 原版四维

MBTI 的 E/I、S/N、T/F、J/P 是**问卷测偏好**的，从行为数据里推不出来，硬套会变成瞎猜。所以：

- **四维改成「阅读行为可测维度」**（见 3.2），每维都有明确的官方字段与算法；
- **字母体系与 MBTI 不通用**，页面上明确写「阅读人格代码，和 MBTI 码不是一回事」；
- 对外**不使用 MBTI® 商标名**（见 3.8）。用「读书人版人格 / 阅读人格 16 型」。

### 1.4 目标用户

- **主**：已配置 `wrk-` Key、有一定阅读量与笔记量的微信读书重度用户（数据够，结论才有说服力）；
- **次**：数据较少的新用户——**允许算，但降级呈现**（见 3.7），绝不能硬出结果。

### 1.5 当前状态

- **插件侧 V1 已落地（v0.18.0 / v0.19.0）**：报告首屏「🧬 我的阅读人格」——四维判定 + 16 型称号 + 词语分析 + 手机版分享图（v0.18.0）；分享图 16 型人物插画（自绘线描 SVG，见 3.10）于 **v0.19.0** 落地并同步进报告人格卡与 HTML / Markdown 导出；
- 插件原有能力：`wrk-` Key 管理与校验、官方网关封装、阅读行为报告 V1/V2、AI 执行摘要（v0.14.0）、AI 人性化人格分析（v0.14.3）、API Key 集中入口（v0.14.2），以及阅读统计 / 书架 / 笔记 / 搜书等附带能力；
- **复用的基础**：`buildPersonaTags()` 的规则化标签 → 作为「特质绰号」来源；`AI_PERSONA_PROMPT` + `runAIEnhance()` → AI 润色通道；`logOfficial()` → 判定过程调试日志；
- 约束：**不引入任何外部依赖**（含中文分词库），全部本机计算；人物插画为**内置自绘 SVG**，运行时不联网。

## 3. 详细需求

### 3.1 可用数据源（全部来自官方，本机计算）

| 字段 | 来源接口 | 用在哪一维 |
|---|---|---|
| 累计/周期时长 `totalReadTime`（**秒**）、`readDays` | `/readdata/detail` | D1、D4 |
| 年度时长轨迹（各统计单元） | `/readdata/detail`（overall/年） | D4 |
| 偏好分类 `preferCategory`（含权重） | `/readdata/detail` | D2、D4 |
| 偏好时段 `preferTime`（24 格，**数组从 6 点开始**） | `/readdata/detail` | D4、绰号「夜读者」 |
| 偏好作者/出版社、读得最久的书 `readLongest`、成就勋章 | `/readdata/detail` | 绰号 |
| 书架结构（电子书/专辑/文章，分类聚合） | `/shelf/sync` | D1、D2 |
| 笔记概览（划线数 / 想法数 / 书签数 / 总数） | `/user/notebooks` | D3、绰号 |
| **笔记最多的 Top N 本书的划线/想法原文** | `/user/notebooks` + 书内笔记接口 | **D3、词语分析（语料）** |
| 完读率（已读完口径） | 书架 + 进度 | D1 |

> **口径红线（沿用现有）**：官方时长单位是**秒**；时间戳转日期展示；**分母是自然日、不是阅读天数**，文案必须写清。

### 3.2 四维模型（读书人版）

> 每维输出「字母 + 判定值（0~100）+ 一句依据」。判定值用于进度条，依据用于「证据」区。

#### D1 阅读能量：深潜 **D**（Depth） ↔ 广撒 **B**（Breadth）
- **问题**：你是把一本书读穿，同时开很多本？
- **数据**：① 单本平均投入时长（总时长 ÷ 有阅读记录的书数）② 书架分类集中度（前 3 类占比）③ 完读率 ④ 在读并行度（V1 用「同期有笔记的书数」近似，V2 接入官方在读列表）
- **判定**：单本时长高 + 集中度高 → **D**；单本时长短 + 分散 → **B**
- **绰号池**：深潜者 / 通读者 / 图书馆漫游者 / 杂食派

#### D2 内容取向：求实 **F**（Fact） ↔ 求意 **M**（Meaning）
- **问题**：你更想要"能用上的"，还是"想明白些的"？
- **数据**：`preferCategory` + 书架分类聚合，映射到两组
  - 求实组：职场/经济·理财/科技·互联网/自我提升/健康/教育/工具
  - 求意组：文学/历史/哲学/心理/社科/艺术/传记
- **判定**：某组占比 ≥ 60% → 该极；40%~60% → 取占比高者但标注「居中」
- **绰号池**：解决问题的人 / 手艺派 / 追问者 / 意义收集者

#### D3 表达方式：理性 **L**（Logic） ↔ 感性 **E**（Emotion）
- **问题**：你的划线和想法，是"分析"还是"共情"？
- **数据**：对笔记语料（划线 + 想法正文）做**本地词表计数**
  - 逻辑词表：因为/所以/本质/逻辑/系统/结构/方法/步骤/数据/结论/假设/验证/机制…
  - 情感词表：喜欢/感动/难过/温暖/孤独/美/爱/心疼/遗憾/自由…
  - 辅助信号：感叹号占比（感性 ↑）、问号占比（理性 ↑）
- **判定**：逻辑词占比 − 情感词占比 → 差值 > +10% 判 **L**，< −10% 判 **E**，中间判居中方并标注
- **绰号池**：拆解者 / 提问机器 / 共情者 / 划线诗人

#### D4 阅读节奏：计划 **P**（Plan） ↔ 随兴 **R**（Roam）
- **问题**：你是"按计划读"，还是"随缘漂"？
- **数据**：① 有阅读天数占比 + 周内波动（方差小 → P）② 主题连贯性（相邻统计单元偏好分类是否稳定）③ 年度时长轨迹的平滑度
- **判定**：规律 + 稳定 → **P**；跳跃 + 漂移大 → **R**
- **绰号池**：清单执行者 / 节奏派 / 缘读者 / 兴趣漂流者

> **代码格式**：`D1D2D3D4`，如 `DFLP`。四维各自的**置信度**随数据量变化，某一维数据不足时该位显示 `–`（如 `DF–P`），并在卡片上说明「这一维数据还不够」。

### 3.4 「输出一个人格化的人」

结果卡的固定结构（顺序即展示顺序）：

1. **人格卡**：`DFLP` 代码 + 主称号 + 三个特质绰号（如「深度精读型 · 主题聚焦型 · 夜读者」，由 3.5 与现有画像标签生成）
2. **一句定调**（3.3 表里的那句）
3. **一句话画像**：「你是那种……的人」——必须由**已算出的判定 + 数据**生成，不许自由发挥
4. **四维进度条**：每维给左右两极与百分比（如 深潜 78% ↔ 广撒 22%）
5. **证据区**（复刻 wereadwave 的做法，**这是可信度的关键**）：
   - 数据证据：累计 247 小时 · 划了 861 条线 · 写了 63 条想法 · 书架 42 本
   - 原文证据：2~3 条**真实引用**（带书名与年份），用于支撑「求意」「感性」这一类判定
   - 口吻红线：**只描述、不评判**；不用"懒惰/拖延/浅薄"这类负向词，全部中性化
6. **你的口头禅**：从划线里挑一句最高频/被划最多的（带书名）
7. **边界声明**：详见 3.8

### 3.5 词语分析（一定要求里的「词语分析」）

| 输出 | 说明 | 数据 |
|---|---|---|
| **高频词 TOP10** | 排名 + 频次，点击可看它出现在哪本书 | 笔记语料分词词频 |
| **情绪比例** | 正向 / 中性 / 负向占比（三色条） | 情感词表 + 程度副词 |
| **你的口头禅** | 1 句原文引用 | 跨书重复出现或被划最多的句子 |
| **主题词** | 5 个主题（如「自我」「关系」「效率」「历史」「城市」） | 分类映射 + 高频词归并 |
| **词云** | 纯 CSS 字号映射，零依赖，可截图 | 高频词 |

**中文分词方案（零外部依赖是硬约束）**：
- V1：**停用词表 + 2~4 字 n-gram 词频 + 白名单过滤**（噪声大但零体积）；
- V2（若 V1 效果不够）：内置**约 500 词小词表**（阅读场景高频词）做正向匹配，体积控制在 ~10KB；
- 红线：**不引入 jieba 等任何外部依赖**（与项目「零外部依赖」约束一致）。

**语料范围**：默认「笔记最多的 Top 5 本书的全部划线/想法」，上限条数写进配置（与现有 `AI_TOP_BOOKS=5`、`AI_MARK_SAMPLE/REVIEW_SAMPLE` 对齐，词频场景可放宽至全量、AI 场景仍用抽样）。

### 3.6 AI 与规则的分工（沿用现有口径）

- **规则（默认路径）**：四维判定、16 型称号、进度条、词语分析 —— **全部本机算，不配 AI 也完整可用**；
- **AI（可选增强）**：把「人格卡 + 词语分析」已算好的结论写成一段有温度的画像正文（复用 `AI_PERSONA_PROMPT` 思路，DeepSeek）；
- 触发时机：**全部手动触发**——打开报告不自动拉语料、不自动调 AI；点「📊 启用分析」才读取语料生成人格卡，点「🤖 生成 AI 解读」才调用 DeepSeek；串行调用；失败静默退回规则文案；
- 隐私提示沿用现有原文（启用 AI 后原文样本会发给 `api.deepseek.com`）。

### 3.7 入口与呈现位置

- **入口**：插件主菜单「🪞 阅读洞察」→ 报告页新增**第一屏**「🧬 我的阅读人格」（放在「📊 阅读行为报告」之上，或作为其首屏卡片）；

## 5. 技术实现方案

**技术栈**：沿用项目现状 —— Manifest V3 + 原生 HTML/CSS/JS，**零外部依赖**；渲染复用 `official.js` 现有的自包含 HTML / Markdown 双渲染器。

**文件结构（新增 / 改动）**：

```text
modules/official.js          ← 改动：新增「阅读人格」函数块（四维判定 / 词频 / 渲染）+ 第十四章
modules/reading-persona.js   ← 可选：内容过大时拆独立模块（旧代码不改，新功能新模块）
modules/persona-words.js     ← 可选：词表（停用词 / 逻辑词 / 情感词 / ≤500 词白名单）
modules/persona-share.js     ← 可选：分享图 Canvas 绘制 + 剪贴板 / 下载（内容多时拆出）
modules/persona-figures.js   ← 可选：16 型人物插画（内联 SVG 字符串 / 绘制路径）+ 人物映射表
manifest.json                ← 版本递增
plan/RPD_阅读人格_需求文档.md  ← 本文档
test/官方数据测试清单.md        ← 追加本功能验收项
```

**关键点**：

- **落地位置**：`modules/official.js` 内新增独立函数块（**旧代码不改**）；如需拆分则新建 `modules/reading-persona.js`；
- **计算成本**：四维判定是纯算术（O(书数)）；词语分析需遍历笔记语料（Top 5 全量），复用现有报告缓存（10 分钟）；
- **可复算**：同一份数据必须得出同一结果 —— **判定过程不含随机、不依赖 AI**，AI 只润色；
- **可调试**：沿用统一日志 `logOfficial()`，输出每一维的原始指标、阈值、判定结果与置信度（便于校准）；**不新增 alert / 旁路打印**。
- **分享图**：用 Canvas 2D 在**离屏画布**绘制（不引入 canvas 库），高度按内容量算好后一次性导出 PNG（`toBlob`）；复制走 `navigator.clipboard.write` + `ClipboardItem`，**实测为准**——若某环境「图片写剪贴板」不可用，则自动降级为「下载 PNG」，**不擅自新增浏览器权限声明**（保持 `manifest` 仅 `storage`；确需权限时须先与你确认并按红线同步商店文案）。
- **人物插画**：用**内联 SVG**（字符串常量或独立 `.svg`）随插件打包，**不联网、不引外链**；报告 HTML 中直接内联渲染；分享图侧用 `new Image()` + **本地 data URI** 把同一 SVG 画到 Canvas（非远程请求）；单张控制在 **≤8KB**，16 张合计 **≤~130KB**。

## 7. 成功标准

1. 任意数据充足的账号能算出 `4 字母 + 称号`，且**每一维都能点出具体数据依据**；
2. 计算结果**可复算**（同数据同结果），不依赖 AI；
3. 数据不足时明确说明并引导，**绝不硬出结论**；
4. 词语分析 TOP10 中**至少 6 个是「人话词」**（非 n-gram 噪声）；
5. **不配 DeepSeek 也完整可用**；开启后文案更自然，且失败静默退回；
6. MD / HTML / PDF 导出均含本章，人格卡在 HTML 中置顶可截图；
7. **一键生成手机版分享图**，可**复制到剪贴板**或**下载 PNG**；复制不可用的环境自动降级为下载；图片含**人物插画** + 人格卡主体 + 词语亮点 + 数据证据 + 品牌署名，且不含任何账号标识；
8. 分享图人物插画满足三条红线：**非宗教、非政治、公有领域**；插画为本项目自绘，不使用真人照片、不联网抓图；
9. 现有 10.2.9 / 10.2.10 / 十三章内容**零改动、零冲突**；
10. 报告内所有数字与主体口径一致，无打架；
11. 页面上「非心理测评/非专业鉴定」声明齐备，无 MBTI 商标字样。
