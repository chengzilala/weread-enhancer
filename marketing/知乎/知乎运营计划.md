## 一、分析

### 1.1 平台特性（决定「怎么答、怎么发」）

知乎与小红书/微信读书 App 最大的不同：**它是一个「搜索 + 问答」的求知社区，用户是带着问题来的**。对「工具类」产品，这是**最省力的精准长尾流量**——一篇好回答可以在两三年里持续被搜到。

| 特性 | 对本次推广的含义 |
|---|---|
| 内容主体是**回答（问题页）**，其次是**文章（专栏）**、**想法** | 打法＝**「挑高流量问题 → 写一篇好回答」**，而非日更笔记 |
| **搜索长尾极强**：站内搜索 + 外部搜索引擎都大量收录 | 找准「微信读书 / 插件 / 读书笔记 / 效率工具」类问题，吃长期搜索流量 |
| 用户**偏 PC 与理性**，对「工具推荐 / 效率方法」接受度高 | 与「插件是电脑端」天然契合，不用像小红书那样费力接手机流量 |
| **外链管控严**：正文放外链易被折叠 / 判营销 | 入口只写**纯文字域名** + 主页简介；完整链接放**评论区 / 私信** |
| 双流量入口：**推荐（问题热榜/关注流）+ 搜索** | 好回答「首发吃推荐、长尾吃搜索」，先赞后搜 |
| 平台对「软广」敏感，但对**亲测经验、开源作品**友好 | 全程**第一人称亲测口吻** + 亮明「自己做的开源工具」，别装第三方推荐 |
| 用户画像：求知 / 成长 / 数码效率人群 | 属「效率工具控 + 读书人」种子人群，无需教育 |

### 1.2 五个流量触点（架构核心 · 决定资源分配）

知乎能输出内容的地方就这五处，**按「曝光量 × 可持续性」排序**：

| # | 触点 | 位置 | 曝光 | 属性 | 主用途 |
|---|---|---|---|---|---|
| ① | **回答** | 问题页 | ★★★★★ | 借问题流量 | **主战场 / 爆点** |
| ② | **文章** | 个人专栏 / 站内推荐 | ★★★★ | 自有 + 长尾 | **长文沉淀 / 搜索** |
| ③ | **想法** | 短内容流 | ★★★ | 日常 | **养人设 / 互动** |
| ④ | **提问 / 话题** | 自建问题、话题页 | ★★★ | 活动 | **破圈 / 引导讨论** |
| ⑤ | **主页 + 关注互动** | 个人页 / 关注流 | ★★ | 承接 | **承接转化 / 复访** |

> **一句话**：**回答打爆点，文章做沉淀，想法养日常，提问破圈，主页接流量**。

### 1.3 产品 × 平台匹配度

- **强匹配**：知乎**用户以 PC 为主**，而插件正是电脑端产品；「网页版难用」这个痛点，在知乎「效率 / 工具」话题里有天然共鸣。
- **卖点翻译成「知乎语言」**（决定行文口吻）：
  - 屏占比 / 沉浸阅读 → 「网页版排版太挤，怎么调」
  - 阅读人格 MBTI → **自带分享图 + 蹭 MBTI 热度**，是最可能的爆点
  - 笔记聚合 / 导出 / 朗读 → 「划过的线怎么变成可复习的知识」
  - 隐私 / 本地存储 → 打消「装插件安不安全」的顾虑
- **风险 / 短板**：
  1. 知乎**外链管控严** → 转化链路靠「纯文字域名 + 主页 + 私信」承接；
  2. 「插件 / API Key / 大模型」偏技术 → 用生活化例子讲，别堆术语；
  3. 平台对工具类软广敏感 → **亮明「开源 / 自己做」**，比伪装第三方更安全、更有说服力。

### 1.4 目标受众分层（决定选题优先级）

| 分层 | 画像 | 最吃的卖点 | 主投触点 |
|---|---|---|---|
| A 读书方法党 | 学生 / 考研 / 考公 / 求知者 | 笔记整理、导出、朗读 | 回答（方法论类问题） |
| B 效率工具控 | 白领 / 产品 / 开发 | 屏占比、导出、找书、快捷键 | 回答（工具盘点类问题） |
| C MBTI / 自我探索 | 泛人群（面最大） | 阅读人格、分享图 | 回答 + 想法 |
| D 微信读书重度用户 | 各年龄段 | 全功能、隐私、PC 增强 | 回答（微信读书相关问题） |

### 1.5 结论（分析落点）

> **钩子 = 痛点（网页版难用）+ 亲测口吻 + 开源身份 + 人格图传播**；
> **先用「工具盘点类高流量问题」的回答建立认知，再用「阅读人格」单篇冲量，最后靠「方法论文章」吃长期搜索长尾。**

## 二、架构（触点 / 内容 / 账号 / 引流 四张图）

> 本节是本文档核心：把「在哪答、答什么、怎么接」一次画清。

### 2.1 触点架构（在哪答）

```
知乎
├── ① 主页（门面 / 落地页）        ← 全部内容的最终去向
│     ├─ 昵称：含「读 / 工具」关键词
│     ├─ 一句话介绍：定位 + 入口关键词（勿放外链）
│     └─ 置顶：把最好的那篇回答顶上去
├── ② 回答（主战场）              ← 借高流量问题，单篇最可能爆
│     └─ 主攻「微信读书 / 读书笔记 / 效率工具」类问题
├── ③ 文章（专栏 / 长尾）          ← 一篇讲透，长期吃搜索
│     └─ 产品体验文 / 开源记录 / 方法论长文
├── ④ 想法（日常 / 人设）          ← 短、轻、可发人格图
│     └─ 顺手记录读书发现，保持活跃
├── ⑤ 提问 / 话题（破圈）          ← 自建问题、参与话题
│     └─ 引导「你的阅读人格是什么」类讨论
└── ⑥ 关注 / 互动（复访 / 裂变）    ← 关注读书 / 效率博主、回评
      └─ 在高赞回答下留高质量评论，让陌生人点进主页
```

### 2.2 内容架构（答什么 · 三层配比 5:3:2）

| 层 | 作用 | 占比 | 特征 | 带产品？ | 主要触点 |
|---|---|---|---|---|---|
| **破圈层** | 涨粉 / 立人设 | 50% | 读书方法、效率工具盘点，认真答题不硬带 | **不带**（最多文末轻带） | 回答 · 想法 |
| **种草层** | 建立「我也想要」 | 30% | 第一人称亲测功能演示 | 带，弱转化 | 回答 · 文章 |
| **转化层** | 安装 / 使用 | 20% | 教程、入口、工具合集 | 强引导 | 回答 · 文章 · 主页 |

> **首篇发「综合全面版」、其后冷启动期「只答破圈题」**：先用一篇综合全面版回答把「微信读书插件」一次讲全、立住完整认知，再把主页做成「爱读书、会做工具的人」，涨到一定赞数与关注者，再上更多带产品的内容。

### 2.3 账号架构（人设 + 主页装修）

- **一号到底**：知乎不搞矩阵，**只运营一个主号**。
- **人设关键词**：`爱读书 + 效率工具控 + 会做小工具的人`——3 个词贯穿全部内容。
- **主页装修四件套**：
  1. **昵称**：如「XX 的阅读实验室」；
  2. **一句话介绍**：定位 + 入口关键词（**写纯文字产品名 / 域名，勿放可点外链**）；
  3. **背景图**：`screenshots/promo/github-banner.png`；
  4. **置顶**：把跑得最好的那篇回答置顶。

### 2.4 引流承接架构（怎么接）

```
【触达】回答 / 文章 / 想法 / 提问
        │  文末软引导：「工具是我自己做的开源项目，想要的说一声 / 看我主页」
        ▼
【承接】主页（一句话介绍里放产品名 + 域名关键词）      ← 唯一能长期挂「入口」的地方
        │  关键词：产品名「微信悦读」/ 官网域名 reader.chesterlee.cn
        ▼
【分流】用户按需自取 —— 正文外链受限，全靠「搜 / 记 / 私信」
        ├─ 电脑用户 → 官网教程：reader.chesterlee.cn（装 Edge / Chrome 插件）
        └─ 手机用户 → H5：reader.chesterlee.cn/app/（报告 + 阅读人格分享图）
        ▼
【闭环】用产品生成的「阅读人格分享图」再发回知乎想法 / 朋友圈  ← 反哺传播
```

> **红线提醒**：正文**不放可点外链、不放二维码、不诱导点赞收藏**。入口一律写成**可被搜索的纯文字记忆点**（产品名 / 域名），完整链接只在**评论区 / 私信**里给。

### 3.5 发布操作（手动 · 无脚本）

- **为什么没有脚本**：知乎问答是**人工创作**（写得好坏决定权重），且平台反自动化严，**全部手动发布**。
- **发布步骤**：
  1. **回答**：知乎 → 搜索目标问题 → 「写回答」→ 正文 + 配图 → 发布；
  2. **文章**：知乎 → 首页「写文章」→ 填标题 / 正文 / 配图 → 发布；
  3. **想法**：知乎 App / 网页 → 「+」→ 发想法（可带图）。
- **发布后 10 分钟内**：在**自己回答的评论区**补一条「入口提示」（**纯文字域名，不放可点链接**），并**点自己评论的「置顶」**（作者可置顶自己的评论）。
- **互动动作**：回答发布后，主动去相关高赞问题下留 2–3 条**有价值**的评论，把陌生流量引向主页。
- **素材**：配图取 `screenshots/store/`（横版）+ `screenshots/promo/feature-*.png`（功能卡）或 `marketing/小红书/`（竖版），**每篇 5–8 张**，规格不同按需挑。
- **发帖文件夹（发帖时直接用）**：`python3 tools/zhihu_post_folders.py` 按 `知乎文案.md` 每篇的「配图」行，生成 `marketing/知乎/帖子/<篇号>-<短标题>/`——图从母版复制、带 `01-` 上传序号（第一张＝题图），可随时重跑重建、不入库。发帖时只打开对应文件夹就能传图，不用在 `screenshots/` 里挑。
