# 可行性分析 · 纸书归档（拍书）与微信读书联动

> **性质**：可行性分析（决策级），不是需求文档、不是开发计划。需求见同目录 `RPD_纸书归档_需求文档.md`。
> **定位（用户已确认）**：**先给自己用**——私人工具，不追求发布/合规指标。
> **落盘位置（用户已确认）**：`微信读书插件/plan/`。
> **核实日期**：2026-10-07（平台规则时效性强，超出 1 个月请重核）。

---

## 一句话结论

**需求真实（晒书房 9 年验证过，2021 停服留下空档），方向对；但"结合微信读书"有一条硬边界必须先讲清：微信读书官方能力是「只读」的——只能把它的数据读过来，不能把纸质书塞回去。**

能做成的闭环：

> **自己的纸书库（能扫、能拍、能存、能写）+ 微信读书的电子书数据（有没有电子版、你的划线/想法/书评/推荐/进度）→ 两边互相索引。**

做不到：

- 把纸质书"加进微信读书书架"；
- 让微信读书同步你在纸书上写的笔记。

**形态建议**：把「纸书」这一页**加进已有的「微信悦读」小程序**（云函数中转、共享模块、网关调用全现成），而不是新起一个孤立 App。

---

## 一、有没有真实用户

**有，而且被验证了 9 年。**

- **晒书房**（2012–2021）就是干这个的：手机扫书背条码 → 自动建档 → 按馆藏分类。App Store 4.9 分、12284 个评分，被爱范儿 / 少数派 / 最美应用等多家媒体推荐。
- **它 2021-07-23 官方宣布停止服务**，理由"遇到一些难以克服的困难"（官网此前还有一则"应有关部门要求内容整改"的通告）。这说明：
  1. 需求真实、用户量大；
  2. **这个品类本身极难养活自己**——做了 9 年、免费，还是死了。
- 它死后空档确实被用户惦记：豆瓣小组有人求"还有和晒书房类似的 App 吗"，被推荐 **私家书藏 / 藏书馆 / 二酉 / 云管书**。
- （注：2026 年部分下载站又挂着"晒书房 v3.23.x"版本号，但这类站点日期多为自动更新，**是否复活待核实**，不作事实引用。）

### 与现有竞品"反着来的点"（诚实评估）

| | 晒书房 / 私家书藏 这类 | 本设想 |
|---|---|---|
| 录入 | 扫 ISBN 条码 | 一样，但顺手查微信读书有没有电子版 |
| 录入之后 | 死档案（分类 / 标签 / 已读状态） | **关联**微信读书：电子版链接、划线/想法、书评、相似推荐、阅读进度 |
| 跳转 | 无 | 一键跳微信读书电子版继续读 |
| 数据方向 | 单向录入 | **双向索引**：这本我有纸书 ↔ 这本我有电子版 |

**实话**：差异是真的，但属"锦上添花"——用户不会因为缺它就不用，只会因为有它更愿意用。**加分，不救命。** 对"自己用"这个定位，这点就足够了。

---

## 二、两条硬边界（最大预期落差，先说清）

### 边界 1：微信读书官方 Skill 只能读，不能写

官方口径：「目前仅支持读取个人阅读数据，**暂不支持自动加书架、同步笔记回传等写入操作，数据单向安全调用**」。

| 想要的 | 能否 | 说明 |
|---|---|---|
| 纸书 → 加进微信读书书架 | ❌ | 网关只读；微信读书也没有"纸质书入库"这个概念 |
| 纸书笔记 → 回传微信读书 | ❌ | 写操作不存在 |
| 微信读书划线/想法 → 挂到纸书条目下 | ✅ | `/book/bookmarklist`、`/review/list/mine` |
| 纸书 ↔ 电子版一键跳转 | ✅ | 书名走 `/store/search` 找 bookId → 拼跳转链接 |
| 用书名查有没有电子版 | ✅ | `/store/search` |
| 用 **ISBN** 直接查微信读书 | ⚠️ **待实测** | `/store/search` 的 keyword 吃不吃 ISBN，需实测 |

### 边界 2："你买纸书的书，多半微信读书没有电子版"

很多人恰恰因为没电子版才买纸书。所以"关联"覆盖率可能只有一部分，**这直接决定闭环感强弱** → 必须实测（见第五节清单第 2 条）。

## 三、可行路径对比

| 路径 | 能否实现 | 门槛 | 用户要装新东西吗 | 风险 |
|---|---|---|---|---|
| **A. 复用「微信悦读」小程序加「纸书」页** ⭐ 推荐 | 手机原生扫码 + 云调用拍照识码 + 云开发建库 + 现成网关中转 | 自用走**体验版**，不发布 → 免备案、免该类目审核；类目沿用「工具」 | 无（已有入口） | **低**（底座全现成） |
| B. 新开独立小程序 | 同 A | 多占 1 个主体名额（个人上限 5 个）+ 再走备案 | 要 | 没必要 |
| C. 浏览器扩展加"我的纸书"面板 | 电脑端可直接调网关（已有） | — | 装扩展 | 拍书是手机场景，电脑上只能手输 ISBN。宜作**附属端**（管理/导出） |
| D. H5/PWA | 拍照需引第三方条码识别 JS 库 | 违背本项目"零外部依赖"红线；iOS 摄像头坑多 | 无 | **不推荐做主线** |
| E. 纯本地脚本（只给自己用） | 手机拍 ISBN → 电脑跑脚本 → 出 Markdown 表格 | 0 门槛 | 无 | 不是产品，但**当天能用**，适合先验需求 |

**关键省事点（为什么推荐 A）**：

- 扫码用小程序原生 `wx.scanCode({ scanType: ['barCode'] })`，支持 EAN-13/ISBN 一维码，手机端体验最好；
- **拍照识码**可用微信官方**云调用 `openapi.img.scanQRCode`**——不用引第三方 OCR、不用额外资质（限制：图片 < 2M）；
- 网关中转复用现成的 `mobile/cloudfunctions/wereadProxy`（已支持 relay、按 openid/deviceId 隔离、Key 只掩码入日志）。

## 四、逐条可行性判定

| 设想 | 能否 | 依据 / 待实测 |
|---|---|---|
| 手机对准书背条码 → 自动出书名作者 → 入库 | ✅ | `wx.scanCode` barCode 支持 EAN-13/ISBN |
| 直接拍照（不扫码）也能识书 | ✅ | 云调用 `openapi.img.scanQRCode` 支持相册图片条形码识别 |
| 元数据（封面/作者/出版社/简介） | ⚠️ 半 | **豆瓣开放 API 已关闭**，第三方代理也失效；免费只剩 Open Library（中文覆盖差）；中文数据好的（聚合/极速/易源/咕咕）都要付费 key |
| 分类 / 标签 / 已读状态 / 导出 | ✅ | 本地做，照抄晒书房即可 |
| 关联微信读书笔记 / 进度 / 书评 / 推荐 | ✅ | 网关只读能力全部可用 |
| 写回微信读书 | ❌ | 官方不提供写接口 |
| 做给别人用的产品 | ⚠️ | 需 ICP 备案 + 隐私政策 + 类目复核（本次**不做**） |

## 五、隐藏坑

1. **覆盖率未知**：纸书 ≠ 微信读书有电子版，这是最大预期落差，必须实测。
2. **ISBN 元数据是隐形成本项**：免费的不好用、好用的要钱，豆瓣这条老路已死。MVP 先用"微信读书书名反查 + 手动补录"兜底，别一上来就买接口；并已增设「**手动关联电子书**」（搜书名 → 挑一本 → 绑定）作为命中率低时的兜底，保证关联闭环无论如何都成立。
3. **低频 + 难变现**：晒书房 9 年免费仍停服；个人主体小程序**不能收微信支付**，只能靠广告（且"个人能否开流量主"网上口径互相矛盾，**待核实**，别算进收入）。自用则不受影响。
4. **版权红线（写进产品定位）**：**绝不能**做成"拍照把纸书 OCR 成电子书文库"——那是盗版分发。本项目只做"建档（元数据）+ 关联"，**不复制书中正文**。
5. **接口会变**：官方 skill 回包带 `upgrade_info` 时强制升级；可用接口以 `{"api_name":"/_list"}` 实测为准。

---

## 六、推荐方向 + 最小验证清单

- **主线**：复用「微信悦读」小程序，新增「📚 纸书」页（扫码建档 + 关联微信读书）。
- **备选**：浏览器扩展加"我的纸书"面板（电脑端管理 / 导出）。
- **兜底**：本地脚本先跑通（只给自己用）。

### 最小验证清单（不写产品代码，成本 0 元）

- [ ] **V1** 发 `{"api_name":"/_list"}`，看有没有"按 ISBN 查书"的接口
  - 判定：通过（ISBN 直查可用）/ 半通过（只能按书名搜）/ 不通过
- [ ] **V2** 拿 **10–20 本**自己的纸书，抄下 ISBN，逐本用 `/store/search` 试，统计命中率
  - 判定：**≥60% 通过 / 30–60% 半通过 / <30% 不通过**（直接决定"闭环"值不值得做）
- [ ] **V3** 用微信"扫一扫"扫一本手上书的条码，看能否识别出书名（旧书条码可能磨损/没有）
- [ ] **V4** 找 1 家免费/试用级 ISBN 接口，实测**中文书**命中率
- [ ] **V5** 搜「私家书藏 / 藏书馆 / 二酉 / 云管书」试用 30 分钟，回答"现有替代品到底差在哪"
  - 判定：它们都做不到"关联微信读书" → 差异化成立
