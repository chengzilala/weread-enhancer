## 1. 项目概述

- **定位**：把插件里最有传播力、最适合手机的部分（阅读数据 + 阅读人格）做成微信小程序；是「阅读数据行为分析展示渠道」，不是阅读器。
- **目标用户**：已在用「微信悦读」插件、或愿意粘贴自己微信读书 `wrk-` API Key 的微信读书用户。
- **当前状态**：从零新建。插件侧的数据算法与报告模型已存在，可复用（见 §5.4）。
- **已确认的三件事（用户目标 / 输入输出 / 成功标准）**：
  - **用户目标**：在手机上随时看自己的阅读数据与阅读人格，并能一键分享；API Key 只输一次。
  - **输入输出**：输入 = 用户自己的 `wrk-` API Key（仅本机保存）；输出 = 手机端可视化报告 + 可分享的图片/小程序卡片。
  - **成功标准**：输入一次 Key 后长期免输；核心数据/人格能正确展示；能生成并分享；提审通过。

### 1.1 关键前提（决定方案成立与否）

1. 插件能拿到官方数据，靠的是**浏览器扩展权限**绕过了官方网关的 CORS 限制。官方网关 `POST https://i.weread.qq.com/api/agent/gateway` 的 OPTIONS 预检返回 401，**浏览器/小程序都无法直连**（依据：[background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js#L6-L11)）。
2. 因此移动端**必须有一个中转服务**。已核实：**微信云开发的云函数出网不受小程序 request 合法域名白名单限制**（走微信私有协议），云函数可自由请求外部 HTTPS 接口，正好充当这个中转。
3. 用户已有**微信小程序账号（个人主体）**，无认证服务号、无自有服务器 → 选「小程序 + 云开发」，不选 H5。

### 1.2 主体与合规状态（已确认）

- **主体类型**：个人主体。
- **微信认证**：✅ **已完成**（30 元/年；认证后为「个人开发者」黄标）。因此本小程序具备**被搜索 / 分享**能力（分享是本项目的核心玩法，此项为硬前提）。
- **ICP 备案**：⏳ 待办（**上线前必须完成**，免费；微信平台初审 1–2 天 + 通管局审核 3–20 个工作日）。建议尽早排队，它比认证更耗时。
- **服务类目**：拟选「**工具**」类（如 工具 → 信息查询 / 效率），在个人主体可选范围内。
- **能力限制（对本案无影响）**：个人主体无微信支付、无「附近的小程序」、无法获取用户手机号；本项目**不收款**，不受影响。
- **合规约束**：上线前需在小程序后台配置《用户隐私保护指引》，如实声明：API Key 及其用途；昵称头像（`chooseAvatar` + `nickname`，仅本机）；相册（仅写入）；openid 云同步（仅存人格结果）；AI 人格画像外发（用户主动触发）；**每日卡片外发（划线 / 想法原文，M11 新增）**。

## 3. 详细功能需求

### M0 云函数中转（地基）

- **需求**：小程序向云函数发起调用，云函数转发到官方网关并把结果回传。
- **接口约定**：
  - 云函数名：`wereadProxy`
  - 入参：`{ apiName: string, params: object, apiKey: string }`
  - 转发：`POST https://i.weread.qq.com/api/agent/gateway`，Body = `params + { api_name, skill_version }`，Header 带 `Authorization: Bearer <apiKey>`
  - 出参：`{ ok: true, data, upgrade } | { ok: false, code, error }`（`code` 覆盖 auth / http / parse / errcode / timeout / network）
- **边界**：
  - `skill_version` 与插件保持一致（当前 `1.0.4`，见 [background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js#L22)），集中一处，便于日后同步升级。
  - 超时 10s；401/403 统一提示「Key 无效或已失效」。
  - **红线**：云函数不持久化、不记录 `apiKey`（日志只允许掩码）；不做任何数据落库。

### M1 API Key 管理

- **需求**：用户粘贴自己的 `wrk-` Key，校验通过后保存到本机，之后免输。
- **交互**：
  1. 「我的 → API Key」设置页：密码型输入框，粘贴后点「保存」。
  2. 保存前调用 `/_list` 探连通 + `/readdata/detail(weekly)` 确认有效（口径同插件 [background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js#L121-L133)）。
  3. 校验通过 → `wx.setStorageSync('wre_api_key', key)`，返回首页并刷新数据。
  4. 支持「清除 Key」；清除后所有需 Key 的页面回到引导态。
- **参数**：Key 必须 `wrk-` 开头，否则前端直接拦截。
- **边界**：
  - Key **仅存手机本地**（小程序 storage）。卸载小程序或清理微信缓存会丢失，需重填 —— 文档中如实说明。
  - 任何页面调用数据前先检查本地是否有 Key；无 Key 一律显示引导，不发起请求。

### M2 数据总览（首页 · 已增强）

- **需求**：首页从「4 个数字」升级为**摘要仪表盘**——一屏 Hero + 2–3 屏内容；只做**摘要 + 入口**，不搬报告全文。
- **数据分档**：
  - **A 档 · 零额外请求**：直接复用 `/readdata/detail` **已返回但此前未展示**的字段 —— `readTimes`（分桶明细）、`preferTime`（24 小时时段）、`preferCategory`（偏好分类）、`preferAuthor`、`readLongest`（读得最多）、`readStat`（官方概要）、`preferCategoryWord` / `preferTimeWord`（官方判定语）。
  - **B 档 · 复用已有缓存**：复用 [data.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/miniprogram/shared/data.js#L129-L152) 的 `fetchOverview`（书架 + 笔记，30 分钟缓存）+ 人格徽章（复用 [persona-core.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/miniprogram/shared/persona-core.js) 的 16 型称号）。
- **信息结构（自上而下）**：
  1. **Hero 主卡**：大字总时长 + 环比（较上期 ↑/↓）+ 一句官方判定语。
  2. **迷你趋势图**：`readTimes` 分桶柱状（本周 7 根 / 本年 12 根 / 累计按年）。
  3. **核心指标卡**：总时长 / 阅读天数 / 自然日均 / 较上期；**官方未提供该周期数据的项直接不展示**（如「累计」下没有自然日均 / 环比时，不再出现「—」占位卡）。
  4. **偏好分类 Top3** + **阅读时段分布**（`preferCategory` / `preferTime`）。
  5. **读得最多 Top3**（`readLongest`：书名 + 时长）。
  6. **入口卡**：书架 / 笔记 / 人格（点击进对应页）。
  7. **底部**：「查看完整报告 →」。
- **交互**：周期切换与下拉刷新保持现状；**A 档随主请求即时渲染**，**B 档懒加载**（下拉刷新时才拉 `fetchOverview`）——避免进首页即发 3 个请求。
- **降级**：`preferTime` 官方**仅「累计」周期提供**，其他周期隐藏「阅读时段分布」块；各块**独立降级**，某字段缺失只隐藏该块，不影响其余；空态沿用现有引导。
- **红线**：
  - 不做「**连续阅读天数（streak）**」：现有数据算不干净（`readTimes` 只有本周期/年桶，无历史每天），需额外接口，暂缓。
  - 「今日金句」归「笔记」页，不塞首页。
  - 首页**不重复报告页内容**，只做摘要与入口。

### M3 阅读人格

- **需求**：基于用户自己的官方数据，本机算出 4 维人格代码 + 16 型称号 + 依据。
- **复用**：算法与判定规则直接复用插件实现（[official.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/modules/official.js) 内的「阅读人格」相关纯计算逻辑，抽出为共享模块）。
- **交互**：主卡展示「人格代码 + 四字母释义（字母→对应的一端，如 `D 深潜`）+ 主称号 + 一句定调」，让读者看得懂代码；展开看 4 维判定值、数据证据、高频词 TOP10、情绪比例。
- **边界**：数据不足时走**降级引导**，绝不硬出结论；固定声明「趣味参考、非心理测评」，不使用 MBTI® 商标名。

### M4 阅读行为报告

- **需求**：把插件「阅读行为报告」的内容按手机屏适配后分章节展示。
- **章节（首版建议）**：执行摘要 → 数据全景 → 阅读时段分布 → 偏好画像（作者/出版社）→ 读得最多 → 完读率 → 笔记行为 → 附录数据说明。
- **边界**：章节可折叠；「执行摘要」首版用**规则化摘要**（不接 AI）；接入 DeepSeek 作为 P2（见 §6 取舍）。

### M5 分享（P1）

- **需求**：把人格/数据做成可分享内容。
- **两种形态**：
  1. **小程序卡片**：`onShareAppMessage`，转发给好友/群，标题带人格称号。
  2. **竖版分享图**：canvas 绘制海报，按 2× 高清导出；支持「转发给朋友」（`wx.showShareImageMenu`，无需先保存相册）与「保存到相册」。已接入五处：**人格页**（人物线描 + 人格卡 + 词语亮点 + 数据证据 + 品牌署名）、**每日卡片页**（划线原文 + 说明 + 品牌署名）、**报告页**（核心指标 + 亮点 + 读得最多 Top3 + 笔记概览 + 品牌署名）、**首页**（总时长主数字 + 指标卡 + 官方判定语 + 偏好分类 + 时段分布 + 读得最多 + 品牌署名）、**书架**（概览四项 + 分类分布 + 最近在读 + 品牌署名）。
- **复用**：分享图的版式与文案复用插件现有分享图设计；人物线描素材随包内置、运行时不联网；报告分享图的数据口径复用 `report-core.js` 纯函数，与页面一致。
- **边界**：canvas 绘制在小程序端需重新实现（不能直接复用插件的 HTML/CSS 版）；报告/人格均需用户自备 Key，「小程序卡片」转发给对方是「邀请对方自测」，只有分享图是可独立查看的内容。

### M6 / M7 书架与笔记概览（P1）

- 书架：`/shelf/sync`，区分电子书 / 专辑 / 公众号，展示封面、作者、进度。
- 笔记：`/user/notebooks`（游标分页），展示笔记数量与最近笔记概览。
- **跳转**：点击书籍 → 用官方回包解析出的**网页版详情页**（沿用插件「不自行拼接链接」的口径）。
- 边界：书架/笔记各自 30 分钟缓存；一路失败只降级对应模块并给出提示。

### M8 / M9 / M10 用户标识 · 头像昵称 · AI 画像（已启用）

- **M8（静默 openid + 云同步）**：云函数 `cloud.getWXContext().OPENID` 天然拿到用户标识，**无需任何授权弹窗、无需 wx.login**。已用于「人格结果云同步」——按 openid 隔离，只存本机算出的人格结果视图（**不存 Key、不存官方原始数据**，上限 400KB），换设备或重装后秒显。启用后**隐私承诺已同步改写**（见 §8、发布前准备 §五）。
- **M9（主动填写）**：`wx.getUserProfile` 已不适用；头像昵称走 `button open-type="chooseAvatar"` + `input type="nickname"`，且**须在《用户隐私保护指引》声明「昵称、头像」**（已补充）。采集到的头像昵称**仅存本机**（`wx.getStorageSync`），用于「我的」页展示与分享图署名，不上传服务器。
- **M10（AI 人格画像，可选）**：把本机已算好的四维判定 + 证据交给 DeepSeek 润色成一段有人格感的画像（提示词同插件 `AI_READING_PERSONA_PROMPT`）。**Key 由用户自填、只存本机**，经云函数 `action:'ai'` 转发（不落库、日志仅掩码、30s 超时）；未填 Key 时完全退回纯本地规则，不影响人格主体结果。

> 三者的对外口径变化（openid 上云、头像昵称收集、人格判定发往 DeepSeek）均须在《用户隐私保护指引》如实声明，配置文案见 [发布前准备 §五](./小程序_发布前准备.md)。

### M11 每日卡片回顾（已完成，分享图待真机验证）

- **背景（用户原话）**：「让过去的记忆不再过去，让过去死去的记忆重新鲜活……通过关联的方式重新构建连接，让知识再次活过来。」——用微信读书的**划线 / 想法**数据，每天生成一篇带**引用 + 说明**的短文卡片。
- **需求**：每天为读者生成 **1 篇「今日卡片」**：以读者自己的历史**划线原文**与**想法**为素材，用 AI 写成一篇短文，含 **引用（划线原文 + 出处）** 与 **说明（串联、延伸、关联）**；并把「同主题 / 语义相关」的其他旧划线一并带出，形成"记忆重新连接"的体验。
- **输入（本机已有取数能力，无需新增接口）**：划线 `markText`（[data.js `fetchBookMarks`](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/miniprogram/shared/data.js#L155-L168)）、想法 `content`（[data.js `fetchBookReviewItems`](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/miniprogram/shared/data.js#L171-L191)）、线程化语料 `fetchCorpus`（笔记最多的前 5 本，10 分钟缓存）。
- **输出（一张卡片，可回看 / 收藏 / 分享成图）**：
  1. **标题**：AI 起的主题句；
  2. **引用**：划线原文（书名 / 作者 / 位置）；
  3. **说明**：AI 的**解读**（这段话在说什么）+ **共情**（你当时为什么划下 / 写下它）+ **关联理由**（它与旧句具体相关在哪里）（**必须标注「AI 生成」**）；
  4. **关联**：指向历史上同主题、且**真实共享关键词**的其他旧划线（可点开）；找不到就**只做单条深读**，不硬凑。
- **"重新关联"的分级落地**：
  - **首版（P0）· 规则 + LLM 近似**：用 [persona-core.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/miniprogram/shared/persona-core.js) 已有的主题 / 关键词表给划线打主题标签 → 按主题召回相关旧划线 → 把候选集交给 LLM 完成"串联成文"。**不做真向量 / embedding**（成本与复杂度高）。为防"关联错乱"，召回设**两条硬约束**：① 主题至少命中 **2** 个关键词才算数（避免数学段落只因一个「理解」被判进「关系与情感」）；② 主划线与他句必须**真实共享至少一个主题关键词**，否则不召回。
  - **增强（P2）· 语义召回**：引入 embedding / 向量相似度，真正按"语义相近"跨书召回。**（"神经网络"是体验目标，非首版承诺——首版用规则 + LLM 近似）**
- **AI 通道**：**复用 M10 的 DeepSeek 通道**（用户自填 Key → 云函数 `action:'ai'` 转发，不落库、日志仅掩码、超时限制）。未填 Key 时的降级见下。
- **降级**：未填 AI Key → 降级为**纯本地模板卡片**（只排版划线 + 想法，**不冒充解读**，也不写「互相照亮」这类空话），并在说明下方提示「配好 DeepSeek Key 后这里会换成解读与关联分析」，保证功能可用。
- **触发与频率**：每天至多 1 篇；**进入小程序时检查是否已生成**（懒生成，不依赖定时推送——个人主体小程序无法可靠下发）。提供「重新生成」，**每日限 N 次**（限流控成本）。
- **入口与提醒（4.9）**：「每日卡片」入口**置顶在首页顶部**（周期切换上方，品牌绿卡突出）；**每天首次打开首页**自动弹出今日卡片弹窗（**可关闭**：点遮罩 / × / 关闭按钮均可；**当天只弹一次**，再次进入不再弹）。弹窗内的卡片与卡片页同源：本机已有今日卡片则直接展示，否则走同一套懒生成（**不消耗重新生成次数**）；素材不足 / 失败在弹窗内给引导与「重试」。
- **存储（已确认）**：每日卡片**只存本机**（可回看 / 收藏），**不上云**；换机 / 清缓存会丢失（与 API Key 同口径）。
- **边界**：
  - 素材不足（划线 / 想法太少）→ 走引导，**不硬生成**；
  - **去重**：记录已用划线，避免连日重复；选材默认**随机**以扩大覆盖面；
  - 每条引用**可溯源**（来自读者自己的数据），**禁止编造原文**。
- **红线 / 合规**：
  - ⚠️ **划线 / 想法原文会随请求发往 DeepSeek** → 必须在《用户隐私保护指引》**新增声明**（现有仅声明"人格判定外发"）；分享图同样含原文，需在用户主动分享时生成并标注来源。
  - AI 说明**必须标注「AI 生成」**；引用需标出处。
- **成功标准**：
  1. 连续多天能稳定产出「今日卡片」，且**不重复、不空洞**；
  2. 每张卡片的引用都**可溯源**到读者自己的划线 / 想法；
  3. **关联准确、说明有共情**：召回的旧句与主划线确有可指认的共同点；AI 说明能讲清「这段话在说什么 / 你为什么划它 / 它和旧句为何相关」；召不到就单条深读，不硬凑；
  4. 未填 AI Key 时功能仍可用（本地模板降级，且不冒充解读）；
  5. 分享图能生成并分享。
- **形态取舍（2026-10-06 · 拾贝调研）**：市面对标《拾贝-同步微信读书笔记并回顾》（Edge 扩展，把读者的划线 / 想法做成**浏览器新标签页**随机书摘）从侧面印证了「让笔记被反复看见」这一需求成立，但其**载体（接管新标签页）不采纳**——侵入性强、脱离「微信读书」使用心智，且该竞品仅 **54 用户、0 评价**，单点新标签页价值有限。故本项目把「回顾」内核**收敛在 M11**：只在站内（小程序页）做「每日卡片 + 可回看 / 可分享」的入口，**不做**替换新标签页的形态；插件侧亦同步「**不新增**接管新标签页的功能」。
- **差异化对比（2026-10-06 · 竞品调研）**：市面对标 **ReadTick**（Edge，76 用户）把「随机回顾」当卖点——只做「**随机抽一条旧划线**」；**Notepal**（Edge，890 用户）做的是「把笔记**同步到外部工具**」（Readwise / flomo / Notion / Logseq / Obsidian / 思源）。本项目的 M11 **两头都不重走**：不做「纯随机」——升级为 **AI 主题关联 + 成文**，让旧记忆真正「重新连接」；也不做「多平台同步」（受小程序 request 合法域名白名单限制、需云函数逐平台中转，且 Obsidian / Logseq 等本地软件无法对接，投入产出比低）。故 M11 是**差异化主线**，而非补课。

## 5. 技术实现方案

### 5.1 技术栈

- 前端：微信小程序原生（WXML/WXSS/JS 或 TS），基础库 ≥ 2.21.2（为未来头像能力预留）。
- 后端：**微信云开发**（云函数 `wereadProxy`）+ 云数据库（集合 `wre_sync`，仅用于 B2 人格结果云同步，按 openid 隔离）。
- 数据源：官方 Agent 网关 `/readdata/detail`、`/shelf/sync`、`/user/notebooks`。
- 零外部依赖原则延续：不引入第三方统计/广告 SDK。

### 5.2 目录结构（建议）

统一放在仓库新增的 `mobile/` 目录下（与浏览器插件源码并存、互不影响）：

```
mobile/
├── project.config.json          # 开发者工具项目配置（miniprogramRoot / cloudfunctionRoot）
├── README.md                    # 运行与验证说明
├── miniprogram/                 # 小程序前端
│   ├── app.js / app.json / app.wxss
│   ├── config.js                # 云开发环境 ID
│   ├── pages/
│   │   ├── home/                # M2 数据总览
│   │   ├── persona/             # M3 阅读人格
│   │   ├── report/              # M4 阅读行为报告
│   │   ├── shelf/               # M6 书架（P1）
│   │   ├── notes/               # M7 笔记（P1）
│   │   └── settings/            # M1 API Key 管理
│   ├── shared/                  # 公共模块（gateway / store / format，见 5.4）
│   └── components/              # 卡片 / 图表 / 空态等
└── cloudfunctions/
    └── wereadProxy/             # 云函数：官方网关中转
```

### 5.3 数据流

```
小程序页面
  → 读本地 Key（wx.getStorageSync）
  → wx.cloud.callFunction('wereadProxy', {apiName, params, apiKey})
      → 云函数补 Authorization + skill_version，转发 i.weread.qq.com
      → 返回 {ok, data}
  → 页面/共享模块做纯计算与渲染
```

### 5.4 复用插件资产（关键，避免重写）

- **纯计算逻辑可复用**：`report-core` / `persona-core` 从 [official.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/modules/official.js) 中抽取「数据计算」与「渲染」解耦后的纯函数部分（报告模型、四维判定、词频/情绪统计等）。
- **不可直接复用**：所有 DOM/HTML/CSS 渲染、分享图绘制、屏占比等桌面增强逻辑 —— 需在小程序端重新实现。
- **原则**：抽取时**不改动插件现有行为**（插件红线：旧代码不改，新功能写新模块）；共享模块由两端引用，避免两套算法漂移。
