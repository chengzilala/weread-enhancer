## 一、分析

### 1.1 平台特性（决定「写什么、怎么投」）

少数派（sspai.com）是**数字生活 / 效率工具**社区，和前面几个渠道最大的不同：**它是「编辑审稿制」的长文平台**——内容质量决定一切，**一篇好文 > 一百篇水帖**。

| 特性 | 对本次推广的含义 |
|---|---|
| 内容以**长文 + 图文并茂**为主，讲究排版与可读性 | 必须**认真写一篇**（标题 / 结构 / 配图 / 截图都到位），不能像发动态那样随手写 |
| **两条提交通道**（官方术语）：① **投稿作品**＝进编辑部审阅、**需少数派首发**、通过才上首页、**有稿酬**；② **社区作品**＝发到「广场 / Matrix」，**发布即公开**、门槛低，但**只有质量特别突出才被设为「精选」上首页 / 侧栏** | 策略＝**先用「社区作品」快速公开、冲「精选」**（发布即公开、能最快进互动）；想要稿酬 / 更高曝光再走「投稿」（需首发、审稿） |
| **身份阶梯**：实名认证后默认「**新手上路**」（发文**需人工确认**、约 1 个工作日才公开）→ **满 3 篇**转正为「**少数派作者**」（可自由公开发布）→ 「**共创计划成员 / 签约作者**」 | **首批正好 3 篇＝跨过转正门槛**；前 3 篇要等确认，**别把最重要的主文卡在等待期**（主文尽量排在能尽快过审的位置） |
| **宣传内容处理规则**（官方《特别规则》）：**明确允许、并鼓励「高质量的自我宣传」**（原文举例即「独立开发者介绍自己的应用作品」），但**必须用编辑器如实披露利益相关**（自我宣传 + 有无赞助 / 奖励） | 我们**不必装第三方推荐**，正文如实写明「这是我自己做的开源项目」；**准确披露是「被精选 / 上首页」的前提**（宣传内容原则上无稿酬，我们本就不取） |
| **曝光出口有限** + 官方 **2026-09 重启「Matrix 周报」→「社区速递」**（每周集中推一次社区优质内容） | 首页时间流 + 侧栏精选容量都小；除冲「精选」外，**「社区速递」是一个新曝光位**，选品更看「**作者自发投稿 + 社区讨论热度**」→ 发布后要积极回评、拉讨论 |
| 文章**相对允许放链接**（以下载 / 官网地址形式），但**仍以审核为准** | 转化比小红书顺，但仍应把「官网 / 商店链接」放在**末尾自然的下载区**，别堆在正文中间 |
| **长尾极强**：「效率工具」「应用推荐」分类 + 搜索引擎长期收录 | 一篇优质工具文能**长期**带来精准用户，属于「一次投入、长期收益」 |
| 用户画像：**效率控 / 数码爱好者 / 开发者** | 与产品「效率工具控」受众**高度重叠**，且这些人**普遍用 PC**，与插件属性契合 |
| 社区文化：**重「实测 / 体验」，反感硬广** | 用**「我用它解决了什么问题」**的体验口吻写，先讲痛点与场景，再讲功能 |

### 1.2 四个流量触点（架构核心 · 决定资源分配）

| # | 触点 | 位置 | 曝光 | 属性 | 主用途 |
|---|---|---|---|---|---|
| ① | **主站文章**（投稿 / 精选） | sspai.com 首页 / 分类流 | ★★★★★ | 编辑推荐 | **目标 / 爆点** |
| ② | **社区作品**（广场 / Matrix） | sspai.com/matrix | ★★★★ | 发布即公开 | **入口 / 试水长文** |
| ③ | **评论区互动** | 文章 / 社区底部 | ★★ | 日常 | **答疑 / 拉信任** |
| ④ | **主页 + 关注** | 个人主页 / 关注流 | ★★ | 承接 | **沉淀 / 复访** |

> **一句话**：**先用「社区作品」发长文、冲「精选」上首页；评论区答疑拉信任，主页做沉淀**。

### 1.3 产品 × 平台匹配度

- **强匹配**：少数派**读者就是「效率工具控 / PC 用户」**，是产品最精准的人群之一；一篇高质量「微信读书网页版增强」长文，天然属于「效率工具」题材。
- **比其它渠道更宽松的地方**：少数派**接受「工具介绍」类文章**（本来就是干这个的），所以**不用像小红书那样刻意弱化产品**，可以更直接地讲它解决了什么。
- **卖点翻译成「少数派语言」**（决定行文口吻）：
  - 屏占比 / 沉浸阅读 → 「把网页版排版调到纸质书的行宽」
  - 阅读人格 MBTI → 「用数据给阅读习惯做一次画像」+ 分享图
  - 笔记聚合 / 导出 / 朗读 → 「让划线变成可复习的知识资产」
  - 隐私 / 本地存储 / 开源 → **少数派读者最吃这一点**，务必写足：零依赖、只 storage 权限、数据不上传、GPL-3.0 开源
- **风险 / 短板**：
  1. **审核门槛高**：写得像广告 / 太空泛会被拒 → 必须**有实测、有细节、有取舍**；
  2. **一次投入重**：一篇长文要花时间（写 + 截图 + 排版），但**回报期长**，值得；
  3. 平台**反硬广** → 亮明「开源 + 自用作品」，坦诚反而加成。

### 1.4 目标受众分层（决定选题优先级）

| 分层 | 画像 | 最吃的卖点 | 主投触点 |
|---|---|---|---|
| A 效率工具控 | 白领 / 产品 / 开发 | 屏占比、导出、找书、快捷键、开源 | 主站文章 |
| B 读书方法党 | 学生 / 考研 / 求知者 | 笔记整理、导出、朗读 | Matrix 长文 |
| C 隐私 / 极简主义者 | 数码爱好者 | 零依赖、只 storage 权限、数据不上传 | 主站文章 |
| D 微信读书重度用户 | 各年龄段 | 全功能、PC 增强 | 主站文章 |

### 1.5 结论（分析落点）

> **钩子 = 真实痛点（网页版难用）+ 完整实测 + 开源 / 隐私**；
> **先用「社区作品」把一篇「产品体验长文」发到 Matrix、冲「精选」（前 3 篇正好跨过「新手上路 → 正式作者」门槛）；再用「开发记录」与「笔记方法论」两篇做补充与长尾。**

## 二、架构（触点 / 内容 / 账号 / 引流 四张图）

> 本节是本文档核心：把「发在哪、写什么、怎么接」一次画清。

### 2.1 触点架构（发在哪）

```
少数派
├── ① 社区作品（入口 / 试水）           ← 发布即公开，先发这里
│     └─ 质量突出 → 被设为「精选」上首页 / 侧栏（另可上「社区速递」周报）
├── ② 主站文章（目标 / 爆点）           ← 编辑推荐 / 主动「投稿」（需首发、有稿酬）
│     └─ 「效率工具 / 应用推荐」分类，长尾最强
├── ③ 评论区（答疑 / 拉信任）           ← 认真回评
│     └─ 解答疑问、补充细节，把路人变用户
└── ④ 主页 + 关注（承接 / 复访）
      └─ 个人简介放定位与入口关键词
```

### 2.2 内容架构（写什么 · 三篇主打 + 备选）

少数派**不看数量看质量**，首批建议 **3 篇**，各司其职：

| # | 类型 | 篇目 | 作用 | 带产品？ | 触点 |
|---|---|---|---|---|---|
| 1 | **主文 · 产品体验** | 我给微信读书网页版写了个增强扩展 | 核心介绍，争取上主站 | **强**（本平台允许） | Matrix → 主站 |
| 2 | **备选 · 开发记录** | 用 AI 一周做一套开源产品的记录 | 打「独立开发者」人设，破圈 | 弱 | Matrix |
| 3 | **备选 · 方法论** | 把微信读书的划线变成可复习的知识资产 | 干货长尾，软带 | 软 | Matrix |

> **配比建议**：主文强带产品（少数派本就接受工具介绍）；另两篇**先讲方法与故事、末尾轻带**，形成「内容 ↔ 产品」的良性循环，避免整个账号像广告号。

### 2.3 账号架构（人设 + 主页装修）

- **一号到底**：只运营一个主号，**人设关键词**＝`爱读书 + 效率工具控 + 独立开发者`。
- **主页装修**：
  1. **昵称**：如「XX 的阅读实验室」；
  2. **简介**：一句话定位 + 入口关键词（可含官网域名）；
  3. **头像**：用 `assets/logo.svg` 或插件图标；
  4. **关注 / 互动**：关注少数派上的效率 / 阅读类作者，回评建立关系。

### 2.4 引流承接架构（怎么接 · 从文章到产品）

```
【触达】Matrix / 主站长文
        │  文末「获取方式」区：官网 / 商店链接（少数派相对宽松）
        ▼
【承接】官网 reader.chesterlee.cn（教程最全）
        │
        ▼
【分流】
        ├─ 电脑用户 → Edge 商店搜「微信悦读」（Chrome 也支持）
        └─ 手机用户 → H5：reader.chesterlee.cn/app/（报告 + 阅读人格分享图）
        ▼
【沉淀】评论区答疑 + 关注，把读者变成长期用户
```

> **提醒**：链接虽相对宽松，但仍应**放在文末「获取方式 / 下载」区**，正文中间别插链接；发布前以平台实际审核为准。

### 3.3 发布节奏（首批 · 3 周）

少数派**不日更**，节奏是「**打磨一篇 → 发 → 观察 → 再写下一篇**」：

| 阶段 | 时间 | 动作 | 重点 |

> **不刷量、不刷赞**（少数派社区氛围严，**诚信比数据重要**）。

### 3.4 发布操作（接管浏览器 · 全自动，`tools/sspai_publish.py`）

- **目标**（对齐 `发帖规范.md` §1.7）：少数派发布**＝全程接管浏览器**——打开站内编辑器 → 填标题 → 粘正文 → 传图 → 填标签，**脚本填完停在「发布」按钮前，由你亲手点最后一下**（安全闸）。
- **现状**：发布脚本**已就绪** ＝ `tools/sspai_publish.py`（沿用 `tools/zhihu_publish.py` 的「真实 Chrome + CDP → 停在发布前」范式，调试端口 9223）。仅两次人工介入：① 首次**扫码登录**（存 `.autoshot/sspai-profile/`、之后免登）；② 最后点「发布」，以及侧栏「利益相关声明」开关。
- **运行**：
  1. `python3 tools/sspai_publish.py --list` 看三篇；
  2. `python3 tools/sspai_publish.py --post 篇1` → 浏览器弹出、你登录 → 脚本自动填好、**停在「发布」前**；
  3. 你在浏览器里核对后：**打开侧栏「利益相关声明」开关 → 选「自我宣传」**，点工具栏「发布」→ 选「立即发布」（社区作品 / 直接发布）或「投稿编辑部」。
  - 可选：`--dry` 只打印将发布内容；`--publish` 连「发布」一起点；`--probe`（登录后）打印编辑器可填字段，便于校正选择器。
- **手动步骤（脚本失灵时的兜底；以站内实际入口为准）**：
  1. 注册并登录少数派 → 点导航栏笔形按钮进入编辑器（`https://sspai.com/write`）；
  2. 填标题 → 贴入正文（本目录 `少数派文案.md`，粘贴时可点「立即转换」转富文本）→ **插入配图**；
  3. 侧栏加标签（`效率工具` `浏览器扩展` `阅读` 等）→ 打开「利益相关声明」选「自我宣传」→ 发布；
  4. 若想上**主站**：发布通道选「投稿编辑部」，或在 Matrix 发优质内容**等编辑推荐**。
- **发帖文件夹（发帖时直接用）**：`python3 tools/sspai_post_folders.py` 按 `少数派文案.md` 每篇的「配图」行，生成 `marketing/少数派/帖子/<篇号>-<短标题>/`——图从母版复制、带 `01-` 上传序号（第一张＝题图），可随时重跑重建、不入库。
- **配图建议**：**每篇 5–8 张**（顺序即上传顺序，第一张＝题图 / 封面），详见 `少数派文案.md` header 与 §5 配图清单。主文用 `github-banner → store-01 → 02 → 03 → 04 → 07 → 06 → 11`（8 张）；图与功能的对应**以文案 §5 表为准**。
- **发布后**：认真回复每一条评论；置顶一条「获取方式」评论（链接可放）。
