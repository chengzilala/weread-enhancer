# 打赏功能 · 需求文档（RPD）

> 状态：阶段一~四已完成（支持中心已含打赏页签 + 真实收款码）；**新增第 9 章「打赏公开名单」（v0.28.2 已实现）**
> 来源：`plan/version_plan.md`「还未确认的开发计划」第 3 条——增加打赏功能：随喜赞叹，几个二维码。

## 1. 项目概述

- **定位**：给「微信悦读」加一个轻量打赏入口，让喜欢它的用户可以随喜支持作者。
- **目标用户**：已经在用插件的微信读书网页版用户（weread.qq.com 访问者）。
- **当前状态**：插件无任何打赏/支持入口；配套网站 `web/` 的「关于」页也没有。

## 2. 核心功能需求（总览）

| 模块 | 描述 | 优先级 |
|---|---|---|
| 插件打赏入口 | 主菜单加「打赏」项，点击弹面板展示收款码 | P0 |
| 打赏弹层 | 弹层内展示微信 + 支付宝两张收款码 + 感谢文案 | P0 |
| 网站打赏区块 | 配套网站「关于」页（或独立区块）展示收款码 | P0 |
| 感谢文案 | 简短、不打扰、不夸张的文案 | P1 |

## 3. 详细功能需求

### 3.1 插件主菜单入口（P0）
- **需求**：主菜单新增一项「💗 打赏支持」，归入「关于」分组（在「快捷键说明」之后）。
- **交互**：点击后打开打赏弹层；点击后菜单收起（与现有菜单项行为一致）。
- **参数**：菜单项 `data-action="support"`。
- **边界**：不改变现有任何菜单项与快捷键；不新增权限。

### 3.2 打赏弹层（P0）
- **需求**：弹出面板，标题如「支持微信悦读」，正文展示两张收款码并排 + 一句感谢文案。
- **交互**：点遮罩或右上角 × 关闭；面板样式沿用现有 `wre-modal` 风格。
- **参数**：微信收款码、支付宝收款码各一张；感谢文案一段。
- **边界**：二维码图片必须清晰可扫；不自动弹窗（只在用户主动点「打赏」时出现）；不收集任何数据、不写日志泄露收款信息。

### 3.3 二维码资源引用（P0）
- **需求**：收款码图片随扩展打包，内容脚本用 `chrome.runtime.getURL()` 引用，避免相对路径被解析到 weread.qq.com 域名导致 404。
- **边界**：图片需在 `manifest.json` 的 `web_accessible_resources` 中声明。

### 3.4 网站打赏区块（P0）
- **需求**：在 `web/content/关于.md` 末尾加「打赏」小节，展示微信 + 支付宝两张收款码 + 感谢文案。
- **边界**：图片放 `web/assets/img/`；文案与插件侧一致，不夸大。

## 4. UI·UX 需求

- 视觉沿用现有 `wre-` 前缀样式，配色与主题一致，不引入新视觉风格。
- 打赏弹层：简洁、居中，两张码并排或竖排（小屏竖排），文案短（一句即可）。
- 网站区块：与「关于」页现有排版一致，标题 + 两张码 + 一句话。
- 文案基调：真诚、克制，示例「如果它帮到了你，欢迎随喜支持一杯咖啡」。

## 5. 技术实现方案

- **技术栈**：沿用 Manifest V3 + 原生 JS/CSS，零依赖，新功能进 `modules/` 新模块。
- **文件结构**：
  - 新增 `modules/support.js`：注入菜单项 + 打开打赏弹层（复用官方数据面板的独立弹层模式）。
  - 新增 `modules/support.css`：打赏弹层样式（`wre-` 前缀）。
  - 新增 `assets/donate/wechat.png`、`assets/donate/alipay.png`：收款码图片。
  - 修改 `content.js`：`handleMenuClick()` 增加 `case 'support'` 分流。
  - 修改 `manifest.json`：版本号 `0.14.3` → `0.14.4`；`content_scripts` 的 `js` 加 `modules/support.js`、`css` 加 `modules/support.css`；新增 `web_accessible_resources` 声明收款码图片。
  - 修改 `web/content/关于.md`：加打赏小节；图片放 `web/assets/img/`。
- **关键点**：内容脚本里的 `<img>` 用 `chrome.runtime.getURL('assets/donate/wechat.png')` 生成真实扩展路径，必须与 `web_accessible_resources` 匹配，否则图片 404。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 收款码图片引用路径错误（未声明 `web_accessible_resources` / 未用 `getURL`） | 图片 404，无法扫码 | 阶段一先用占位图验证 `getURL` 链路；声明与路径严格对齐 |
| 收款码是私人收款凭证 | 可能涉及隐私 | 图片是否提交 Git 由用户决定；文案/日志不关联收款码 |
| 收款码过期或更换 | 打赏失效 | 图片集中放 `assets/donate/`，替换单文件即可 |
| 官方 CSP 限制外链图片 | 若走外链会加载失败 | 一律打包进扩展走 `getURL`，不用外链 |

## 9. 打赏公开名单（v0.28.2，已实现）

### 9.1 需求背景
把打赏做成**公开记录清单**（像慈善网站的功德榜），按到账顺序列出每一笔——昵称 + 金额 + 日期 + 留言，让打赏**透明可见**。功能放在**官网**，插件 / H5 / 小程序都能跳到该名单。

> 数据来源：**作者手动登记**（收款码是个人码，微信/支付宝不会回传打赏数据，故不做后端对接）。每收到一笔就往数据文件加一条，重建网站即更新。

### 9.2 数据源：`web/donate.json`
- 与内容 vault 分离，避免 Obsidian 私有语法干扰；`build.py` 构建时读取。
- 字段：`name` 昵称（留空显示「读者」）、`amount` 金额（元，数字）、`date` 日期（YYYY-MM-DD）、`message` 留言（可空）、`anonymous` 是否匿名（true 显示「匿名读者」）。
- **登记方式：本地后台 `web/admin.py`**（v0.28.2 追加）——运行 `python3 web/admin.py` 在浏览器打开 `http://localhost:5180`，用表单**增 / 改 / 删**，数据直接写入 `donate.json`，页面内可一键「重新构建网站」。该工具仅在本机运行、不进 `dist`、不随官网发布；彻底免去手改 JSON。

### 9.3 官网「打赏名单」页（`/donate/`）
- 由 `build.py` 的 `render_donate_page()` 生成，`GENERATED_URLS` 登记该 URL；顶部导航新增「打赏」入口。
- 页面含：统计卡（累计金额 / 笔数）+ 收款码（微信 / 支付宝）+ 名单列表（按日期倒序）。
- 每条含**首字圆标**（`avatar_color()` 按昵称稳定取色）、昵称、￥金额、日期、留言；匿名者显示「匿名读者」。

### 9.4 四端入口
| 端 | 位置 | 行为 |
|---|---|---|
| 插件 | 支持与反馈 → 打赏页签 | 「查看打赏名单 →」新标签打开 `/donate/` |
| H5 | 我的 → 💗 打赏支持 | 收款码 + 「查看打赏名单 →」外链 |
| 小程序 | 设置 → 💗 打赏支持 | 收款码（走官网 CDN）+「查看打赏名单」复制链接 + 弹窗提示 |

### 9.5 成功标准
- [x] 官网 `/donate/` 页可按日期倒序展示昵称 + 金额 + 日期 + 留言，支持匿名与首字圆标。
- [x] 顶部导航有「打赏」入口。
- [x] 插件 / H5 / 小程序都有跳转或复制名单链接的入口。
- [x] 权限仍只有 `storage`；不新增后端、不上传任何数据。
