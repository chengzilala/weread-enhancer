## 1. 项目概述

### 1.1 产品定位

对标 flomo 的「产品 + 帮助中心 + 内容」三层闭环，为「微信悦读」浏览器插件配套一个对外网站：

- **教你怎么用**（快速上手 / 功能教程 / FAQ）
- **教你怎么用得好**（知识资产 / 阅读方法论 —— **粘性核心**）
- **和插件互通**（插件跳教程、网站跳安装、版本公告）

网站不是"说明书的电子版"，而是插件生态的**内容入口**：用户从插件一键跳到对应教程，从网站一键装插件。

> 复刻程度：**栏目结构与层级照搬 flomo，视觉风格自定**（适合本项目的简约文档风）。

### 1.3 目标用户

- 已安装或准备安装插件的微信读书网页版用户 —— 找"怎么用"、"为什么没生效"、看新版本改了什么、学阅读方法；
- 插件作者本人 —— 用最低成本维护内容（在 Obsidian 里写 → 一键生成 → 上线）。

### 1.4 关键决策（已与用户确认，2026-09-29）

| 决策项 | 结论 | 影响 |
|---|---|---|
| 插件 ↔ 网站联动深度 | **链接互通 + 版本公告**（不做账号、不上传任何用户数据） | 延续插件"零上传"隐私定位；只需新增一个静态 JSON |
| 「后台」形态 | **本地 Markdown + 一键生成**（无在线管理后台） | 写文章 = 加 `.md` 文件，跑一条命令生成静态站 |
| **内容工作台** | **Obsidian + 本仓库 `web/content/` 作为 vault** | 你日常用 Obsidian，直接在里面写；front-matter 即 Obsidian 属性；构建脚本兼容 wiki 链接 / `![[图片]]` / callout |
| 第一版内容范围 | **标准版 + 知识资产（阅读方法论）** | 方法论板块是粘性核心，**进第一版**，不放储备 |
| 复刻程度 | **结构照搬，视觉自定** | 见 1.2 |
| 代码落点与部署 | **本项目内 `web/` 目录 + 帽子云静态托管** | 与插件同仓库；构建产物走 `site-dist` 分支 |
| 站点域名 | **帽子云自动分配**：`wereadapp-32km31c.maozi.io`（随机前缀，无法自选；不带前缀的为跟随最新部署的主域名） | 换域名只改 `site.config.json` 一处 |
| Obsidian vault 形态 | **独立 vault（`web/content/`）** | 不并入你现有库，零冲突 |
| 知识资产首版选题 | **已确认**（4 篇，见 3.3） | — |

> ⚠️ **与最初设想的偏差（需知悉）**：你最初说"需要后台系统来填写文章数据"，最终选择"本地 Markdown + Obsidian"。这意味着**没有网页版登录后台**，"写文章"= 在 Obsidian 里写 Markdown + 跑一条命令发布。换来零后端、零数据库、零运维、零成本。若以后需要网页版后台，可平滑升级（见 6.6 储备）。

## 3. 详细功能需求

### 3.1 内容源规范（Obsidian 兼容，P0）

**需求**：文章以 Markdown 文件为唯一事实源，且**能直接用 Obsidian 打开、编辑、预览**。

**目录即栏目**（Obsidian 习惯用文件夹组织内容）：

```
web/content/
├── 首页.md                    # slug: /
├── 快速上手.md                # slug: /start/
├── 功能教程/                  # → /guide/*
│   ├── 屏占比调节.md
│   ├── 自动阅读.md
│   ├── 快捷键.md
│   ├── 阅读统计.md
│   ├── 笔记增强.md
│   ├── 官方数据.md
│   └── API Key 使用说明.md
├── 进阶技巧/                  # → /tips/*
│   └── 沉浸夜读.md
├── 知识资产/                  # → /thinking/*
│   ├── 从这里开始.md
│   ├── 高效阅读的方法.md
│   ├── 划线之后.md
│   └── 怎么选书.md
├── 阅读人格/                  # → /persona/*（见 3.10）
│   ├── 阅读人格是什么.md
│   ├── 四维详解.md
│   ├── 16 型图鉴.md
│   └── 分享图与隐私.md
├── 界面图库.md                # slug: /gallery/（图库栏目，见 3.9）
│                              #   图片源目录另在 web/assets/img/gallery/
├── 常见问题.md                # slug: /faq/
├── 更新日志.md                # slug: /changelog/
├── 关于.md                    # slug: /about/
├── 隐私政策.md                # slug: /privacy/
├── 反馈.md                    # slug: /feedback/
└── attachments/               # Obsidian 附件目录（图片）
```

**front-matter（= Obsidian 属性 / Properties）**：

```yaml
---
title: 屏占比调节：让阅读区更宽更沉浸
slug: guide/screen-ratio     # 决定 URL，写死一次不再改（换文件名不换链接）
order: 1                     # 同栏目内排序
description: 一句话摘要，用于列表页与 SEO
updatedAt: 2026-09-29
draft: false                 # true 则构建时跳过
aliases: [屏占比, 宽度]       # Obsidian 别名，同时用于 [[双链]] 解析
---
```

**语法支持清单（构建脚本必须支持）**：

| 语法 | 来源 | 处理 |
|---|---|---|
| 标准 Markdown | 通用 | 标题 / 段落 / 列表 / 引用 / 代码块 / 表格 / 链接 / 图片 / 加粗 / 分隔线 |
| `[[文件名]]`、`[[文件名\|显示文字]]` | Obsidian 双链 | 按文件名或 `aliases` 解析为站内链接；解析不到则渲染为普通文字 + 构建告警 |
| `![[图片.png]]` | Obsidian 图片 | 从 `attachments/` 复制到 `dist/assets/img/` 并渲染为 `<img>` |
| `> [!note] 标题` | Obsidian Callout | 渲染为站点提示框（支持 note/tip/warning） |
| `:::store` | 本站指令 | 渲染为「商店跳转」按钮组（只显示 `site.config.json` 里已配置链接的商店，Edge/Chrome/360；都没配则回退「安装插件」）。用在 `/start/` 的「方式 A：从商店安装」下 |
| front-matter `tags` | Obsidian | 用于栏目页分组（P1） |

**红线（避免构建踩坑）**：
- **只用标准 Markdown + 上面清单里的 Obsidian 通用语法**，不使用 Dataview、Templater 等插件私有语法（构建脚本不认）；
- 功能类文章必须注明"以代码为准"的版本，例如"适用插件 v0.11.0"；
- 文案中的**快捷键 / 权限 / 生效域名**必须与代码一致：快捷键仅 `空格 / D / F / ?`；权限为 `storage` + `host_permissions`；仅 `weread.qq.com` 生效；
- 不夸大商店文案。

### 3.3 知识资产 / 阅读方法论板块（P0，粘性核心）

**需求**：对标 flomo 的 `thinking/`（知识资产）与 flomo101，写**不依赖插件也能看**的阅读内容，让用户"为了方法而回来"。

**首版文章（已确认）**：

| 文件 | 对标 | 内容方向 |
|---|---|---|
| `从这里开始.md` | flomo `thinking/start` | 为什么"读得多"不等于"读得进去"，本站怎么帮你 |
| `高效阅读的方法.md` | 《笔记的方法》类 | 网页版阅读的效率技巧（含插件能帮上的地方） |
| `划线之后.md` | flomo 记录哲学 | 划线只是开始：怎么把划线变成自己的东西 |
| `怎么选书.md` | flomo101 系列 | 选书 / 书单思路 |

**边界与红线**：
- 方法论文章**不得变成插件硬广**——允许自然带出"插件能帮你做什么"，但主体必须是通用方法；
- 不做绝对化、评判性、健康类建议；不编造数据；
- 文章可以互相 `[[双链]]`，形成知识网络（这正是 Obsidian 的强项）。

### 3.4 站点导航与通用组件（P0）

- **顶部导航**：首页 / 快速上手 / 功能教程 / 进阶技巧 / **阅读人格** / 知识资产 / **图片** / FAQ / 更新日志（响应式折叠为汉堡菜单）；
- **左侧目录**：文章所属栏目的全部文章 + 当前高亮（对标 flomo 文档站的目录树）；
- **文章页**：标题、更新时间、正文、上一页 / 下一页、页脚；
- **全站页脚**：插件安装入口、更新日志、隐私政策、版本号（**构建时自动读 `manifest.json`**）；
- **锚点**：每篇教程生成稳定 URL（由 front-matter `slug` 决定），供插件深链使用。

### 3.5 版本公告接口（P0，联动关键）

**需求**：构建时自动生成一份静态 JSON，插件无需任何后端即可查询最新版本。

- **产物路径**：`/api/latest.json`
- **结构（草案）**：

```json
{
  "latestVersion": "0.11.0",
  "releasedAt": "2026-09-29",
  "minSupportedVersion": "0.9.0",
  "notice": "v0.11.0 新增：官方数据阅读行为报告",
  "changelogUrl": "https://wereadapp-32km31c.maozi.io/changelog/",
  "storeUrls": { "edge": "…", "chrome": "…" }
}
```

- **版本号来源**：构建时读取仓库根 `manifest.json` 的 `version` 自动写入 —— **单一事实源，杜绝两处漂移**；
- **边界**：纯静态 GET，无鉴权、无写操作、不接收任何用户数据。

### 3.6 Obsidian 内容工作流（P0）

**需求**：把"写文章 → 上线"压缩成最短路径，全程在 Obsidian 里完成。

**工作流**：

1. Obsidian 里 **打开 `web/content/` 作为 vault**（独立 vault，不影响你现有库）；
2. 「设置 → 文件与链接」中把**附件默认位置**设为 `attachments/`（与 3.1 目录一致）；
3. 新建 `.md`（或用模板插件套 front-matter 模板）→ 写内容 → 用 `[[双链]]` 互链、`![[图.png]]` 插图；
4. 发布：终端跑 `python3 web/build.py`（可选：装 Obsidian 的 **Shell commands** 插件，绑定该命令，在 Obsidian 内一键构建 + 部署）；
5. 本地预览：`python3 web/serve.py`。

**可选增强**：
- **Obsidian Git 插件**：自动 commit / push 内容变更（若你已在用 Git 工作流）；
- **模板**：提供一份 `_模板.md`，新建文章时自动带 front-matter 骨架（title / slug / order / description / draft）；
- **发布前自检**：`build.py` 输出告警清单（双链解析失败 / 图片缺失 / slug 重复 / 缺 description），写完就发现问题。

**边界与红线**：
- `web/content/.obsidian/` 属本地配置，**不入库**（加入 `.gitignore`）；

#### 3.7.1 菜单入口「📖 帮助中心」

- 旧代码只动一处：`content.js` 的 `handleMenuClick()` 增加 `case 'help'` 做分流（与 `stats` / `notes` / `official` 同一做法）；
- 点击行为：`window.open('<站点>/guide/?from=ext&v=<当前版本>&p=<当前面板>')`；
- 参数用途：**仅**用于站点侧聚合"哪篇教程被看得多"（可选），不含任何用户标识。

#### 3.7.2 版本提示

- 时机：插件启动时（或每天首次）GET `<站点>/api/latest.json`；
- 逻辑：`latestVersion` 比当前 `chrome.runtime.getManifest().version` 新 → 「帮助中心」菜单旁显示红点，面板内提示"有新版本，去看看更新了什么"；
- 边界：**网络失败 / 超时（3s）/ 返回异常一律静默**，绝不打扰、绝不报错弹窗；
- 缓存：结果缓存 24 小时到 `chrome.storage.local`，避免每次启动都请求。

#### 3.7.3 权限与隐私（红线）

- `manifest.json` 需在 `host_permissions` 新增站点域名；
- 该请求**只发一个 GET、只带版本号类参数，不上传任何用户数据、不使用 Cookie、不做用户追踪**；
- 必须同步更新：`README.md`、`release/privacy.md`、商店文案 —— 权限项从"仅 storage + 官方网关"变为"多一个网站域名"。

### 3.8 API Key 使用说明页（P0）

**需求**：在「功能教程」新增一篇「API Key 使用说明」（文件 `web/content/功能教程/API Key 使用说明.md`，slug `guide/api-key`），把插件里**两把 Key** 的获取、配置、校验、清除与风险一次讲清。

**必须覆盖的 6 段**：

1. **Key 是什么、为什么需要**

2. **怎么获取（`wrk-` Key）**
   - 路径（以代码文案为准）：微信读书 App → 「微信读书 Skill」页面 → 复制 `wrk-` 开头的 API Key；
   - 配步骤截图（图片放 `web/content/attachments/`）。
3. **怎么在插件里配置**
   - 路径：微信悦读主菜单 → 「🔑 API Key」→ 粘贴 → 「保存并校验」；
   - **保存即校验**：先探连通（`/_list`），再用需登录的轻量接口（`/readdata/detail`，`mode=weekly`）确认真实有效后才会写入；
   - 面板行为：输入框为密码态 + 「显示 / 隐藏」明文；「清除 Key」；「刷新状态」；
   - 状态字段：已配置 / 未配置 · 保存时间 · 最近校验时间 · `skill_version`。
4. **可选：DeepSeek Key（AI 增强）**
   - `sk-` 开头，**可选项**；用于让「阅读洞察」报告的**执行摘要**由 AI 生成人格化解读，**数字仍由本机规则计算、不交给 AI**；不配置则用默认规则化摘要，功能不受影响；
   - **隐私必须显式写明**：启用后，生成报告时会把「笔记最多的几本书」的划线 / 想法**原文样本**发送给 `api.deepseek.com` 用于生成文字。
5. **隐私与安全（红线口径）**
   - Key 只存在**本机** `chrome.storage.local`（`wreOfficialSkill` / `wreDeepSeekKey`），不上传（DeepSeek 例外见上）；
   - 插件日志只输出**掩码**（形如 `wrk-****(长度)`），不打印明文；
   - 官方提醒原话：Key 等同账号读取权限，请勿粘贴到聊天、截图或提交到代码仓库；怀疑泄露可在 App 里重置。
6. **常见问题（错误对照，文案以代码为准）**

| 情形 | 插件实际提示（对齐代码） | 用户该做什么 |
|---|---|---|
| 未配置 | 尚未配置 API Key | 去「🔑 API Key」粘贴 |
| 格式不对 | Key 格式不对：应以 `wrk-` 开头 | 确认复制完整、未漏前缀 |
| 无效 / 失效 | API Key 无效或已失效（HTTP 401 / 403） | 回 App 重新获取 |
| 超时 | 请求超时（超过 10 秒） | 检查网络后重试 |
| 网络不通 | 网络不通或官方网关不可达 | 检查网络 / 代理 |
| 网关异常 | 官方网关返回异常 / 内容无法解析 / `errcode` 业务错误 | 稍后重试；持续失败走「支持与反馈」 |
| 需要升级 | 返回 `upgrade_info` | 更新插件版本 |

**红线**：
- 教程**禁止出现任何真实 Key**，示例一律用 `wrk-xxxxxxxx` / `sk-xxxxxxxx` 占位；
- 获取路径、校验行为、存储位置、错误文案必须与 `background.js`、`modules/official.js` **逐条对齐**，页内标注"以 vX.Y.Z 代码为准"；

- 图内**无真实 Key / 隐私 / 账号标识**；快捷键 / 权限 / 域名与代码一致；不夸大（不写"最强 / 第一"）；

## 4. UI·UX 需求

### 4.1 设计原则

- **像文档，不像宣传页**：以阅读为主的排版，正文宽度收敛、行高舒适；
- **零跳转成本**：任何一篇教程页面，3 秒内能拿到"我该怎么用"；
- **结构与 flomo 一致，视觉自定**：沿用插件观感（圆角、柔和阴影、Emoji 分组），但不搬 flomo 的样式；网站不引入插件里的 `wre-` 前缀（独立站点）。
- **展示型页面是例外**：`/` 首页与 `/gallery/` 图库**可以"像宣传页"**——**大图为主、极简文案、滚动顺滑**（见 3.11）；正文类页面（教程 / 方法论 / FAQ / 关于）仍保持"像文档"。

### 4.2 视觉需求

- 亮 / 暗双主题：跟随系统 `prefers-color-scheme`，不强制手动切换（P1 可加手动开关）；
- 移动端自适应：单列、导航折叠、正文可读；
- 代码块 / 快捷键用等宽字体展示；
- 截图统一放 `web/content/attachments/`（Obsidian 管理），构建时复制到 `dist/assets/img/`；可复用 `screenshots/` 里的成品图。
- **首页（`/`）**：**大图落地页**——Hero 主视觉（含安装等按钮组）+ 功能大图区 + 极简清单；图片进入视口**渐入**、悬停**微放大**（见 3.11）。
- **图库（`/gallery/`）**：**响应式大图**（宽屏大图、移动端单列）+ 分组标题 + 一句说明；点击看大图（lightbox，纯 CSS/JS，图注来自 `alt`），`Esc` / 遮罩关闭；图注用中性描述，不做促销话术。
- **动效统一（顺滑感）**：渐入 / 悬停缩放用原生 CSS `transition` + 原生 JS `IntersectionObserver`，时长 **200–400ms**；`prefers-reduced-motion` 下**关闭位移与缩放**，降级为静态。

### 4.3 文案原则

- 全程中文人话，少术语；错误场景给"怎么办"而不只是"为什么"；
- 标注"以 vX.Y.Z 代码为准"；不夸大（不写"最强""第一"）。

## 5. 技术实现方案

### 5.1 技术栈

- **内容**：Markdown + front-matter（在 Obsidian 中书写）
- **构建**：Python 脚本 `web/build.py`（**零第三方依赖**：只用 Python 标准库，本机 Python 3.9 即可；Markdown 渲染先自写"够用子集"，覆盖 3.1 的语法清单，不引入任何 npm/pip 依赖）
- **产出**：`web/dist/` 纯静态 HTML/CSS/JS（**零 CDN、零第三方脚本、无运行时依赖**）
- **预览**：`web/serve.py`（Python 内置 `http` 模块，极简静态服务器）
- **部署**：帽子云静态托管（国内可直连）；构建产物 `web/dist/` 走 `site-dist` 分支，平台直接发分支内容、无需平台侧构建

### 5.2 文件结构（规划）

```
微信读书插件/
└── web/
    ├── content/                 # 📝 Obsidian vault（文章源，唯一事实源）
    │   ├── …（见 3.1 结构）
    │   ├── attachments/         #     图片（Obsidian 附件目录）
    │   └── .obsidian/           #     本地配置，不入库
    ├── assets/
    │   ├── site.css
    │   ├── site.js
    │   ├── account.js           # 「我的账户」页脚本（import /app/src/ 的 store/api/ui，与网页版同一套账户）
    │   └── img/
    ├── templates/
    │   └── layout.html          # 站点骨架（顶栏 / 侧栏 / 页脚）
    ├── site.config.json         # 站点名 / 导航 / 页脚 / 商店链接 / 站点域名
    ├── build.py                 # 🔨 一键构建：md → dist/ + dist/api/latest.json
    ├── serve.py                 # 🖥 本地预览（零依赖）
```

### 5.3 一键命令

```bash
python3 web/build.py    # 构建（生成 dist/ 与 dist/api/latest.json）
python3 web/serve.py    # 本地预览（默认 http://localhost:5173）
```

### 5.4 构建脚本要做的事

1. 读 `site.config.json` 与仓库根 `manifest.json`；
2. 扫描 `web/content/**.md`，解析 front-matter，跳过 `draft: true`；
3. Markdown → HTML，并处理 **Obsidian 语法**（`[[双链]]` → 站内链接、`![[图片]]` → `<img>` + 复制附件、`> [!note]` → 提示框）；
4. 套 `templates/layout.html`，生成导航、左侧目录、上下篇、页脚；
5. 复制 `assets/` 与 `attachments/` 到 `dist/`；
6. 生成各栏目索引页（功能教程 / 进阶技巧 / 知识资产 / 阅读人格）与 `/changelog/`；**首页（`/`）按「大图落地页」结构渲染**（作者的话 / Hero / 功能大图块 / 极简清单，走专用模板或结构化区块，见 3.11）；
7. 为图库原图（`web/assets/img/gallery/`）生成缩略图到 `dist/assets/img/gallery/thumbs/`，并把内容页里的图库图片渲染为**响应式大图**（首屏缩略图 + 点击看原图；见 3.9）；需 Pillow，缺失则退回原图 + 告警；
8. 生成 `dist/api/latest.json`（版本号取自 `manifest.json`，更新说明取 `更新日志.md` 最新一节）；
9. 输出构建摘要 + **告警清单**（双链解析失败 / 图片缺失 / slug 重复 / 缺 description）。
10. 入场动效由 `site.js`（`IntersectionObserver` 加 `.is-inview`）+ `site.css`（`transition`）实现，构建只需产出这两个静态资源，**不引入任何动画库**。

### 5.5 与插件仓库的边界（红线）

- **不改插件既有逻辑**：网站是全新 `web/` 子目录，插件侧只新增 `modules/help.js|css` 与 `content.js` 的一处 `case`；
- `web/dist/`、`web/content/.obsidian/`、zip 一律不入库（沿用 `.gitignore` 习惯）；
- 密钥 / token 一律不入库；作者个人信息只放公开联系方式。

## 8. 风险与应对

| 风险 | 应对措施 |
|---|---|
| 自写 Markdown 子集不够用，或 Obsidian 特殊语法渲染出错 | 3.1 明确"语法支持清单"，清单外用 Obsidian 原生预览即可、不指望构建支持；构建输出告警清单；确认不够时在 `build.py` 内扩展渲染子集（保持零依赖），不引入第三方 Markdown 库 |
| Obsidian 双链 / 图片解析不到（改名、中文名、路径） | `slug` 与文件名解耦（改文件名不影响链接）；`aliases` 参与解析；解析失败降级为普通文字 + 构建告警，不中断构建 |
| 内容放仓库 vs 放 Obsidian 现有 vault 的取舍 | 本期用**独立 vault = `web/content/`**，零冲突；后续若想并入现有 vault，用软链切换（附 B 假设 6） |
| `.obsidian/` 本地配置误入库 | `.gitignore` 增加 `web/content/.obsidian/` |
| 新增 `host_permissions` 触发浏览器权限提示，用户疑虑 | 权限只加一个网站域名、只用于 GET 版本公告；同步更新 README / `release/privacy.md` / 商店文案，把"为什么需要"写清楚 |
| 用户误以为插件向网站上传了阅读数据 | 动线文案与隐私政策写明："只发一个 GET 请求取版本号，不上传任何阅读数据，不使用 Cookie" |
| 网站文案与代码漂移（快捷键 / 权限 / 域名说错） | 每篇功能文章标注"以 vX.Y.Z 代码为准"；发布前按第 7 章第 5 条逐项核对；版本号由构建自动同步 |
| 网站与插件版本号两处维护、容易不一致 | `latest.json` 与页脚版本号**一律构建时读 `manifest.json`**，禁止手写 |
| 帽子云免费额度 / 域名限制 | 纯静态站，额度足够；域名由平台自动分配（随机前缀、无法自选），换名重建会换域名；后续有需要可绑自有域名（改 `site.config.json` 一处） |
| 内容长期不更新，网站变"僵尸" | 更新日志与插件发版**绑定**：发版即补一节 changelog 再构建；写入插件发版流程 |
| 教程里出现真实 Key / 诱导用户把 Key 交给他人 | 红线（3.8）：示例只用 `wrk-xxxxxxxx` / `sk-xxxxxxxx` 占位；明确"Key 等同账号读取权限、只存本机、勿发任何人"；发布前全站搜 `wrk-`、`sk-` 逐个确认是占位符 |
| 用户以为配置 Key = 把账号密码交给插件 | 教程第 1 段先讲清"Key 是什么、不是账号密码、只存本机、可随时清除/重置"；插件侧同口径（3.7 帮助中心/引导态文案与网站对齐） |
| 方法论文章写成插件硬广，失去粘性 | 明确红线（3.3）：主体是通用方法，插件只能自然带出 |
| `dist/` 误入库导致仓库膨胀 | `.gitignore` 增加 `web/dist/` |

| 首页改版偏离"像文档"定位 | 明确首页 / 图库为**展示型页面例外**（3.11 / 4.1）；正文页仍文档风；文案极简但准确 |
| 首页大图与插件当前界面脱节 | 图片复用图库源；发版即同步；图注标注适用版本 |

## 附 A. 需求三件事（确认用）

- **用户目标**：微信读书插件用户有一个内容入口站（教程 / 技巧 / **阅读方法论** / FAQ / 更新日志），插件与网站互相引流；作者能在 **Obsidian** 里用最低成本维护内容。
- **输入输出**：
  - 输入 = 作者在 `web/content/`（Obsidian vault）写的 Markdown 文章 + 仓库根 `manifest.json` 的版本号
  - 输出 = ① 纯静态网站（帽子云）；② `dist/api/latest.json`（插件版本公告源）；③ 插件内「📖 帮助中心」入口
- **成功标准**：见第 7 章（13 条，均可判定）。
