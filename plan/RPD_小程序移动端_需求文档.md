# RPD 需求文档 · 微信悦读移动端（微信小程序 + 云开发）

> 版本：v0.1（需求稿）
> 定位：**浏览器插件的移动端延伸**，只做「读完之后」的复盘与分享，不做阅读过程增强。
> 关系：本文档与 [RPD_需求文档.md](file:///Users/Admin/Knowledge/Coding/微信读书插件/plan/RPD_需求文档.md)（插件主文档）并列，互不覆盖。插件侧功能仍以主文档为准。

## 1. 项目概述

- **定位**：把插件里最有传播力、最适合手机的部分（阅读数据 + 阅读人格）做成微信小程序；是「阅读数据行为分析展示渠道」，不是阅读器。
- **目标用户**：已在用「微信悦读」插件、或愿意粘贴自己微信读书 `wrk-` API Key 的微信读书用户。
- **当前状态**：从零新建。插件侧的数据算法与报告模型已存在，可复用（见 §5.4）。
- **已确认的三件事（用户目标 / 输入输出 / 成功标准）**：
  - **用户目标**：在手机上随时看自己的阅读数据与阅读人格，并能一键分享；API Key 只输一次。
  - **输入输出**：输入 = 用户自己的 `wrk-` API Key（仅本机保存）；输出 = 手机端可视化报告 + 可分享的图片/小程序卡片。
  - **成功标准**：输入一次 Key 后长期免输；核心数据/人格能正确展示；能生成并分享；提审通过。

### 1.1 关键前提（决定方案成立与否）

1. 插件能拿到官方数据，靠的是**浏览器扩展权限**绕过了官方网关的 CORS 限制。官方网关 `POST https://i.weread.qq.com/api/agent/gateway` 的 OPTIONS 预检返回 401，**浏览器/小程序都无法直连**（依据：[background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js#L6-L11)）。
2. 因此移动端**必须有一个中转服务**。已核实：**微信云开发的云函数出网不受小程序 request 合法域名白名单限制**（走微信私有协议），云函数可自由请求外部 HTTPS 接口，正好充当这个中转。
3. 用户已有**微信小程序账号**，无认证服务号、无自有服务器 → 选「小程序 + 云开发」，不选 H5。

## 3. 详细功能需求

### M0 云函数中转（地基）

- **需求**：小程序向云函数发起调用，云函数转发到官方网关并把结果回传。
- **接口约定**：
  - 云函数名：`wereadProxy`
  - 入参：`{ apiName: string, params: object, apiKey: string }`
  - 转发：`POST https://i.weread.qq.com/api/agent/gateway`，Body = `params + { api_name, skill_version }`，Header 带 `Authorization: Bearer <apiKey>`
  - 出参：`{ ok: true, data, upgrade } | { ok: false, code, error }`（`code` 覆盖 auth / http / parse / errcode / timeout / network）
- **边界**：
  - `skill_version` 与插件保持一致（当前 `1.0.4`，见 [background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js#L22)），集中一处，便于日后同步升级。
  - 超时 10s；401/403 统一提示「Key 无效或已失效」。
  - **红线**：云函数不持久化、不记录 `apiKey`（日志只允许掩码）；不做任何数据落库。

### M1 API Key 管理

- **需求**：用户粘贴自己的 `wrk-` Key，校验通过后保存到本机，之后免输。
- **交互**：
  1. 「我的 → API Key」设置页：密码型输入框，粘贴后点「保存」。
  2. 保存前调用 `/_list` 探连通 + `/readdata/detail(weekly)` 确认有效（口径同插件 [background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js#L121-L133)）。
  3. 校验通过 → `wx.setStorageSync('wre_api_key', key)`，返回首页并刷新数据。
  4. 支持「清除 Key」；清除后所有需 Key 的页面回到引导态。
- **参数**：Key 必须 `wrk-` 开头，否则前端直接拦截。
- **边界**：
  - Key **仅存手机本地**（小程序 storage）。卸载小程序或清理微信缓存会丢失，需重填 —— 文档中如实说明。
  - 任何页面调用数据前先检查本地是否有 Key；无 Key 一律显示引导，不发起请求。

### M2 数据总览（首页）

- **需求**：一屏看完关键数字。
- **内容**：阅读时长（今日 / 本周 / 本月 / 本年 / 累计）、读完本数、笔记数等，来自 `/readdata/detail`（多模式：`weekly` / `monthly` / `annually` / `overall`）。
- **交互**：周期切换（本周 / 本月 / 本年 / 累计）；下拉刷新；数据缓存 30 分钟（与插件一致）。
- **边界**：无数据/新用户 → 友好空态，不报错；单接口失败只降级该卡片。

### M3 阅读人格

- **需求**：基于用户自己的官方数据，本机算出 4 维人格代码 + 16 型称号 + 依据。
- **复用**：算法与判定规则直接复用插件实现（[official.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/modules/official.js) 内的「阅读人格」相关纯计算逻辑，抽出为共享模块）。
- **交互**：主卡展示「人格代码 + 主称号 + 一句定调」；展开看 4 维判定值、数据证据、高频词 TOP10、情绪比例。
- **边界**：数据不足时走**降级引导**，绝不硬出结论；固定声明「趣味参考、非心理测评」，不使用 MBTI® 商标名。

### M4 阅读行为报告

- **需求**：把插件「阅读行为报告」的内容按手机屏适配后分章节展示。
- **章节（首版建议）**：执行摘要 → 数据全景 → 阅读时段分布 → 偏好画像（作者/出版社）→ 读得最多 → 完读率 → 笔记行为 → 附录数据说明。
- **边界**：章节可折叠；「执行摘要」首版用**规则化摘要**（不接 AI）；接入 DeepSeek 作为 P2（见 §6 取舍）。

### M5 分享（P1）

- **需求**：把人格/数据做成可分享内容。
- **两种形态**：
  1. **小程序卡片**：`onShareAppMessage`，转发给好友/群，标题带人格称号。
  2. **竖版分享图**：canvas 绘制海报（人物线描 + 人格卡 + 词语亮点 + 数据证据 + 品牌署名），保存到相册或分享。
- **复用**：分享图的版式与文案复用插件现有分享图设计；人物线描素材随包内置、运行时不联网。
- **边界**：canvas 绘制在小程序端需重新实现（不能直接复用插件的 HTML/CSS 版）。

### M6 / M7 书架与笔记概览（P1）

- 书架：`/shelf/sync`，区分电子书 / 专辑 / 公众号，展示封面、作者、进度。
- 笔记：`/user/notebooks`（游标分页），展示笔记数量与最近笔记概览。
- **跳转**：点击书籍 → 用官方回包解析出的**网页版详情页**（沿用插件「不自行拼接链接」的口径）。
- 边界：书架/笔记各自 30 分钟缓存；一路失败只降级对应模块并给出提示。

### M8 / M9 用户标识（P1/P2，可选）

- **M8（静默）**：云函数天然能用 `cloud.getWXContext().OPENID` 拿到用户标识，**无需任何授权弹窗、无需 wx.login 用户操作**。首版可不用；若将来要做「换手机也能同步」，再启用。启用时**隐私承诺需改写**（见 §8）。
- **M9（主动填写）**：`wx.getUserProfile` 已不适用于真实信息；现在要头像昵称需 `button open-type="chooseAvatar"` + `input type="nickname"`，且必须在**用户隐私保护指引**中声明。首版不做。

## 4. UI · UX 需求

- **形态**：竖屏优先；底部 Tab 导航（已确认）：**首页 / 人格 / 报告 / 书架 / 我的**（五栏；笔记概览归入「我的」，设置亦归入「我的」）。
- **风格**：与插件、官网保持一致的品牌色与圆角卡片；移动端以「大数字 + 卡片 + 折叠区」为主。
- **必备状态**：加载中（骨架屏）、空态（引导配 Key）、错误态（可重试）、无 Key 拦截态。
- **性能**：首屏 1 屏内出关键数字；重数据异步加载；接口结果本地缓存，避免重复请求。
- **文案**：所有权限 / 域名 / 数据来源说明**以代码实测为准**，不夸大（沿用项目红线）。

## 5. 技术实现方案

### 5.1 技术栈

- 前端：微信小程序原生（WXML/WXSS/JS 或 TS），基础库 ≥ 2.21.2（为未来头像能力预留）。
- 后端：**微信云开发**（云函数 `wereadProxy`）+ 云数据库（**本期不用**，仅预留）。
- 数据源：官方 Agent 网关 `/readdata/detail`、`/shelf/sync`、`/user/notebooks`。
- 零外部依赖原则延续：不引入第三方统计/广告 SDK。

### 5.2 目录结构（建议）

统一放在仓库新增的 `mobile/` 目录下（与浏览器插件源码并存、互不影响）：

```
mobile/
├── project.config.json          # 开发者工具项目配置（miniprogramRoot / cloudfunctionRoot）
├── README.md                    # 运行与验证说明
├── miniprogram/                 # 小程序前端
│   ├── app.js / app.json / app.wxss
│   ├── config.js                # 云开发环境 ID
│   ├── pages/
│   │   ├── home/                # M2 数据总览
│   │   ├── persona/             # M3 阅读人格
│   │   ├── report/              # M4 阅读行为报告
│   │   ├── shelf/               # M6 书架（P1）
│   │   ├── notes/               # M7 笔记（P1）
│   │   └── settings/            # M1 API Key 管理
│   ├── shared/                  # 公共模块（gateway / store / format，见 5.4）
│   └── components/              # 卡片 / 图表 / 空态等
└── cloudfunctions/
    └── wereadProxy/             # 云函数：官方网关中转
```

### 5.3 数据流

```
小程序页面
  → 读本地 Key（wx.getStorageSync）
  → wx.cloud.callFunction('wereadProxy', {apiName, params, apiKey})
      → 云函数补 Authorization + skill_version，转发 i.weread.qq.com
      → 返回 {ok, data}
  → 页面/共享模块做纯计算与渲染
```

### 5.4 复用插件资产（关键，避免重写）

- **纯计算逻辑可复用**：`report-core` / `persona-core` 从 [official.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/modules/official.js) 中抽取「数据计算」与「渲染」解耦后的纯函数部分（报告模型、四维判定、词频/情绪统计等）。
- **不可直接复用**：所有 DOM/HTML/CSS 渲染、分享图绘制、屏占比等桌面增强逻辑 —— 需在小程序端重新实现。
- **原则**：抽取时**不改动插件现有行为**（插件红线：旧代码不改，新功能写新模块）；共享模块由两端引用，避免两套算法漂移。

## 7. 成功标准

1. 用户粘贴 `wrk-` Key 一次后，之后打开小程序**免输**即可看数据。
2. 首页核心指标、阅读人格、行为报告在真机上**数据正确、无白屏**。
3. 无 Key / Key 失效 / 接口失败均有明确引导，不出现未处理报错。
4. 能生成竖版分享图并成功分享（或转发小程序卡片）。
5. 小程序**提审通过**并可正式发布。

## 8. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 云开发费用/额度 | 云开发按量计费，免费额度以开通时控制台为准 | 阶段 0 先确认额度；接口做缓存与合并，减少调用次数 |
| 中转导致「Key 上传」的隐私表述冲突 | Key 会随请求经过云函数（内存中转、不存储） | 如实改写隐私声明：「Key 仅本机保存，调用时经服务中转，不存储、不记录」；隐私指引中同步声明 |
| 官方网关变更 / Key 风控 | 网关接口、`skill_version` 或风控策略可能变化 | `skill_version` 集中一处便于升级；错误码统一降级提示；不做高频轮询 |
| 小程序审核（类目/资质/隐私） | 个人主体类目受限；涉及第三方数据可能被追问 | 提前确认类目；隐私指引如实填写；不夸大文案 |
| 分享图 canvas 移植成本 | 插件分享图基于 HTML/CSS，无法直接复用 | 首版可先只做「小程序卡片分享」，分享图作为阶段 2 增强 |
| 算法抽取引入漂移 | 两端共享计算逻辑若无统一来源易分叉 | 抽成单一共享模块被两端引用；抽取过程不改插件行为 |
| iOS/Android 差异 | 相册权限、canvas 表现等有差异 | 阶段 2 在两端真机各验证一遍 |
