## 一、分析

### 1.1 平台特性（决定「在哪发、怎么发」）

微信读书 App 与小红书最大的不同：**它是一个「围绕书」的封闭社区**，且**几乎没有可点外链**。本号**只在「书友（书圈）」里发想法**（不在书评区写），所以打法不是「发笔记引流」，而是**「用一条条贴书的想法把自己做成一个可信的读书人」**，让用户主动来找你。

| 特性 | 对本次推广的含义 |
|---|---|
| 内容围绕「书」组织：**书友（书圈）动态 / 话题、书评** 等是主要 UGC 入口 | 选题必须**贴书**，不能像小红书那样发纯情绪帖 |
| **无外链**：想法里放不了可点链接，敏感词还会被过滤 | 引流只能「**软引导**」：主页简介写关键词、正文引导「主页 / 私信 / 评论区」，让用户自己搜 |
| 主页（个人页）是唯一「门面」，可写简介、展示想法 / 书评 / 书单 / 笔记数 | **主页＝落地页**，所有内容都为「把人引到主页」服务 |
| **熟人关系链**（打通微信）：好友能看你的读书动态 | 内容要「**体面、可信、不像广告**」，否则伤熟人好感 |
| 流量入口＝**书友「推荐 / 关注 / 话题」三流 + 搜索**，想法曝光最大 | 用热门 / 长销书**蹭书自带流量**；发帖带 **#话题** 进话题流 |
| 用户画像：以爱读书、自我提升人群为主，**与产品受众高度重合** | 属「种子人群」，无需教育「微信读书是什么」 |
| 审查比小红书更「静默」：可能不出提示就限流 / 删除 | 规避硬广口吻、外链、二维码、诱导互动、刷量 |

### 1.2 五个流量触点（架构核心 · 决定资源分配）

微信读书 App 能做 UGC 的地方就这几处，**按「曝光量 × 可持续性」排序**：

| # | 触点 | 位置 | 曝光 | 属性 | 主用途 |
|---|---|---|---|---|---|
| ① | **书友 · 动态（想法）** | App 底部「书友」→ 右下「+」发想法 | ★★★★★ | 主战场 | **爆点 / 主战场** |
| ② | **书友 · 话题** | 发想法时带 `#话题`，进「书友 → 话题」流 | ★★★★ | 借话题流量 | **破圈 / 互动** |
| ③ | **书友 · 推荐 / 关注** | 书友首页「推荐 / 关注」两条流 | ★★★★ | 算法推荐 | **曝光 / 涨粉** |
| ④ | **书评** | 每本书详情页「书评」区 | ★★★ | 借书的流量 | （备用 · **本号不主发**） |
| ⑤ | **主页 + 关注互动** | 个人页 / 关注流 | ★★ | 承接 + 裂变 | **承接转化 / 复访** |

> **一句话**：**书友发想法打爆点，带话题蹭流量，推荐流涨粉，主页接流量**（书评仅备用）。

### 1.3 产品 × 平台匹配度

- **强匹配**：微信读书用户＝产品天然受众，且「网页版难用」这个痛点，**只有微信读书重度用户才懂**——在书友想法里写这个痛点，共鸣度最高。
- **关键错位（必须处理）**：App 是**手机端**，而**插件是电脑端**。所以落地页不是插件本身，而是：
  - 手机用户 → **H5 阅读报告 / 阅读人格**（`reader.chesterlee.cn/app/`，打开即用，生成「阅读人格」分享图可再发回微信读书 / 朋友圈）；
  - 电脑用户 → **官网教程** `reader.chesterlee.cn`（告诉他在电脑上装 Edge / Chrome 插件）。
- **卖点翻译成「微信读书语言」**（决定文案口吻）：
  - 屏占比 / 沉浸阅读 → 「网页版读着太挤」
  - 阅读人格 MBTI → **借「书」+ 借 MBTI 热度**，最适合做书友想法的传播钩子
  - 笔记聚合 / 导出 / 朗读 → 「你划过的线，别再躺着睡觉」
  - 隐私 / 本地存储 → 打消「装插件安不安全」的顾虑
- **风险 / 短板**：
  1. 无外链 → 转化链路比小红书更长，靠「关键词 + 主页」承接；
  2. 「插件 / API Key / 大模型」偏技术 → 用生活化例子讲；
  3. 平台对工具类推广敏感 → 全程**第一人称亲测口吻**，弱化广告感。

### 1.4 目标受众分层（决定选题优先级）

| 分层 | 画像 | 最吃的卖点 | 主投触点 |
|---|---|---|---|
| A 读书打卡党 | 学生 / 考研 / 考公 | 统计、笔记、专注勿扰 | 书友动态 |
| B 效率工具控 | 白领 / 产品 / 开发 | 屏占比、导出、找书、快捷键 | 书友动态 |
| C MBTI / 自我探索 | 泛人群（面最大） | 阅读人格、分享图 | 书友动态 + 话题 |
| D 微信读书重度用户 | 各年龄段 | 全功能、隐私、手机版 | 书友动态 |

### 1.5 结论（分析落点）

> **钩子 = 痛点（网页版难用）+ 亲测口吻 + 人格图传播**；
> **首发在「书友」里发一篇综合全面版想法建立认知，再用「阅读人格」冲量，最后靠话题 + 高频想法长期承接复访。**

## 二、架构（内容 / 账号 / 引流 三张图）

> 本节是本文档的**核心**：把「在哪发、发什么、怎么接」一次画清。三张图分别是**触点架构**（发在哪）、**内容架构**（发什么）、**引流承接架构**（怎么接）。

### 2.1 触点架构（发在哪）

```
微信读书 App（底部「书友」＝书圈）
├── ① 主页（门面 / 落地页）        ← 全部内容的最终去向
│     ├─ 昵称：含「读 / 书」关键词
│     ├─ 简介：一句话定位 + 入口关键词（谐音避敏感词）
│     └─ 置顶：把跑得最好的想法顶上去
├── ② 书友 · 动态（爆点 / 主战场）  ← 右下「+」→ 写下这一刻的想法，单篇最可能爆
│     └─ 写贴书的想法；文末软引导「主页 / 私信」
├── ③ 书友 · 话题（破圈 / 借流量）  ← 发想法时带 #话题，进「书友 → 话题」流
│     └─ 选读书打卡 / 你在读什么书类话题，蹭公共流量
├── ④ 书友 · 推荐 / 关注（曝光）    ← 发完靠算法推 / 关注流分发
│     └─ 首图 + 钩子标题提点开率；高频发养号
└── ⑤ 关注 / 互动（复访 / 裂变）    ← 关注读书博主、回评、互关
      └─ 评论高质量内容，让陌生人点进你的主页
```
（书评区为平台功能，但**本号不在书评里写**，仅备用。）

### 2.2 内容架构（发什么 · 三层配比 5:3:2）

| 层 | 作用 | 占比 | 特征 | 带产品？ | 主要触点 |
|---|---|---|---|---|---|
| **破圈层** | 涨粉 / 立人设 | 50% | 贴书的想法，讲读书方法、情绪共鸣 | **不带**（最多文末轻带） | 书友动态 · 话题 |
| **种草层** | 建立「我也想要」 | 30% | 第一人称亲测功能演示 | 带，弱转化 | 书友动态 |
| **转化层** | 安装 / 使用 | 20% | 教程、入口、工具合集 | 强引导 | 书友动态 · 主页 |

> **首篇发「综合全面版」、其后冷启动期「只发破圈层」**：先用一篇综合全面版想法把功能一次讲全、立住完整认知，再把主页做成「爱读书的人」，让系统给账号打上「读书」标签，再上更多带产品的内容。
>
> **与小红书的差异**：微信读书无外链 + 内容必须贴书，所以「转化层」比重要更低、更软——**别指望一篇想法直接拉装插件，先让人信你、再让人搜你**。

### 2.3 账号架构（主号人设 + 主页装修）

- **一号到底**：微信读书账号与微信绑定、换号成本高，**只运营一个主号**，不搞矩阵（App 内也没有小号生态）。
- **人设关键词**：`爱读书 + 效率工具控 + 会做小工具的人`——3 个词贯穿全部内容。
- **主页装修四件套**：
  1. **昵称**：如「XX 的阅读实验室」；
  2. **简介**：一句话定位 + 入口提示（**用谐音 / 图标绕敏感词**，如「网纸 reader.chesterlee.cn」）；
  3. **背景图**：用 3:4 竖图裁切或 `screenshots/promo/github-banner.png`；
  4. **置顶**：把跑得最好的那篇想法置顶（发完 1 周再定顶哪篇）。

### 2.4 引流承接架构（怎么接 · 从 App 到产品）

```
【触达】书友 · 想法（可带 #话题）
        │  文末软引导：「想要的说一声 / 看我主页」
        ▼
【承接】主页（简介里放入口关键词）        ← 唯一能长期挂「入口」的地方
        │  关键词：产品名「微信悦读」/ 域名谐音 / 官网
        ▼
【分流】用户按需自取 —— 无外链，全靠「搜 / 记 / 私信」
        ├─ 手机用户 → H5：reader.chesterlee.cn/app/（报告 + 阅读人格分享图）
        └─ 电脑用户 → 官网教程：reader.chesterlee.cn（装 Edge / Chrome 插件）
        ▼
【闭环】用产品生成的「阅读人格分享图」再发回微信读书 / 朋友圈  ← 反哺传播
```

> **红线提醒**：App 内**不放外链、不放二维码、不诱导点赞收藏**。入口一律写成**可被搜索的记忆点**（产品名 / 域名），完整链接只在**私信**里给。

### 3.3 发布节奏（首批 · 2 周）

微信读书 App 的节奏与小红书不同：**不追求日更，追求「贴着读书行为」自然发**。

| 阶段 | 时间 | 频率 | 重点 |
|---|---|---|---|
| 冷启动 | 第 1 周 | 隔天 1 条（约 3–4 条） | **首篇发综合全面版**，其后以破圈层（贴书想法）养人设 |
| 起量 | 第 2 周 | 日更 1 条 | 破圈 + 种草混发，**主推「阅读人格」想法** |
| 稳定 | 第 3 周起 | 每周 4–5 条 | 书友想法打爆点 + 带话题，追节点热点 |

> 频率不是越多越好：**同一账号一天最多 2 条、间隔 ≥ 4 小时**；先保想法质量，再提数量。

### 3.5 发布操作（App 手动 · 无脚本）

- **为什么没有脚本**：微信读书 UGC 只在 **App 内**（手机端）发布，**网页版 weread.qq.com 不能发想法 / 动态**，因此**无法用 Playwright 之类的浏览器自动化**——本渠道**全部手动发布**。
- **发布步骤（统一走「书友」）**：
  1. 打开 App 底部 **「书友」** → 点右下角 **「+」**；
  2. 在「写下这一刻的想法…」文本框里粘贴文案（只粘两条 `────` 之间的正文，别带「【标题】/ 📍」）；
  3. 点 **「添加图片」** 选配图（见 `../帖子/<分类>/<序号-帖子>/`，01 即封面）；**可点「书籍」挂一本在读的书**；
  4. 点 **「# 添加话题」** 选 1 个话题（见 §3.4「建议话题」；**帖子自带 `#书友`，无需手写**）；
  5. 确认左侧为 **「🌐 公开」** → 点右上 **「发表」**。
- **发布后 10 分钟内**：在自己帖子下回一句「入口提示」（**不放链接**，只写「想要的说一声 / 看我主页」）。
- **素材**：文案 + 按序配图都已在 `../帖子/<分类>/<序号-帖子>/`（脚本 `tools/wereadapp_post_folders.py` 生成，可重跑）。

### 3.6 合规与风控清单（发布前必过）

- [ ] 正文 / 想法**无外链、无二维码**；入口只写「产品名 / 域名谐音」，完整链接只在**私信**里给。
- [ ] 不做「点赞收藏抽奖」等**诱导互动**。
- [ ] 快捷键只写 `空格 / D / F / ?`（**不写 T**）。
- [ ] 大模型只写 6 家国产，不写国外模型。
- [ ] 语音一律「朗读 / 听」，不写「音频导出」。
- [ ] 隐私口径：只说「不上传你的阅读数据」；匿名统计提「默认开、可关」。
- [ ] 不出现「永久免费 / 绝对无广告」等绝对化表述。
- [ ] 帖子底部已带小程序入口（`🔍 微信小程序：微信搜「悦读且住」`，**未上线也写**）。
