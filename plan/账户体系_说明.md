# 微信悦读 · 账户体系说明（索引 + 登录方式）

> **用途**：把散落在多份 RPD 里的「账户 / 登录」信息收敛到一处，方便查阅。
> **性质**：说明文档（索引 + 现状），**不作为需求源**；需求以各 RPD 为准，实现以代码为准。
> **最后更新**：2026-10-08

---

## 1. 一句话心智

**账户码 = 账号 + 登录凭证（一体），本机唯一持有。** 没有传统意义的「注册 / 用户名 / 密码」——
浏览器首次访问自动生成一个随机串存在本机，它就是你的账户；服务端按它认人。

生活类比：像自助储物柜，系统给你一个柜子 + 一张取物码；**取物码就是账户码**，抄好它就能在别的设备打开同一个柜子。

---

## 2. 账户是什么

| 项 | 值 |
|---|---|
| 账户标识 | `deviceId`，**32 位十六进制随机串**（浏览器 CSPRNG 生成，非个人信息） |
| 对外称呼 | **账户码**（页面默认只显示掩码：前 4 + `····` + 后 4，可点「显示完整」） |
| 生成时机 | 首次访问自动生成一次，之后长期复用（[store.js `getDeviceId`](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/store.js#L64-L81)） |
| 服务端认人 | 集合 `wre_users` 的 `_id` 就是它（[index.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js#L104)） |
| 服务端校验 | 只留白名单字符、长度下限 16（`DEVICE_MIN_LEN`） |

## 3. 数据落点

### 3.1 本机（`localStorage`，同域名同 origin）

官网（`/`）与网页版（`/app/`）**共用同一组键** → 同一 localStorage → 登录态天然互通，无需同步机制（[store.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/store.js#L19-L23)）。

| 键 | 内容 |
|---|---|
| `wre_account_id` | 账户码（账号 + 凭证） |
| `wre_account_endpoint` | 中转服务地址 |
| `wre_account_mask` | 掩码缓存 `{ masked, hasKey, aiMasked, hasAiKey }` |
| `wre_account_profile` | 昵称缓存 `{ nickName, avatarUrl }` |
| `wre_h5_cache_*` | 接口临时缓存（纯本机，不共享） |

> 旧键（`wre_h5_device / _endpoint / _masked / _profile`）首次加载**一次性自动迁移**到新键，老用户登录态不丢。

### 3.2 服务端（微信云开发）

| 集合 | `_id` | 存什么 | 说明 |
|---|---|---|---|
| `wre_users` | 账户码 | `enc` / `aiEnc`（AES-256-GCM 加密的 Key）、`masked` / `aiMasked`（掩码）、`nickName`、`createdAt` / `updatedAt` | 权限＝**仅管理端可读写**；两把 Key 一把微信读书 `wrk-`、一把 DeepSeek `sk-`（可选） |
| `wre_sync` | 账户码 / openid | 本机算出的**人格结果**（上限 400KB） | 与小程序共用同一集合；**不存 Key、不存官方原始数据**；绑定后统一按**账户码**存取 |
| `wre_links` | 见下 | 跨端身份映射 `openid ↔ 账户码` + 一次性绑定码 | 权限＝**仅管理端可读写**；用 `kind` 区分三类文档（见下），**不存 Key、不存官方原始数据** |

**`wre_links` 文档三类**（用 `kind` 区分，避免多建集合）：

| `_id` | `kind` | 内容 | 用途 |
|---|---|---|---|
| `l_<openid>` | `link` | `{ openid, deviceId }` | 正向映射：小程序侧按 openid 找到账户码 |
| `d_<deviceId>` | `link` | `{ openid, deviceId }` | 反向映射：网页侧解绑时 O(1) 定位 |
| `b_<deviceId>` | `bind` | `{ code, status, deviceId, expireAt }` | 一次性 6 位绑定码会话（10 分钟有效） |

- **加密**：应用层 `AES-256-GCM`，密文格式 `v1:<iv b64>:<tag b64>:<密文 b64>`；密钥在云函数环境变量（[index.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js#L661-L686)）。
- **Key 明文只在提交那一刻经 HTTPS 上行**，之后前端只带账户码，服务端按账户码取 Key；响应不含明文。

## 5. 登录方式（规划口径）

只有两种：**一种已实现、一种预留未做**。

### 5.1 账户码登录 —— ✅ 已实现（当前唯一方式）

- 匿名 `deviceId`，**无登录、无授权弹窗、不含个人信息**；
- 换设备：在「我的账户 → 跨设备登录」粘贴账户码即可找回同一账户的托管 Key + 昵称（[me.js `restore-device`](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/views/me.js#L248-L262) / [account.js `restore`](file:///Users/Admin/Knowledge/Coding/微信读书插件/web/assets/account.js#L196-L218)）；
- 账户码等同密码：页面默认只显示掩码，点「显示完整」才展开。
- **6 位登录码（H5↔H5 快捷方式，2026-10-08 新增）**：同一卡片里点「生成 6 位登录码」，在另一台设备的网页版输入这 6 位即可登录同一账户（复用 `bindCreate` 的一次性 6 位码会话，10 分钟有效；`bindRedeem` 换回账户码后本机改存该码并重载）。免去手抄 32 位账户码。

### 5.2 微信登录 —— 🔜 预留，未实现

- 账户模型**已预留 `openid` 绑定位**；将来接入时把 openid 绑到已有账户即可，属**叠加改动**，不动现有账户码体系。
- 优先方案：**「小程序 `web-view` 免费取 openid」**；其次「认证服务号网页授权」。
- **明确不引入公众号 / 开放平台依赖**。
- 来源：[RPD_H5 §9 决策 7](file:///Users/Admin/Knowledge/Coding/微信读书插件/plan/RPD_H5移动端_需求文档.md#L304) + [§H8 未来扩展](file:///Users/Admin/Knowledge/Coding/微信读书插件/plan/RPD_H5移动端_需求文档.md#L129)。

### 5.3 小程序端的 `openid`（不算「登录方式」）

小程序内 `cloud.getWXContext().OPENID` 由微信平台**天然提供**、零弹窗（[RPD_小程序 §M8](file:///Users/Admin/Knowledge/Coding/微信读书插件/plan/RPD_小程序移动端_需求文档.md#L48)）。它只在小程序内部用（人格结果云同步、运营看板白名单），**网页版 / H5 拿不到**，所以网页侧才改用账户码。

### 5.4 网页端 ↔ 小程序端：✅ 已实现「主动绑定」（2026-10-08）

**绑定前（现状）**：

| 端 | 身份 | `wre_sync` 的 `_id` | 处理函数 |
|---|---|---|---|
| 小程序 | 微信 `openid`（平台天然提供） | `openid` | [handleSync](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js#L332-L374) |
| 官网 `/account/` + 网页版 `/app/` | 账户码（`deviceId`） | `deviceId` | [handleH5Sync](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js#L872-L909) |

- 两端写的是**同一集合 `wre_sync`**，但 `_id` 不同（小程序＝openid、网页＝deviceId）→ **同一用户在两边的数据互不可见**（同一栋储物柜，两把不同的钥匙、两个不同的柜子）。绑定后统一按**账户码**存取，即读写同一份文档。
- 受影响的只有**共有数据**：**人格结果**、**昵称**在两端各存各的；**托管 Key** 仅网页端有（小程序端 M15 后不托管 Key）；**「我的纸书」** 仅小程序端有（按 openid）。

**为什么这样（非 bug，是身份来源不同）**：浏览器拿不到 openid（微信只在微信生态内下发），小程序又用不到账户码；所以当初各用各的身份，各自解决「换设备找回自己那一边」。

**打通方案（属「用户主动绑定」的一次性动作，叠加改动，不动现有账户码体系；[§H8 未来扩展](file:///Users/Admin/Knowledge/Coding/微信读书插件/plan/RPD_H5移动端_需求文档.md#L128) / [§9 决策 7](file:///Users/Admin/Knowledge/Coding/微信读书插件/plan/RPD_H5移动端_需求文档.md#L306) 已预留在先）**：

> ⚠️ **原设想的 web-view 方案不可用（2026-10-08 核实）**：微信官方文档明确「**个人类型的小程序暂不支持使用 web-view**」，且业务域名需 ICP 备案 + 校验文件。本项目为**个人主体**，故「小程序 web-view 免费取 openid」这条路封死。

改为「用户主动把网页账户码递给小程序」一条思路，绑定入口原定**三种都做**（覆盖不同人群与选择习惯，2026-10-08 决定）：

| 入口 | 用户动作 | 体验 | 状态 |
|---|---|---|---|
| **① 扫码绑定** | 网页显示二维码 → 小程序「关联网页账户」点「扫一扫」 | 最方便、零抄写 | ✅ **已实现**（2026-10-08 纯本地零依赖二维码生成器） |
| **② 短码绑定** | 网页显示 6 位数字 → 小程序内输入这 6 位 | 方便、手输很短 | ✅ **已实现** |
| **③ 粘贴账户码** | 网页复制 32 位账户码 → 小程序内粘贴 | 一般 | ✅ **已实现** |

- 三种入口**结果一致**：绑定后 **人格结果 / 昵称**双向同步（绑定一次长期有效，换设备才需重绑）。
- ① 与 ② 走的是**同一个一次性 6 位绑定码**，只是「扫码」把它编成二维码免去手输；二维码由**纯本地生成器**（[h5/src/qrcode.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/qrcode.js)）绘制，不引入任何外部库 / CDN，不违背「零外部依赖」红线。
- 服务端共用一条映射：`openid ↔ deviceId`；绑定后两端统一按 **deviceId** 存取 `wre_sync`。
- ~~认证服务号网页授权~~：需认证服务号，**明确不引入**（见 §9 决策 7）。

**二维码生成器（2026-10-08 新增）**：

- **纯本地实现**：ISO/IEC 18004 固定 **Version 3 / 纠错级别 M / 字节模式**（29×29，44 数据码字 + 26 纠错码字），自研 GF(256) Reed-Solomon、8 种掩码按标准罚分择优，输出 **SVG**（矢量、清晰、无位图）。见 [h5/src/qrcode.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/qrcode.js)。
- **正确性已校验**：与参考实现（Python `qrcode`）逐位比对，8 种掩码 + 真实 32 位账户码**全部一致**。
- **承载内容**：一次性 6 位绑定码（短时有效、非长期账户码），扫码即等价于手输那 6 位数字。

**实现要点（2026-10-08）**：

- **绑定**：网页侧「我的账户」生成 6 位码（10 分钟有效，存 `b_<deviceId>`）→ 小程序「关联网页账户」**扫一扫二维码**或输入 6 位码（或粘贴完整账户码）→ 云函数写 `l_<openid>` + `d_<deviceId>` 两条映射。
- **数据不丢**：绑定瞬间 `migratePersonaOnBind`（账户侧**无人格**才把小程序的搬过去，绝不覆盖）；解绑瞬间 `migratePersonaOnUnbind`（把账户最新人格回搬本机）。
- **昵称**：以账户侧为准拉回本机；账户侧没有则把小程序的推上去。
- **入口位置**：网页版 [me.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/views/me.js) / 官网 [account.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/web/assets/account.js) 均在「我的账户」；小程序 `pages/link/index`（从「我的 → 更多 → 关联网页账户」进入，内含「扫一扫」按钮，走 `wx.scanCode`）。
- **前置部署**：云开发控制台**新建集合 `wre_links`**（权限「仅管理端可读写」）+ 重新上传云函数 `wereadProxy`。

**状态**：**已实现**（扫码 + 短码 + 粘贴三种入口全部可用，见上表）。

**反向统一：用户先从「手机端（小程序）」开始用（2026-10-08 新增）**

- **缺口**：上面三种入口都由**网页端发起**（网页先有账户码 → 小程序认领）。若用户**先在小程序使用**，小程序侧只有 openid、产不出账户码，网页端便无从统一。
- **补法**：让账户码**也能由小程序侧产生**。云函数新增 [`accountEnsure`](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js#L1121-L1149)：未分配则新建一个账户码、建立 `openid ↔ deviceId` 映射，并把 openid 侧已算好的人格搬到该账户码名下；已分配则原样返回（**幂等**）。
- **用户动作**：小程序「我的 → 关联网页账户」页 → 点「**获取我的账户码**」→ 展示账户码（可显示完整 / 复制）→ 在网页端「我的账户 → 跨设备登录」**粘贴登录** → 两端统一。
- **网页端登录防呆**：若本机当前账户已有数据，登录另一账户码前**弹窗确认**，并提示旧账户数据仍在云端、可用旧账户码登回。
- **关于 H5**：H5（手机浏览器打开的 `/app/`）本身就是网页端，与官网 / 桌面网页共用同一套账户码机制 —— 换设备只需粘贴账户码，**无需额外绑定**；真正需要反向打通的是**小程序**（openid）。
- **状态**：**已实现**（2026-10-08）。

**网页端 ↔ 网页端（H5↔H5）跨设备登录：新增 6 位码快捷方式（2026-10-08 新增）**

- **场景**：电脑打开网页版，手机上再打开网页版，想登录同一账户（同一份托管 Key / 昵称 / 人格）。
- **原方式**：复制 32 位账户码 → 另一台设备粘贴登录（已可用，但 32 位难抄）。
- **新方式（6 位码）**：电脑「我的账户 → 跨设备登录」点「**生成 6 位登录码**」→ 手机在**同一卡片**的输入框输入这 6 位 → 点「用 6 位码登录」→ 提示确认后即登录同一账户并重载。
- **实现**：复用 `bindCreate` 的一次性 6 位码会话（存 `b_<deviceId>`，10 分钟有效）；云函数新增 [`bindRedeem`](file:///Users/Admin/Knowledge/Coding/微信读书插件/mobile/cloudfunctions/wereadProxy/index.js#L1122-L1153)，凭码用 `findBindSession` 找回 `deviceId` 并标记会话 `redeemed`（一次性，且**不影响**「已关联小程序」的判定 —— 该判定只看 `claimed`）。
- **防呆**：手机端登录前同样弹窗确认（旧账户数据仍在云端，可凭旧账户码登回）。
- **状态**：**已实现**（2026-10-08）。

### 5.5 浏览器插件接入账户（可选，2026-10-08 新增）

- **动机**：插件「🔑 API Key」面板原本只把 Key 存本机（`chrome.storage.local`），与 H5 / 官网的账户体系割裂；用户希望「账户在所有产品中一致、Key 只在一处填一次，全部地方同步」。
- **开关形态**：**可选、默认关闭**。未启用时插件行为与旧版**完全一致**（Key 只存本机、不联网），老用户无感。
- **本机存储**：`chrome.storage.local` 键 `wreAccount = { id: 32位账户码, sync: 是否启用云端同步 }`；账户码由 `crypto.getRandomValues` 本地生成，与 H5 / 官网的 `deviceId` **同构**（32 位十六进制）。
- **启用 / 登录后**：把本机已配置 Key 用 `keySave` 加密托管到同一套云函数；再用 `keyPull` **把托管 Key 明文拉回本机**，由插件后台**直连**官方网关 / DeepSeek（请求路径与未启用时相同，不经服务端中转）。保存 Key 成功后自动 `keySave` 推送（best-effort）。
- **登录方式**（与 H5 一致）：① 本机「启用」自动生成账户码；② 粘贴 32 位账户码登录（`wre-account-login`）；③ 在本机「生成 6 位登录码」→ 在另一台设备的插件 / H5 / 官网输入（`wre-account-gencode` 走 `bindCreate`、对方走 `bindRedeem`，复用同一套一次性 6 位码会话）。
- **安全口径变化（重要）**：`keyGet` 只回掩码（持账户码只能「用」Key）；新增的 `keyPull` 回明文 —— 因此**启用云端同步后，持有账户码即等同「可抄走 Key」**。故做成开关，并在隐私政策如实声明。
- **可控操作**：面板内可「关闭同步」（本机 Key 保留）、「清除云端 Key」（本机 Key 不受影响）、「退出账户」（本机 Key 保留、云端不动）。
- **跨端范围**：本方案只统一**插件 / H5 / 官网**的 **Key（+昵称）**；**小程序不托管 Key**（合规原因已去 AI），只共享账户 / 人格 / 昵称。
- **状态**：**已实现**（2026-10-08）。插件端见 [background.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/background.js)（账户存储 + 云函数客户端 + `wre-account-*` 消息）、[official.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/modules/official.js)（面板 UI）；云函数见 `keyPull`。

## 6. 关键语义（易混，务必分清）

| 操作 | 清什么 | 保留什么 | 恢复方式 |
|---|---|---|---|
| **退出登录** | 本机账户码 + 掩码 + 昵称（`resetDeviceId()`，[store.js](file:///Users/Admin/Knowledge/Coding/微信读书插件/h5/src/store.js#L83-L92)） | 服务端账户与全部数据**原封不动** | 用**原账户码**在新设备/本机登录 |
| **清除云端 Key** | 只清 `wre_users` 的 Key 字段（`enc`/`masked`/`aiEnc`/`aiMasked`） | **昵称、账户**：保留 | 重新填写 Key |
| **跨设备登录** | 本机掩码缓存（换账户后失效） | — | 写入新账户码 → 向服务端拉掩码 / 昵称 |

### 退出登录的防呆（2026-10-08）

账户码是本机唯一持有、退出即丢，为防「没抄号码就退出」导致旧账户永久失联，
退出登录**不再用系统确认框**，改为**站内弹层**：弹出时展示**完整账户码 + 一键复制**，用户须点「我已保存，退出登录」才真正退出。
共用实现：`ui.js` 的 `confirmSignOut()` —— 官网 `/account/` 与网页版「我的账户」页共用一份。
